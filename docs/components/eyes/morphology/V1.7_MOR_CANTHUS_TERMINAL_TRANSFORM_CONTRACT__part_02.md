## 12. Visual evidence

- inner and outer close-up renders;

The visual matrix includes front gaze, upper-right gaze, lower-left gaze, ±30° parent rotation, narrow opening, epicanthic fold, endpoint tangent profile, explicit legacy bridge, and paired eyes.

## 13. Reference boundary

The checkpoint does not contain the original source pixel sheets used in the earlier reference analysis. Therefore V1.7 does not claim a pixel-fitted universal anime canthus/caruncle parameter range.

The anatomical distinction was cross-checked against public anatomical descriptions and image references; the numeric style values remain engine defaults rather than claims about all anime styles.

## 14. Acceptance decision

The default V1.7 shared-terminal representation is promoted because close-up inspection no longer shows the V1.6 finite-gap bridge cap. The medial caruncle is visually separated from the terminal and the pair-side placement is mirrored correctly.

Reference-pixel calibration remains open. No global numeric claim is made for caruncle colour, size, epicanthal prominence, or anime-specific terminal shape.

## 15. Next brick

The next step should **not** add another canthus curvature scalar. The remaining work should be reference-calibrated and transform-system oriented:

1. digitize the clean reference canthus/caruncle regions;
2. extract upper/lower terminal tangent rays independently;
3. measure medial caruncle width/height/curvature against eye envelope;
4. model epicanthal fold coverage as an independent medial occlusion/fold layer;
5. distinguish human-default, anime-stylized and deliberately exaggerated terminal profiles without universalizing one style;
6. feed resolved parent/world transforms from the generic runtime transform resolver into ocular geometry instead of relying only on `rotation_deg` when the scene graph is used;
7. add transform-inheritance regression tests for brow, lashes, caruncle, epicanthic fold and any future face-parent children;
8. add visual anti-cap/anti-hook/anti-lash-terminal diagnostics to the acceptance gate;
9. calibrate only from digitized reference pixels and retain a human-review gate for artistic acceptance.

## 16. Artifact retention policy

Only the current V1.7 evidence directory is retained in the working checkpoint:

`artifacts/v17_canthus_terminal_transform/`

Superseded V1.3–V1.6 generated artifacts were inspected for historical usefulness and then removed because the source code, tests, contracts and implementation history already preserve the engineering record. This reduces checkpoint size and prevents obsolete visual evidence from being mistaken for the current accepted render set.
