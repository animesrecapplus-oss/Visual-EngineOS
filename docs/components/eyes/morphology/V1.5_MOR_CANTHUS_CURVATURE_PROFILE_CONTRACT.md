# V1.5 — MOR canthus curvature-profile micro-brick

## Status

**IMPLEMENTED / VISUAL ACCEPTANCE OPEN**. This micro-brick addresses the specific residual defect
left visible after V1.4 endpoint reconstruction: curvature remained concentrated close to the canthus
endpoints even though the artificial endpoint gap had been removed.

It is intentionally narrower than a full reference-curve reconstruction.

## Problem established by V1.4 evidence

V1.4 measured the actual cubic bridges and showed that several families still had strong endpoint
curvature concentration. For the default almond case after V1.4, the inner/outer bridge had an
endpoint-curvature fraction around 0.889 and a curvature peak-to-mean around 12.05. The diagnostic
was explicitly visual rather than merely numerical: the rendered canthus could still read as a
small point/cap.

The supplied reference analysis describes the canthus as a local curved convergence, with distinct
subfamilies including tight convergence, small rounding and slight medial opening. It also warns
against treating the canthus as a triangle or using the epicanthic fold as its closure. No pixel-
level reference curve or universal numeric target is claimed.

## Design constraint

The current public representation is a cubic bridge and its endpoint derivatives are required to
match the adjacent lid curves. A cubic with fixed endpoints and fixed endpoint derivatives has no
remaining independent internal curvature parameter. Therefore V1.5 does **not** fake an extra cubic
control point and does not weaken C1 validation.

Instead, the brick moves the curvature-profile control upstream into the local endpoint tangent
construction of the sampled upper/lower lids. This preserves:

- the semantic canthus coordinates;
- the renderer-neutral cubic bridge representation;
- exact C1 derivative equality;
- independence of inner and outer controls;
- separation from iris/pupil/gaze semantics.

## Authoring parameters

Two continuous, independent controls are added:

- `canthus_inner_transition ∈ [0,1]`;
- `canthus_outer_transition ∈ [0,1]`.

`0` is a strict compatibility value: it reproduces the V1.4 tangent-construction policy.
Higher values lengthen the local endpoint tangent transition using the bounded interpolation:

`local_cap = local_spacing * (0.5 + 0.4*t)`

`gap_target = corner_gap * (0.45 + 0.75*t)`

`handle = min(local_cap, max(gap_target, ε))`

where `t` is the corresponding transition parameter.

The local cap is intentionally below one full pre-existing local spacing. This prevents the new
control from becoming an unrestricted global contour deformation.

## What this parameter means

It means **transition length / curvature distribution**, not anatomy, ethnicity, eye type, or a
universal anime style. It does not move the canthus semantic anchor.

The parameter is deliberately continuous so variation can later sample it with constraints rather
than introducing arbitrary discrete presets.

## Invariants

1. Inputs remain finite and transitions remain in `[0,1]`.
2. `transition=0` is backward-compatible with the V1.4 tangent construction.
3. Inner transition changes only inner endpoint tangent construction; outer geometry and internal
   ocular placement remain unchanged, subject only to explicitly shared global inputs.
4. Outer transition has the symmetric independence property.
5. Semantic inner/outer canthus coordinates are unchanged by transition.
6. Iris/pupil centers and radii are unchanged by transition.
7. All generated lid/bridge coordinates remain finite.
8. C1 continuity remains mandatory and is checked after gaze-follow.
9. Full-contour self-intersection remains a hard rejection.
10. Zero/near-zero opening remains tested as a boundary; no transition is allowed to bypass the
    existing degenerate-opening contract.
11. The public bridge remains exactly four cubic control points; no renderer-specific approximation
    is introduced.

## Visual QA rule

A lower metric number is not sufficient evidence of visual correctness. Each candidate must be
reviewed in:

- normal full-eye framing;
- magnified inner corner;
- magnified outer corner;
- actual sampled bridge overlay;
- representative narrow, round, upturned and downturned contexts;
- strong gaze/rotation cases.

A candidate that improves a metric while producing a visibly swollen, detached, hooked or otherwise
incoherent corner is rejected.

## Visual review result

The rendered sweep confirms that the parameter changes the bridge geometry and that the metrics respond in the expected direction on the calibration case. It also exposes an important failure mode: larger transition values can make the canthus read as a swollen cap rather than the smooth convergence described by the references. Therefore the micro-brick is **not promoted as a visual solution** and no non-zero default is enabled. The rejection is intentional and fail-closed.

## Current calibration decision

No new default transition value is promoted solely from this micro-brick. The compatibility default
remains `0.0` until a larger reference-digitization campaign establishes a defensible visual band.
The QA artifact nevertheless renders a sweep through the full `[0,1]` domain so the effect is visible
and auditable.

## Nonclaims

This brick does not:

- digitize the two reference sheets into ground-truth curves;
- infer anatomical truth from anime drawings;
- declare a universal anime threshold;
- solve the entire upper/lower lid curvature family;
- implement the epicanthic fold;
- distinguish all stylistic termination modes;
- prove that one transition value is optimal for every eye family.

## Next required geometry work

The next brick should move from a single endpoint-transition axis toward **explicit canthus tangent
and transition-length controls per endpoint**, while keeping the lid curves independently authored.
It should also add a reference-digitization layer capable of extracting reproducible curve samples
from the clean reference sheet, so future numeric bands come from measured source geometry rather
than invented thresholds.
