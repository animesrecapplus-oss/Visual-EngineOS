## 6. Clean default + quasi-infinite variation

The target is not “random eyes”. It is a **valid parameter manifold**. A default eye is one canonical interior point with stable aesthetic constraints. Variation is generated around that point using parameter domains, correlations and hard invariants. A generated sample is accepted only when:

1. all parameter values are valid and finite;
2. geometry is continuous and contained;
3. bilateral constraints hold when human-pair mode is active;
4. expression/style/camera do not violate morphology invariants;
5. appearance remains legible at the selected shot/LOD;
6. the result is deterministic for a fixed seed/spec/version;
7. its evidence can be regenerated and compared;
8. its parameter provenance is inspectable.

## 7. Execution order

1. **GEN** common contracts and shared terminology.
2. **MOR → LID** establish the geometric base manifold.
3. **IRI → PUP → LAS → BRW → HIL** deepen ocular subcomponents.
4. **EXP → PAIR → OCC** establish coupled behaviour.
5. **COL → STY** establish appearance/style behaviour without geometry contamination.
6. **CAM** formalise presentation-space effects and LOD.
7. **VAR** build constrained variation over the validated parameter manifold.
8. **PRM** compile human-readable requests into the explicit IR.
9. **RND** run the complete evidence/visual acceptance loop.

## 8. Definition of Done for every atom

No atom moves from `PARTIAL_OR_SKETCH` to accepted merely because code exists. The atom requires the full lifecycle: **develop → test → deterministic artefact → visualise → correct → validate → document**. The evidence must state what was actually tested and what remains unverified.

## 9. Explicit nonclaims

This blueprint does not claim physical ocular anatomy, true optical refraction/reflection, automatic image understanding, a completed prompt compiler, production-grade raster quality, or a biologically faithful expression model. Those become separate atoms with their own acceptance evidence.
