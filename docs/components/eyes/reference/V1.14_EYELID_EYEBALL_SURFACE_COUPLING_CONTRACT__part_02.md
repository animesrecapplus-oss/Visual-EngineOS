## 12. Aperture occlusion

Projected iris/pupil samples are measured against the actual 2D aperture polygon.
The measurement returns:

```text
visible
partially_visible
hidden
```

The SVG clip path remains the final visual clipping authority. The measurement is a
QA/geometry diagnostic, not a second renderer that can disagree with the clip.

## 13. Blink

Closed/covered eyes keep the existing `opening <= 0` renderer gate. V1.14 does not
invent visible iris/pupil pixels during a blink merely because a 3D globe exists.

The globe/coupling metadata may still exist for continuity and future animation.

## 14. Visibility and depth limits

V1.14 provides deterministic surface/depth metadata but is not yet a full z-buffered
3D renderer. In particular, the current SVG backend still performs final aperture
clipping in 2D.

Therefore this brick does **not** claim:

- physical ray-traced eyelid occlusion;
- full facial orbital topology;
- corneal refraction;
- optical transmission;
- anatomical eyelid tissue simulation.

## 15. Orientation inheritance

The existing V1.12/V1.13 ocular basis remains authoritative:

```text
parent basis
   + local ocular pose
   ↓
resolved eye basis
```

Yaw, pitch, roll and alignment-axis rotation are composed as basis rotations rather
than added as Euler scalars.

## 16. Extreme orientations

The tests cover yaw:

```text
±90, ±120, ±150, 180
```

and pitch:

```text
±60, ±90
```

including combinations with roll and alignment rotation.

The invariant is not "the iris must remain visible". The invariant is that the
geometry must remain finite, attached and correctly classified when it becomes
edge-on or back-facing.

## 17. Prompt semantics

V1.14 does not change the V1.12 semantic vocabulary:

```text
look_behind_right_eye
look_behind_left_eye
look_behind_both_eyes
```

The semantic resolver remains separate from the geometry builder. `look_behind_*`
does not silently become screen-left or screen-right.

## 18. Cache invalidation

The eye geometry generator version is now `4` because parent-child surface
attachment changes generated geometry and must invalidate V1.13 caches.

## 19. Testing

The dedicated V1.14 tests verify:

- concentric pupil attachment;
- gaze-induced iris motion with matching pupil-parent motion;
- authored pupil child offsets;
- multiple children;
- spherical surface radius invariants;
- aperture occlusion measurement;
- 3D lid lifting without mutating the 2D aperture;
- near/far canthus classification;
- caruncle/epicanthus surface lifting;
- closed-eye gating;
- extreme yaw/pitch invariants.

The complete repository regression must pass before checkpoint promotion, with any
existing environment-dependent skip explicitly recorded.

## 20. Visual QA acceptance

The V1.14 visual QA must contain both clean and sampled outputs. Sampling is limited
to actually visible aperture points so hidden geometry does not appear as false red
pixels outside the eye.

A dedicated offset-pupil artifact is retained to prove that a displaced pupil still
moves with and remains attached to the iris parent.

No external reference-pixel overlay is generated because V1.11 human approval is
still pending.

## 21. Reference calibration boundary

V1.14 does not promote V1.11 reference samples into MOR ranges. Human validation,
true pixel digitization and reference/engine error maps remain separate work.

## 22. Performance and auditability

Spherical-specific work is isolated in small modules. `geometry/builder.py` remains
under the 250-line audit budget. The attachment calculation is deterministic and
uses scalar vector operations; no heavyweight 3D dependency is introduced.

## 23. Final engineering statement

V1.14 fixes the confirmed V1.13 pupil-detachment defect and introduces the first
explicit lid/globe depth coupling. It is a controlled geometric bridge, not a claim
of complete ocular anatomy.
