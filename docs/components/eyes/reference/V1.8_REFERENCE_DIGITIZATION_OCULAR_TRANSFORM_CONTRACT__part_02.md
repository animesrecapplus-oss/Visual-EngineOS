## 8. Reference digitization contract

`reference/digitization.py` introduces explicit structures for:

- source provenance;
- upper contour samples;
- lower contour samples;
- medial/lateral terminal coordinates;
- caruncle polygon;
- epicanthic curve;
- style-family classification;
- tangent extraction;
- caruncle measurements.

Three descriptive family values are available:

- `human_generic`;
- `anime_stylized`;
- `exaggerated_artistic`.

They are not treated as biological truths.

### Source gate

The checkpoint does **not** contain the original reference pixels. The previous V1.4 evidence records the source hash and envelope measurements, but the actual image file is absent from the current working source/library.

Therefore V1.8 stores the measured envelope table as `envelope_only` and explicitly leaves these axes unresolved:

- upper contour control points;
- lower contour control points;
- medial terminal;
- lateral terminal;
- four endpoint tangents;
- caruncle polygon/curvature;
- epicanthic fold curve.

No coordinates are reconstructed from a bounding box. This is a deliberate fail-closed rule.

## 9. Reference measurements available once pixels are supplied

The digitization code extracts, independently:

- upper start/end tangent angle;
- lower start/end tangent angle;
- envelope aspect ratio;
- caruncle width/height;
- caruncle centroid offset from the medial terminal;
- epicanthic start/end tangent angle.

The same measurement functions can therefore be applied to source references and engine-generated samples without changing definitions.

## 10. Visual acceptance gates

A V1.8 render is not accepted merely because a transform matrix is mathematically correct.

The visual gates include:

- no brow crossing/overlap caused by pair placement;
- brow remains attached to its eye under parent rotation;
- gaze does not move the brow;
- closed eye does not collapse the brow gap;
- no terminal cap from full-width lid strokes;
- no legacy bridge plug at small finite gaps;
- no medial detail painted over the black corner border;
- caruncle remains inside the ocular aperture;
- epicanthic endpoints remain inset;
- medial detail stays on the medial side in mirrored pairs;
- parent rotations ±30°, ±45°, +90° remain structurally coherent.

## 11. Performance

A warmed 1000-default-build benchmark was run against the extracted V1.7 checkpoint in the same environment:

- V1.7 baseline: 13.768 s
- V1.8: 9.966 s
- measured change: approximately **−27.6%** in this local run.

This is a regression/engineering measurement, not a production performance certification.

## 12. Non-goals

V1.8 does not claim:

- pixel-level reference fitting without the original pixels;
- universal anime anatomy;
- a universal human canthus geometry;
- population statistics;
- automatic classification of an absent source image;
- arbitrary scene-graph rendering inside the eye-specific SVG renderer.

The generic runtime remains the authoritative world-transform layer; the eye-specific renderer remains a local ocular renderer.

## 13. Evidence

Generated under `artifacts/v18_reference_digitization_ocular_transform/`:

- clean pair rotations;
- gaze center/diagonal comparison;
- closed-eye brow anchoring;
- epicanthic/caruncle layer inspection;
- legacy bridge inner/outer close-ups;
- envelope-only reference panel;
- deterministic manifest;
- evidence report.

The source-pixel absence is encoded in the manifest and evidence report rather than hidden.
