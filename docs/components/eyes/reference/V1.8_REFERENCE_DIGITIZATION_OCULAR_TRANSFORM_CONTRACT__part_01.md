# V1.8 — Reference Digitization + Ocular Transform Resolution

**Status:** `IMPLEMENTED — ENGINEERING PASS / VISUAL REVIEWED / PIXEL DIGITIZATION SOURCE GATED`

## 1. Scope

V1.8 closes several defects found by inspecting the V1.7 artifacts and establishes the next reference-calibration layer without inventing missing source pixels.

The brick covers:

1. brow-to-eye clearance as a stable local anatomical relationship;
2. brow inheritance from the ocular parent, independent from gaze;
3. pair-side brow anchoring and symmetry under parent rotation;
4. terminal-safe rendering of the upper/lower lid margins;
5. explicit medial-detail layering and aperture clipping;
6. an authoritative eye façade over the existing runtime `world_transform` resolver;
7. a reference-digitization data contract with provenance and a hard source-availability gate;
8. tangent, terminal, caruncle and epicanthic measurements when actual pixel coordinates are supplied;
9. adversarial transform tests and deterministic visual QA.

## 2. Confirmed V1.7 defects

### 2.1 Brow displacement

The previous SVG transform was effectively:

`translate(center) rotate(angle) translate(-center)`

applied to coordinates that were still local to the eye. At non-zero parent rotation this rotated the local brow around a world-space center without first placing its local origin there. In a pair this displaced brows toward the middle and could make them overlap/cross.

The V1.8 transform is:

`translate(eye_center) rotate(parent_rotation + local_brow_angle)`

The path remains local until the transform is applied.

### 2.2 Gaze/brow contamination

Gaze previously added small x/y corrections to the eyebrow. This contradicted the hierarchy: gaze controls the internal ocular assembly; the brow is a child of the eye/face parent.

V1.8 removes that coupling. Expression may still author brow changes explicitly.

### 2.3 Pair reference-frame defect

The V1.7 brow reference conversion subtracted the pair eye center from data that was already eye-local. This was invisible for a single eye at `(0,0)` but corrupted the reference frame for paired eyes at `(-0.65, 0)` and `(0.65, 0)`.

V1.8 converts only the rotation of the local contour; pair translation is applied later by the renderer transform.

## 3. Brow clearance contract

The default `BrowSpec.min_eye_gap` is now `0.45` instead of `0.08`.

This is an **engine/style placement default**, not an anatomical universal.

The effective clearance remains derived from the stable full-opening local ocular reference, so it survives:

- opening changes;
- closed/covered state;
- gaze direction;
- diagonal gaze;
- parent rotation;
- pair mirroring;
- resizing.

An explicit `BrowSpec(min_eye_gap=...)` continues to override the default.

## 4. Gaze separation

The envelope remains owned by morphology/parent rotation.

Gaze resolves the internal iris/pupil assembly. It does not:

- rotate the aperture;
- translate the eyebrow;
- redefine the superior axis;
- move the caruncle/epicanthic fold.

The V1.8 tests explicitly compare neutral and diagonal gaze with identical brow geometry.

## 5. Terminal rendering

The geometry layer continues to store the semantic shared terminal or explicit legacy cubic bridge.

The renderer now uses a **terminal-safe sampled ribbon** for finite-gap bridges and **point-tapered lid margins** at all ocular terminals.

The taper is not a replacement geometry model: the stored lid samples and bridge cubic remain the authoritative geometry. The renderer only controls the visual stroke envelope so a mathematically valid endpoint cannot become a visually incorrect full-width cap.

For very small finite gaps relative to local lid stroke width, the legacy bridge is not visually stroked. The lid margins own the terminal. The bridge remains available in the geometry contract for continuity/regression diagnostics.

## 6. Medial detail layering

The caruncle and epicanthic fold are rendered in a dedicated medial-detail layer:

`fill sclera → medial details (clipped) → lid contours → internal ocular assembly → lashes/brow`

This guarantees that the pale medial detail cannot paint over the black canthal border.

The epicanthic fold endpoints are inset toward the ocular interior rather than sharing the exact canthal border points.

The caruncle remains medial-only and is generated toward the eye interior. Pair side ownership is unchanged:

- image-left eye → medial feature points toward pair centre;
- image-right eye → medial feature points toward pair centre.

## 7. Runtime transform resolution

The runtime already owns the authoritative root→target affine composition in `runtime.geometry_transform`.

V1.8 does not create a competing eye-specific transform system. `reference.transform` exposes:

- `resolve_ocular_transform(graph, component_id)`;
- `resolve_ocular_geometry(graph, component_id, geometry, target=...)`.

These call the existing runtime resolver directly.

Therefore the hierarchy remains:

`face → eye → child`

and composition supports:

- translation;
- rotation;
- uniform scale;
- non-uniform scale;
- nested parent→child→grandchild composition;
- scene/camera resolution through the existing generic contract.
