# V1.22 — Dual-Sample Provenance Gate / Real Pixel Calibration Handoff

Date: 2026-09-20

## Purpose

V1.22 is the handoff layer between the V1.21 source-pixel trace capture system and the first real source↔engine calibration sweep.

It does **not** choose a follow-strength value. It does not convert machine observations into human approval. Its job is to prove that a future calibration run has at least two independent, explicitly reviewed, source-pixel digitizations with immutable provenance.

## Why this brick was necessary

V1.21 solved the difficult-contour problem, but a later calibration step could still be vulnerable to a provenance mistake: a `ReferenceSample` by itself does not prove which source file produced it. V1.22 therefore introduces `V122DigitizedSample`, which couples:

1. candidate ID;
2. digitized `ReferenceSample`;
3. source SHA-256;
4. source dimensions;
5. component/manual trace mode.

The calibration gate accepts only this provenance-bearing object.

## Independence contract

The real-pixel handoff requires at least two eligible records and verifies:

- distinct candidate IDs;
- distinct sample IDs;
- complete upper and lower source curves;
- explicit medial and lateral terminals;
- approved V1.20 semantic review;
- completed V1.21 trace capture;
- source SHA-256 equal to the exact calibration source;
- source dimensions equal to the exact calibration source.

Two observations of the same candidate are therefore not silently counted as two independent reference samples.

## Diagnostic evidence before approval

V1.22 intentionally produces diagnostic pixel-trace previews even while calibration is closed. These previews are not semantic labels. They show the actual source pixels and the raw connected-component centerline proposals produced by the existing tracer.

Two representative cases were sampled:

- candidate 001: multiple retained components;
- candidate 014: one retained component, demonstrating why V1.21 manual tracing is necessary.

The preview captions explicitly state that component IDs have no anatomical meaning.

## Fail-closed cases

The gate rejects or blocks:

- no human approval;
- missing trace capture;
- missing digitized sample;
- incomplete curves;
- missing source provenance;
- source SHA mismatch;
- source dimension mismatch;
- candidate/sample identity mismatch;
- duplicate eligible candidate IDs;
- duplicate eligible sample IDs.

No fallback estimate is inserted for any of these cases.
