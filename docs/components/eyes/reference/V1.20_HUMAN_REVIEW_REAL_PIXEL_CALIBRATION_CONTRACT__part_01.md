# V1.20 — Human Review → Real Pixel Calibration Contract

**Date:** 2026-09-20  
**Status:** ENGINEERING IMPLEMENTED / REVIEW PACKET READY / REAL PIXEL CALIBRATION BLOCKED BY ZERO EXPLICIT APPROVALS

## 1. Purpose

V1.19 made `eyelid_surface_follow_strength` a real authoring parameter. V1.20 is the
bridge between that parameter and the actual reference pixels. The purpose is not to
make a numerical fit look authoritative. The purpose is to create an auditable chain:

```text
source bytes
  ↓
28 segmentation proposals
  ↓
human semantic review
  ↓
approved source-pixel traces
  ↓
fixed comparison frame
  ↓
actual engine geometry at observed strengths
  ↓
per-sample error fields
  ↓
common-strength aggregate
  ↓
candidate_only
  ↓
human visual acceptance
  ↓
promotion (future step only)
```

No arrow may be skipped.

## 2. Source integrity

- dimensions: 792 × 792 px
- format: JPEG
- segmentation candidates: 28

The V1.20 tool refuses to run against a different byte stream or a different candidate
count. This prevents calibration against an accidentally substituted reference.

## 3. Human review schema

Every candidate has an explicit record containing:

1. `eye_identification`: `yes | no | uncertain`;
2. `eye_side`: `image_left | image_right | single`;
3. selected upper trace candidate;
4. selected lower trace candidate;
5. medial terminal coordinate;
6. lateral terminal coordinate;
7. caruncle status: `present | absent | unknown`;
8. epicanthus status: `present | absent | unknown`;
9. observable family (`unclassified` is allowed when the reviewer cannot justify a family);
10. `sample_id`;
11. reviewer note;
12. explicit review state.

`unknown` is not converted to `absent`.

An approved record must contain every required semantic field. A sample ID is illegal
before approval, preventing an unreviewed candidate from becoming calibration data by
accident.

## 4. Contextual candidates

The 28 segmentation boxes are not all guaranteed to be individual eyes. Some are
contextual face panels containing multiple eyes. V1.20 therefore permits the reviewer
to retain the segmentation candidate as provenance while specifying an exact smaller
trace region for the selected eye.

The machine-generated connected-component IDs remain proposals. They are not semantic
upper/lower anatomy until the reviewer explicitly selects them.

## 5. Pixel digitization

For an approved record, the existing source-pixel tracer is used without replacing
source coordinates with a fitted curve:

```text
source pixels
 ↓
connected ink component
 ↓
orientation-independent centerline proposal
 ↓
explicit reviewer upper/lower selection
 ↓
explicit terminal coordinates
 ↓
inner/outer orientation
 ↓
ReferenceCurve
```

The source curve remains sampled pixel geometry. Tangents and curvature are derived
from those stored samples.

### Medial detail

Caruncle and epicanthus are separately reviewed. A detection failure is never treated
as absence.

- caruncle `present` requires an explicit polygon;
- epicanthus `present` requires an explicit trace candidate;
- `absent` and `unknown` remain semantically distinct.

## 6. Fixed comparison frame

The engine is not fitted to the reference control points.

The comparison frame uses only:

- source medial terminal;
- source lateral terminal;
- engine inner canthus;
- engine outer canthus;
- source upper/lower normal span;
- engine upper/lower normal span.

The affine mapping therefore normalizes the terminal axis and normal scale. It does not
optimize the engine curve against the reference curve.

This distinction is critical: otherwise a calibration could always improve by changing
the comparison frame rather than the geometry.
