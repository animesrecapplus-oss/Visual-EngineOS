# V1.15 — True Ocular Depth Occlusion / Orbital Surface Contract

Date: 2026-09-19
Status: ENGINEERING PASS / VISUAL QA PASS / REFERENCE CALIBRATION STILL HUMAN-REVIEW GATED

## Purpose

V1.15 closes the next geometric gap after V1.14: a spherical eyeball and a 3D-lifted eyelid trace now receive an explicit local depth contract. The implementation does **not** claim a full anatomical face or a physically based renderer. The orbital surface is an explicit procedural ellipsoid used as a local soft-tissue depth surface around the aperture.

## Hierarchy

```text
FACE
 └── ORBIT (procedural orbital surface)
      ├── EYELID SURFACE
      ├── EYEBALL
      │    ├── SCLERA
      │    ├── IRIS
      │    │    └── PUPIL[n]
      │    └── CORNEA
      ├── CARUNCLE
      └── EPICANTHUS
```

The pupil remains an iris child. Its position and surface frame are never recomputed independently from the eye origin.

## Coordinate/depth convention

The existing `projection3d.py` camera convention is retained: the orthographic camera is on +Z looking toward the origin, and larger world Z means closer to the camera. Depth comparisons therefore use `point.z - center.z`.

No Euler-angle addition is introduced. V1.13's ocular basis remains the orientation authority.

## V1.15 depth contract

The resolved object `OcularDepthOcclusion` contains:

- procedural `OrbitalSurface3D`;
- upper/lower lid depth layers;
- iris depth layer;
- one depth layer per pupil child;
- sampled visible/hidden fractions;
- near/far canthus labels inherited from the V1.14 3D coupling;
- explicit z-order: `orbit → sclera → iris → pupil → cornea → eyelid`.

### Local occlusion rule

1. The 2D aperture remains the global morphology boundary.
2. A projected ocular sample outside that aperture is hidden.
3. Near a lid margin, the nearest sampled lid depth is compared against the child depth.
4. A child sample behind a foreground lid surface is classified hidden.
5. If no lid sample is near the child, the orbital shell provides the fallback local depth surface.
6. Depth diagnostics never modify geometry after resolution.

This is intentionally a **sampled local depth gate**, not a full GPU-style z-buffer.

## Visual rendering rule

For spherical eyes, the SVG renderer paints ocular children first and the eyelid contour afterward. This gives the lid margin foreground ownership at the boundary while preserving the existing aperture clip. Legacy non-spherical eyes retain their historical order.

The cornea is a transparent/outline marker and does not hide the iris or pupil. The iris is the parent surface for pupil children; therefore the pupil is rendered after the iris and before the corneal marker.

## Orbital surface

`OrbitalSurface3D` is a conservative ellipsoid derived from globe scale:

- X radius = `1.18 * globe_radius`;
- Y radius = `0.82 * globe_radius`;
- Z radius = `0.30 * globe_radius`;
- front offset = `0.025 * globe_radius`.

These values are procedural defaults, not measurements of human anatomy. They exist to provide a deterministic local depth surface until a future 3D facial/orbital calibration exists.

## Edge cases

The tests cover:

- yaw ±90/±120/±150/180;
- pitch ±90;
- roll + yaw + pitch + alignment;
- forward/backward independent eyes;
- multiple pupil children;
- pupil/iris parent attachment;
- finite depth layers;
- aperture/depth consistency;
- orbital-surface boundary rejection;
- closed eyes;
- existing V1.10–V1.14 regressions.

## Deliberate limits

V1.15 does not implement:

- a complete 3D facial/orbital anatomy;
- physical corneal refraction/transmission;
- a continuous ray-traced z-buffer;
- subpixel raster visibility solving;
- anatomical claims from the procedural orbital ellipsoid;
- V1.11 reference calibration.

Those remain separate future contracts.
