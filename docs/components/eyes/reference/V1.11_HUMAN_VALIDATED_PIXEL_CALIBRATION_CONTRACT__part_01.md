# V1.11 — Human-Validated Pixel Calibration Contract

Date: 2026-09-18

## 1. Objective

V1.11 closes the **pixel → geometry** pipeline only after an explicit human review gate.
The uploaded 792×792 JPEG is byte-preserved and the V1.10 segmentation is reproduced as 28
review candidates. Candidate detection is evidence generation, not annotation.

## 2. Review state machine

```text
candidate
   ↓
review board / crop
   ↓
PENDING
   ├── REJECTED
   ├── NEEDS_REVISION
   └── APPROVED + sample_id
```

An approved candidate must have a sample ID. Non-approved candidates cannot carry one.
The manifest is immutable at the API level: a decision returns a new manifest instead of
mutating the previous decision.

## 3. What the reviewer must decide

For every candidate:

- whether it is an eye sample, a contextual face panel, or another region;
- if it is an eye sample, its semantic side (`image_left`, `image_right`, or `single`);
- exact upper and lower contour components;
- inner and outer terminals;
- whether a caruncle is actually visible;
- whether an epicanthic fold is `present`, `absent`, or `unknown`;
- observable family label only when construction evidence supports it.

No classifier silently supplies these decisions.

## 4. Terminal contract

The canonical authoring vocabulary is:

```text
inner terminal → medial terminal
outer terminal → lateral terminal
```

For a front-view image-left eye, medial should normally lie to the right of lateral;
for an image-right eye, medial should normally lie to the left. This is a sanity check,
not an anatomy detector. Strongly oblique samples may set `allow_oblique=True`; semantic
roles still come from the reviewer.

## 5. Dense trace contract

Selected dark-ink components are converted to dense source-pixel centerline proposals.
The trace no longer assumes that image X is the curve's longitudinal axis: PCA-based
perpendicular medians support horizontal, diagonal and near-vertical studies. The trace
remains a proposal because stroke texture, intersections and component selection still
require visual review.

Approved upper/lower traces are oriented so their start point is the reviewer-selected
inner/medial side. Ambiguous orientation is rejected rather than guessed.

## 6. Four endpoint measurements

After approval, the engine retains four independent endpoint measurements:

```text
inner-upper
inner-lower
outer-upper
outer-lower
```

The tangent-stability threshold is recorded with the measurement. It is a measurement
convention, not an anatomical constant.

## 7. Canthus measurements

The approved pixel curves provide:

- terminal distance;
- alignment-axis angle;
- upper/lower start/end tangent;
- medial convergence;
- lateral convergence;
- endpoint transition length;
- arc length;
- discrete curvature profile and peak.

No canthus curvature value is promoted to a global MOR range from one sample.

## 8. Caruncle

A caruncle is stored only when a reviewer explicitly digitizes its polygon. Measurements
include centroid, width, height, terminal distance, RGB and opacity when available.
Missing color/opacity remain missing; they are never converted to black, zero or a default.

## 9. Epicanthus

The state is explicit:

```text
present | absent | unknown
```

A failed edge/component search is never interpreted as `absent`. If `present`, a reviewer
must identify the curve component separately from the eyelid/canthal border.

## 10. Reference/engine overlay

For an approved sample only:

```text
SOURCE PIXELS
     +
DIGITIZED CURVES
     +
INVERSE-MAPPED ENGINE
     +
ERROR SEGMENTS
```

The mapping is fixed from reviewer terminals and independent normal scale. The engine is
not fitted until its error disappears. This preserves the diagnostic value of the overlay.

The current repository run intentionally produces **no real source overlay**, because no
candidate has an explicit human approval in the manifest. A synthetic overlay belongs only
to tests of the mapping implementation.

## 11. Quantitative comparison

The overlay exposes:

- upper RMS / mean / max error;
- lower RMS / mean / max error;
- inner-upper, inner-lower, outer-upper and outer-lower tangent angular error;
- medial and lateral terminal error.

Caruncle and epicanthus errors remain absent until those fields exist on both sides of a
comparison. Missing is not zero.
