## 8. V1.10.3 dense pixel contours

`trace_component_candidates()` extracts dark-ink connected components and produces dense one-point-per-x-bin polylines as **trace candidates**.

It does not decide which component is the upper or lower lid. `digitize_approved_eye()` requires:

- an explicitly approved `TraceRegion`;
- an independently selected upper component;
- an independently selected lower component;
- explicit medial terminal;
- explicit lateral terminal.

This prevents eyebrow strokes, decorative strokes, iris marks, or unrelated black components from becoming contour truth by heuristic accident.

## 9. V1.10.4 four endpoint tangents

The existing V1.9 measurement machinery remains independent:

```text
inner-upper
outer-upper
inner-lower
outer-lower
```

No bilateral symmetrisation is introduced. Transition length is a measurement under an explicit tangent-deviation threshold, not an anatomical constant.

## 10. V1.10.5 canthus

The calibration data model retains enough information to measure:

- convergence;
- local/discrete curvature;
- transition length;
- terminal geometry;
- medial/lateral differences.

No value is promoted to a style band until actual source pixels and human review exist.

## 11. V1.10.6 caruncle

The sample model supports:

- polygon contour;
- width;
- height;
- centroid;
- terminal-relative placement;
- RGB colour;
- opacity.

Missing observations remain absent/unknown. They are never converted to zero or a guessed default.

## 12. V1.10.7 epicanthus

The epicanthic fold is optional and must be digitized only when the reviewed source pixels justify identifying it. Absence is not inferred from a failed edge search.

## 13. V1.10.8 calibration

`ReferenceEngineAlignment` provides an explicit pixel↔engine mapping from reviewer-supplied terminal anchors and independent normal-axis scale.

`overlay_metrics()` compares normalized, equal-arc-length samples without modifying the engine geometry to hide error.

## 14. V1.10.9 real overlay

`render_reference_engine_overlay()` renders:

- original reference pixels;
- digitized reference curves;
- inverse-mapped engine curves;
- terminal markers;
- per-sample disagreement segments.

The implementation is ready, but no real overlay is admitted for the uploaded sheet in this run because no human-selected sample has yet passed the V1.10 segmentation gate.

A synthetic self-consistent overlay is retained only as a wiring/inverse-mapping test artifact.

## 15. Image observation and implementation boundary

The supplied sheet visibly contains repeated eye studies progressing from broad/front-facing appearances toward strongly narrowed, side-oriented appearances. Across those studies the visible aperture, iris exposure, canthal visibility and lid/skin relationships change together rather than behaving like a simple 2D rotation.

That observation motivates the new separation between:

- **roll** — screen-plane rotation;
- **alignment-axis depth rotation** — foreshortening of the ocular plane;
- **future view-axis/yaw rotation** — a separate 3D gaze/view problem.

The image is inspiration/evidence for the need for coupled behaviour, not a license to assign numeric 3D angles to its cells without pixel segmentation and provenance.
