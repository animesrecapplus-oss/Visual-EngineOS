# V1.19 — Explicit Eyelid-Surface Follow Parameter + Human-Gated Calibration

## Status

`IMPLEMENTED — CALIBRATION INFRASTRUCTURE READY / REFERENCE CALIBRATION BLOCKED`

V1.18 exposed the procedural eyelid/globe coupling as a hard-coded kernel default.
That was sufficient for engineering validation but not sufficient for a serious
reference-calibration workflow: a parameter that cannot be authored, persisted and
measured explicitly cannot be calibrated reproducibly.

V1.19 therefore does two things:

1. promotes the existing V1.18 `0.10` coupling value to an explicit
   `EyeParameters.eyelid_surface_follow_strength` field;
2. adds a fail-closed calibration estimator which can consume only explicitly
   human-approved V1.11 samples and never promotes a value without an explicit
   human visual-acceptance gate.

It does **not** claim that `0.10` is anatomically correct or reference-derived.

## 1. Parameter ownership

`EyeParameters.eyelid_surface_follow_strength` is constrained to `[0, 1]`.

- `0.0`: no globe-follow contribution to interior lid samples;
- `0.10`: the V1.18 compatibility default;
- larger values: stronger surface-follow deformation;
- endpoints/canthi remain face-owned semantic anchors.

The parameter is passed from the public eye morphology object into the actual
`couple_lid_curve()` kernel. There is no duplicate hidden calibration constant.

The geometry generator version is incremented because the generated geometry can
change when this parameter changes.

## 2. Calibration input gate

A calibration observation must contain:

- an explicit `sample_id`;
- `reviewer_status="approved"`;
- independently approved source identity;
- errors evaluated at actual tested follow-strength values.

Pending, rejected, or unlabelled candidates are rejected. Two approved samples
are the minimum for a follow-strength fit. All samples must share at least two
actually evaluated candidate values; no interpolation or extrapolation is invented.

## 3. Fit semantics

`fit_eyelid_surface_follow_strength()` computes the mean observed source-to-engine
error at each candidate strength common to all supplied samples and returns the
lowest-error **candidate**.

The function does not:

- infer a continuous curve from sparse values;
- extrapolate outside tested values;
- turn one sample into a population range;
- call lower error anatomical truth;
- promote a candidate automatically.

Ties are resolved deterministically by the smaller tested strength. This is a
reproducibility rule, not a claim that smaller coupling is biologically preferable.

## 4. Promotion gate

`promote_eyelid_surface_follow_strength()` requires explicit
`human_visual_acceptance=True` in addition to the two-sample calibration gate.

This preserves the project rule:

`pixel evidence → numerical candidate → clean visual inspection → human acceptance → promotion`

A lower numerical error alone is never an acceptance criterion.

## 5. Current source state

The V1.11 review manifest in this checkpoint still contains **28 pending candidates
and zero approvals**. Therefore V1.19 deliberately produces no reference-derived
numeric calibration and leaves the engine default at `0.10`.

This is a blocked state, not a failed calibration and not evidence that `0.10` is
correct.

## 6. Visual QA

The V1.19 visual sweep renders the actual engine at:

- follow strength: `0.00, 0.05, 0.10, 0.15, 0.20`;
- alignment: `-45°, 0°, +45°`.

The ocular child overlay is clipped by the actual generated aperture before being
placed in the QA image. This is important: an unclipped spherical outline would
be visually misleading because production visibility is aperture-aware.

The sweep is engineering evidence only. It is not a source-reference match.

## 7. Acceptance gates

V1.19 is accepted only for the calibration infrastructure when:

- focused V1.17/V1.18/V1.19 tests pass;
- compileall passes;
- visual QA is deterministic;
- the parameter demonstrably reaches the real geometry kernel;
- canthi remain invariant under parameter changes;
- malformed/pending calibration observations fail closed;
- no numeric calibration is promoted without explicit approval.

Reference calibration remains blocked until V1.11 human review supplies actual
approved samples.
