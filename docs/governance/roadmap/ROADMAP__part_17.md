# Roadmap — V1.50+ architectural discipline

## V1.50 — foundation and pilot

Formalize the architectural immune-system protocol before broad modularization.

1. Define component truth and semantic ownership.
2. Define stable traceability IDs.
3. Define multidirectional impact analysis.
4. Define hostile test/reviewer obligations.
5. Define parent/child/sibling/system integration checks.
6. Define prompt→render→inspect→diagnose→correct loop.
7. Define naming, duplication, cleanup and artifact retention rules.
8. Build a machine-readable component gate.
9. Apply the protocol to one real component without mass migration.
10. Detect and correct one concrete ownership conflict.

with legacy API identity preserved.

## Long-term adoption

Each component is migrated when touched by real work. Do not create empty speculative folders or documentation farms.
A component dossier grows only when a real responsibility, relation, contract, test, decision or defect exists.
