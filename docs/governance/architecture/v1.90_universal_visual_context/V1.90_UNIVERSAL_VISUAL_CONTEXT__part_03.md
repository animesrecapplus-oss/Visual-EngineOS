# V1.90 — Universal Visual Context Audit — Part 03

## AUD-V190-014 — Camera infrastructure

A real scene `Camera` exists with position `(x,y,z)`, `zoom` and `rotation_deg`, validated for finite values and positive zoom. Evidence: `src/visual_engine/scene/composition.py:21-28`.

A deterministic affine camera transform exists and production geometry can resolve `LOCAL → WORLD → SCENE → CAMERA`. Evidence: `src/visual_engine/runtime/geometry_transform_resolution.py:63-72, 94-111`.

**Classification:** generic 2D camera infrastructure = `VERIFIED`.

## AUD-V190-015 — Camera semantic default

When `camera=None`, the runtime currently substitutes `Camera()`, whose numeric defaults are `x=0,y=0,z=0,zoom=1,rotation=0`. Evidence: `geometry_transform_resolution.py:94-108`.

This proves an **identity affine camera fallback**, not a semantic contract saying "front view". There is no verified generic prompt-level declaration of camera viewpoint, subject-facing convention, projection mode or framing policy for an unspecified prompt.

**Classification:** numeric fallback = `VERIFIED`; semantic default camera = `GAP`.

## AUD-V190-016 — Projection

The generic scene camera is 2D affine; it does not implement perspective. The permanent vision explicitly says the transform system must not claim full 3D optics/perspective before those systems exist.

A separate `Camera3D` exists under the ocular geometry subsystem. It supports orthographic and explicit perspective projection and is intentionally ocular-local.

Evidence: `ENGINE_VISION__part_05.md:76-94`; `components/face/eyes/geometry/projection3d.py:11-40`.

**Classification:** 2D camera = `VERIFIED`; ocular 3D camera = `VERIFIED / COMPONENT-SCOPED`; unified scene 3D projection = `PLANNED/GAP`.

## AUD-V190-017 — Composition and framing

`Frame`, `CompositionPolicy`, placement, margins, spacing and overflow policies exist in `scene/composition.py`. The permanent vision also requires frame, viewport, placement, scale, depth, spacing, safe areas and partial visibility.

Evidence: `scene/composition.py:12-45`; `ENGINE_VISION__part_05.md:52-72`.

However, the production face render accepts a caller-provided `Placement` and optional `Camera`; it does not resolve a semantic shot/framing request from a prompt.

**Classification:** composition primitives = `VERIFIED`; prompt-driven framing resolver = `PLANNED/GAP`.

## AUD-V190-018 — Shot

`scene/shot.py` provides `ShotScale` and `fill_ratio`. It is real, validated and tested, but the audit found no verified connection from prompt ambiguity to automatic shot selection in the generic production path.

**Classification:** shot vocabulary = `VERIFIED`; shot selection from prompt/default context = `GAP`.

## AUD-V190-019 — Camera is contextual, not entity identity

This is already a permanent architectural rule: scene instances store camera and contextual placement separately from persistent entity identity.

Evidence: `ENGINE_VISION__part_05.md:3-36, 52-72`.

**Classification:** architecture = `VERIFIED`; complete operational scene-context compiler = `PLANNED`.
