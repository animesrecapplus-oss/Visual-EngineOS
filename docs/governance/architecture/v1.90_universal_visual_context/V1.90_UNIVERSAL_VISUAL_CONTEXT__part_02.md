# V1.90 — Universal Visual Context Audit — Part 02

## AUD-V190-008 — Prompt compiler status

The permanent vision already defines the long-term flow:

`PROMPT → Semantic Interpretation → Visual Specification → Entity Graph → Parameters/Morphology → Generators → Resolvers → Composition/Camera → Renderer → IMAGE/SVG/ANIMATION`.

Evidence: `ENGINE_VISION__part_06.md:33-59`.

Roadmap Phase 7 independently marks the prompt compiler as planned: visual vocabulary, structured IR, prompt-to-parameter mapping, ambiguity handling, validation, deterministic seed handling and prompt provenance are unchecked.

Evidence: `ROADMAP__part_02.md:39-60`.

**Classification:** prompt compiler architecture = `PLANNED`; executable generic prompt compiler = `ABSENT/NOT_IMPLEMENTED`.

## AUD-V190-009 — Ocular prompt semantics are not a generic prompt compiler

`gaze/semantics.py` has a real prompt-facing ocular vocabulary (`look_left`, `look_right`, `look_up`, `look_down`, explicit depth intents and alignment intents), but this is an ocular semantic adapter, not a general natural-language prompt compiler.

Evidence: `src/visual_engine/components/face/eyes/gaze/semantics.py:12-78`.

**Classification:** ocular prompt vocabulary = `IMPLEMENTED`; generic prompt compiler = `PLANNED`.

## AUD-V190-010 — Default resolution

The audit found no verified generic resolver that turns an unspecified prompt field into a documented, provenance-bearing system default for viewpoint, projection, framing, pose, gaze, expression, style, appearance, lighting, seed and quality.

The existing code has local defaults, for example `Camera()` and component defaults, but these are not equivalent to a semantic default-resolution layer.

**Classification:** local defaults = `VERIFIED`; universal default-resolution policy = `GAP`.

## AUD-V190-011 — Entity/component graph

The authoring `Component` tree and compiled `RuntimeGraph` are real. `RuntimeGraph` is a topology view, not a second mutable source of truth; stale topology is rejected until rebuild.

Evidence: `ARCHITECTURE_CONTRACT__part_02.md:A0 structural closure` and `COMPONENT_TRUTH_ARCHITECTURE.md`.

**Classification:** entity/component graph infrastructure = `VERIFIED`; prompt-to-graph compiler = `PLANNED`.

## AUD-V190-012 — Child/parent/sibling semantics

The project already distinguishes semantic parentage from aggregate/public ownership in the eye system. Iris→Pupil is direct semantic parentage; CMP-EYE is aggregate/public; eyelid/lashes/eyebrow are periocular siblings/relations.

Evidence: `ARCHITECTURE_COMPONENT_TREE.md` V1.82 section and `EYE_SEMANTIC_HIERARCHY_MATRIX__V1.83`.

**Classification:** explicit eye hierarchy = `VERIFIED`; universal relation dossier coverage = `VERIFIED` for adopted components, incomplete repository-wide adoption = `PARTIAL`.

## AUD-V190-013 — Child→parent feasibility

The vision requires hard/soft constraints and parent-region validity, but the audit found no universal production contract that propagates every child requirement back into parent feasibility.

Existing placement/constraint systems answer concrete placement questions and fail closed, but they are not a universal bidirectional visual-feasibility solver.

**Classification:** local constraint/placement infrastructure = `VERIFIED`; universal child→parent feasibility propagation = `GAP`.
