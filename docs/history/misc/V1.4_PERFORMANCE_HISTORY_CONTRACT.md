# V1.4 — Artifact performance history contract

## Purpose

Every visual QA artifact run may record timing alongside deterministic evidence so future
checkpoints can be compared for rendering performance.

## Measurements

The ocular visual QA layer records:

- `geometry_build_ms` — geometry solver/build cost;
- `envelope_metric_ms` — numerical envelope measurement cost;
- `svg_render_ms` — renderer serialization cost;
- `png_raster_ms` — rasterization cost;
- `total_case_ms` — sum of those measured stages;
- SVG/PNG byte sizes.

The history may also record Python/runtime platform and the timing-file hash.

## Determinism boundary

Timing is **not** part of deterministic artifact identity. OS scheduling, CPU frequency,
background load and raster library implementation can change timings without changing the
artifact. Therefore deterministic manifests contain hashes/sizes, while timing lives in a
separate `performance_timing.json` and chronological `artifacts/performance_history.jsonl`.

This permits optimization work without weakening reproducibility.

## Interpretation

Measurements are diagnostic benchmarks, not production guarantees. Comparisons should use
the same environment where possible and should inspect stage-level changes rather than only
total time. A faster renderer that changes geometry identity or invalidation correctness is
not accepted as an optimization.

For `CanthusMetrics`, numerical integration is a QA/measurement cost and is recorded separately as
`inner_metric_ms` and `outer_metric_ms`. The accepted implementation uses fixed 128-point
Gauss-Legendre quadrature after a 128-vs-256 node accuracy challenge; this keeps measurement cheap
without silently changing the geometry or deterministic artifact identity.
