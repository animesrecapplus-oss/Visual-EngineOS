# V0.3 architecture decisions

## 1. Source of truth vs runtime
PostgreSQL stores persistent knowledge and entity records. RuntimeGraph is the operational representation. Geometry/render code consumes memory structures, never issuing SQL per component/pixel.

## 2. Hierarchy plus relations
A tree models ownership/containment. Relations model cross-links such as CONTACT, OCCLUDES, ATTACHED_TO, AFFECTS and DEFORMS. V0.3 validates endpoints but does not yet implement a general semantic solver.

## 3. Identity separation
Entity IDs and component IDs are stable identifiers. Composition Placement carries position, scale, rotation and z; these do not mutate identity.

## 4. Composition
A frame is independent from entities. The same entity can be placed in different frames/scenes without changing its stored morphology. AUTO chooses CENTER for one entity and GRID for multiple entities in V0.3.

## 5. PostgreSQL schema
Critical relations are relational. JSONB is used only for extensible payloads such as parameter maps, anchors, metadata and profile values. This avoids both schema explosion and one giant opaque entity blob.

## 6. Honest boundary
Constraint expressions are declarations in V0.3. An arbitrary expression engine is deliberately not embedded yet. Future solver work must introduce a typed, safe constraint language rather than eval/exec.
