# Visual Engine V0.4 — Parametric Eye Geometry

## Objective

V0.4 turns the V0.3 `Eye` grammar into a real deterministic geometric object.
The scope is intentionally narrow: geometry + vector output + regression tests.

## Pipeline

```text
Eye Component
    ↓
EyeParameters
    ↓
Parametric Eye Geometry
    ↓
SVG vector renderer
```

The component remains the semantic source. `EyeParameters` is a geometry-facing
projection; it does not replace the component model.

## Parameters

- `width`, `height`: nominal envelope
- `opening`: continuous eyelid aperture
- `iris_ratio`, `pupil_ratio`: dependent ocular dimensions
- `asymmetry`: left/right envelope imbalance
- `upper_curve`, `lower_curve`: reserved curvature controls for the next geometry refinement
- iris/pupil offsets
- corneal reflection position/size/strength
- rotation

## State behavior

`normal`, `wide_open`, `closed`, and `covered` alter the visible aperture. The
state is not stored in geometry as a new identity: it is a rendering-time state.

## Why SVG now?

V0.4 needs an observable output. SVG gives us a resolution-independent reference
render without committing the engine to a raster-only representation.

## Explicit non-goals

Not implemented yet:

- physical corneal refraction
- detailed iris fiber simulation
- tear-film optics
- anatomical 3D eyeball
- facial deformation solver
- interaction/occlusion solver
- raster anti-aliasing improvements
- database persistence of generated geometry

Those belong to later increments and should not be hidden behind V0.4 claims.
