# V0.6 — True Gaze Solver

## Scope

V0.6 strengthens the eye engine specifically around **gaze resolution**. It does not claim facial expression solving, biological ocular optics, or general scene occlusion.

## Pipeline

```text
Gaze request
   ↓
Gaze vector resolution
   ├─ named direction (cardinal/diagonal)
   ├─ continuous x/y offset
   └─ optional world-space target point
   ↓
Normalization + requested amplitude
   ↓
Morphology limits
   ├─ actual sampled eye contour
   └─ actual iris ellipse
   ↓
Pupil footprint margin
   ↓
Resolved pupil displacement
   ↓
Explicit pupil offset
   ↓
Final containment pass
   ├─ iris containment
   └─ eye-aperture containment
```

## Important design decisions

### 1. Gaze is geometric, not a renderer feature
`GazeSolver` lives in `geometry/eye.py`. It knows nothing about SVG, raster rendering, faces, or scene composition. This allows the same solver to serve future non-human eyes.

### 2. Target points are supported
`Gaze(target=(x, y))` resolves the vector from the eye centre to the target. `x/y` remain additive offsets for backward-compatible procedural control.

### 3. Morphology controls the limit
The solver intersects the requested ray with the actual sampled eye contour instead of using one generic ellipse. Therefore narrow, round, droopy, rotated, and deformed eyes can have different gaze limits.

### 4. The iris is a second containment boundary
A pupil centre must remain inside the iris as well as the eye aperture. Pupil radius is treated as a footprint, not a point, so the centre is pulled inward before the boundary is reached.

### 5. Multiple pupils share the gaze request but have independent footprints
Each pupil receives the same resolved direction but its own pupil dimensions. A larger pupil therefore gets a tighter safe displacement. Explicit per-pupil offsets are checked again after gaze resolution.

### 6. Diagnostics are retained
`EyeGeometry.gaze_solution` exposes the resolved direction, requested magnitude, safe limit, actual offset, and whether clamping occurred. This is useful for tests, animation, and future expression systems.

## What is deliberately NOT implemented in V0.6

- eyelid deformation driven by gaze
- binocular convergence based on a 3D target
- perspective/3D ocular rotation
- corneal refraction model
- biological tear dynamics
- facial expression resolver
- general scene occlusion/depth solver

These remain separate systems rather than being faked inside the gaze solver.
