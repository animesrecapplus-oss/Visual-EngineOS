# V1.1 — data-driven visual effects architecture

## Principle

PostgreSQL is the source of truth for reusable visual definitions. It is **not** a render-time dependency.

The execution path is:

`Prompt/Scene request -> Profile resolver -> PostgreSQL (cold path) -> validation/compilation -> process cache -> runtime graph -> geometry -> renderer`

A render frame never executes a PostgreSQL query.

## What belongs in PostgreSQL

- named ocular profiles and versions;
- lash density/length/thickness/form/style;
- lash-shadow response coefficients;
- pupil glow and smoke effect parameters;
- presentation profiles;
- expression profiles;
- style/material profiles;
- compatibility/constraint rules;
- future component-specific definitions.

Stable identifiers and versions remain relational/indexed. Fast-evolving parameter sets use controlled JSONB rather than a single opaque entity blob.

## What remains in Python

Only generic execution machinery:

- validation;
- profile compilation;
- geometry algorithms;
- generic effect renderers;
- dependency resolution;
- caching;
- SVG/raster backends.

There should be no renderer branch such as `if anime`, `if female`, or `if smoke`. A profile selects data; generic code executes it.

## CPU strategy

1. Query once per profile/version.
2. Validate and compile into immutable runtime objects.
3. Cache by `(family, name, version)`.
4. Reuse compiled geometry when identity/morphology has not changed.
5. Recompute only affected dependent nodes when state/pose/expression changes.
6. Keep SVG generation vectorial where possible.
7. Rasterize only when required by the target effect/material.

## Lash shadow

The upper-lash shadow is a continuous appearance effect attached causally to the upper-lash system. Its strength is derived from density, thickness and length and then bounded by the profile's opacity. It is clipped by the eye aperture.

This is deliberately an approximation of the visible optical effect, not a physical light transport simulation.

## Pupil glow and smoke

Both are optional effects attached to a pupil definition.

- Glow: vector aura + optional bright core + Gaussian blur.
- Smoke: deterministic Bézier wisps; default direction is upward (`-90°` in SVG coordinates).

They are emitted before the pupil body so the pupil remains the semantic source component.

## Separation rule

`Identity != Morphology != Style != Appearance != State != Expression != Gaze != Effect != Geometry != Renderer`

This separation is the main scalability mechanism for the future face/body/entity engine.
