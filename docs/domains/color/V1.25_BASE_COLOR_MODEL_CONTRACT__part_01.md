# V1.25 — Base Color Model Contract

**Date:** 2026-09-21  
**Status:** implemented / verified  
**Depends on:** V1.24 canonical color-space foundation

## Purpose

V1.25 turns BASE color from an open-ended appearance dictionary into one typed,
renderer-neutral authority per component. The model keeps authoring identity and
canonical color identity together without mixing BASE semantics with material,
lighting, palette, or compositing behavior.

## Contract shape

```text
BaseColor
├── canonical_color
├── authored_representation
├── source
├── provenance
├── role
├── alpha_semantics
├── inheritance
└── fingerprint
```

### `canonical_color`

Always `ColorRGBA` in **linear sRGB RGBA**. The V1.24 transfer-function and gamut
rules remain authoritative. No clipping or gamut mapping is introduced here.

### `authored_representation`

For authored and inherited colors, the exact source sRGB spelling is retained as
`#RRGGBB` or `#RRGGBBAA`, including case. This prevents provenance from being
reconstructed from a lossy normalized representation.

Generated colors have no authored representation unless a future explicit contract
introduces one; generator identity instead belongs to provenance.

### `source`

`BaseColorSourceKind` is closed to:

- `authored`
- `inherited`
- `generated`

Each source also carries a stable source ID and authority component ID.

### `provenance`

Provenance records target component, authority component, source ID, ordered lineage,
resolution rule, and generator ID/version when generation is involved. It contains no
wall-clock timestamp, random token, or renderer state, preserving deterministic identity.

### `role`

The role vocabulary is intentionally semantic rather than physical:
`primary`, `secondary`, `accent`, `detail`, `background`, `custom`.
It must not encode roughness, metallicity, transmission, lighting direction, or BRDF
behavior.

### `alpha_semantics`

- `opaque` means alpha is exactly `1`.
- `unassociated` means alpha is carried independently from RGB.

V1.25 never premultiplies, blends, composites, or chooses an underlay.

## Authority and inheritance

`Component.base_color` is one optional local typed BASE authority. There is no BASE
list on a component.

Inheritance is explicit through `BaseColorInheritance`:

- `allow_children=True` permits a descendant to inherit that authority;
- `allow_children=False` blocks propagation at that authority;
- `LOCAL_WINS` lets a descendant's local authority override inherited color;
- `INHERIT_WINS` lets the nearest inheritable ancestor remain authoritative;
- `REJECT_CONFLICT` rejects a local authority when it conflicts with the nearest
  inheritable ancestor.

The nearest ancestor carrying a BASE authority is decisive. The resolver never skips a
closer authority to invent a more distant source.

## Contradiction policy

The following cases fail closed:

- typed `Component.base_color` plus a legacy appearance `base_color` source;
- more than one legacy BASE source on one component;
- malformed authored sRGB representation;
- generated color without generator provenance;
- inherited color without inherited-authority provenance;
- alpha semantics contradicting the canonical alpha value;
- unsupported source/role/inheritance enum values;
- persisted fingerprint mismatch.

A legacy adapter exists, but it is explicit. It converts exactly one legacy BASE layer
into a typed `BaseColor`; it never silently promotes a dictionary during resolution.

## Fingerprint and invalidation

`BaseColor.fingerprint` hashes only the BASE value object. It contains no geometry,
transform, material, lighting, or renderer state.

`base_color_resolution_fingerprint(graph, component_id)` is the targeted appearance
invalidation key. It includes only the target's local authority and the nearest ancestor
authority when that ancestor can actually affect resolution. In particular, a local
`LOCAL_WINS` authority does **not** depend on an ancestor's color, and an unrelated
sibling cannot invalidate the target BASE resolution.

Geometry mutation is therefore outside the BASE invalidation domain.

## Persistence

The typed BASE object is stored inside the existing component metadata JSON extension
point. No PostgreSQL migration is required for this brick. Deserialization recomputes
the immutable fingerprint and rejects tampered persisted fingerprints.

Older component payloads without `base_color` remain loadable and are not silently
converted. Explicit migration is required to promote a legacy BASE layer.

sRGB swatches against canonical linear-sRGB values re-encoded for display, with generic
