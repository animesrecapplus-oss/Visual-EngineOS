# V1.38 — EFFECT COLOR Semantic Closure Contract

**Date:** 2026-09-25  
**Baseline:** V1.37 COLOR consumer audit  
**Checkpoint:** `V1.38_EFFECT_COLOR_SEMANTIC_CLOSURE`

## 1. Scope

V1.38 descends inside the already-certified `effect_color` path. It does **not** create a
new color space and does **not** add a second RGB transformation.

The existing operation remains:

```text
operation_id       = effect.color.srgb8-interpolation
operation_version  = 1
calculation_space  = encoded sRGB 8-bit RGB
input/output       = canonical linear-sRGB ColorRGBA
```

The work is limited to semantic closure: caller inventory, alpha authority, lineage,
ordering, duplicate identity, invalidation/fingerprint completeness, performance and
visual verification.

## 2. Complete production call graph

There are exactly two production call sites of `apply_effect_color()`:

1. `src/visual_engine/runtime/effects.py:91` — `apply_shadow_color()` legacy compatibility adapter;
2. `src/visual_engine/runtime/effects.py:115` — `_apply_canonical_effect()`.

There are exactly two production call sites of `_apply_canonical_effect()`:

1. `src/visual_engine/runtime/effects.py:171` — fill;
2. `src/visual_engine/runtime/effects.py:175` — contour.

The canonical path is therefore:

```text
resolve_effects
  ├─ fill   → _apply_canonical_effect → apply_effect_color
  └─ contour→ _apply_canonical_effect → apply_effect_color
```

`apply_shadow_color()` remains a legacy string adapter only; it is not a second RGB
algorithm.

## 3. Alpha contract

There is exactly one RGB-effect strength authority:

```text
VisualEffect.alpha → effect_alpha
```

`effect.color` is a color value. Its embedded alpha channel is ignored by the RGB
operation. The base color alpha is preserved unchanged.

For alpha `0`, the canonical operation is strict identity and does not quantize the
canonical base color. For alpha `1`, effect RGB replaces base RGB while base alpha remains.

## 4. Lineage contract

For every shadow/tint operation, lineage is the ordered sequence:

```text
(source_id, effect_id, source_id, effect_id, ...)
```

for the color effects that have already executed in `precedence_key` order.

Fill and contour receive the **same cumulative lineage** for the same effect step. This
prevents the two geometry channels from acquiring different effect histories.

Scalar effects (`opacity`, `visibility`, `occlusion`) are deliberately excluded from
color lineage because they do not modify RGB.

## 5. Effect ordering

Effects are canonically sorted by:

```text
(priority, effect_id, source_id)
```

Therefore:

- input tuple order is not semantic;
- priority is semantic for non-commutative color effects;
- equal-priority effects have deterministic `effect_id` then `source_id` tie-breaking;
- duplicate `effect_id` values are rejected before color application.

The following chains are explicitly tested:

- shadow → shadow;
- tint → tint;
- shadow → tint;
- tint → shadow.

The tests compare real `resolve_effects()` output with sequential calls to the same
canonical operation. No independent color formula is used as an oracle.

## 6. Fingerprint/invalidation contract

The final effect-operation fingerprint depends on:

- operation ID;
- operation version;
- calculation space;
- base color fingerprint;
- actual effect color fingerprint;
- external effect identity, when supplied;
- `VisualEffect.alpha`;
- ordered lineage fingerprint;
- resulting color.

A supplied external effect fingerprint can add identity but **cannot hide a color change**.
This closes a real V1.37-era edge case in which an unchanged external fingerprint could have
masked a changed `ColorRGBA` effect value.

The operation version remains explicit, so changing the operation version invalidates the
fingerprint even when the color and parameters are unchanged.

## 7. Cache policy

`effect_color` has no hidden mutable cache. Deterministic dependency fingerprints remain
suitable for an external cache. V1.38 additionally avoids recomputing the immutable effect
fingerprint separately for fill and contour and avoids hashing the same lineage tuple twice
within one effect step.

## 8. No hidden second operation

The V1.38 AST audit found only the declared conversion seams inside `effect_color.py`:

- `ColorRGBA.to_rgba8()`;
- `ColorRGBA.from_rgba8()`;
- `_interpolate_srgb8()`;
- deterministic digest calculation;
- alpha validation.

No HSL, OKLab, XYZ, gamut mapping, compositing, lighting, shading, material response or
second color transform was found inside the path.
