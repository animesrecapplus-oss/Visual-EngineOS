# V1.28 — Appearance Role Bridge — Implementation Report

Date: 2026-09-22
Checkpoint: `V1.28_APPEARANCE_ROLE_BRIDGE`

## 1. Objective

V1.28 establishes an explicit bridge from the typed V1.27 appearance composition
to the existing renderer-neutral `AppearanceResolutionInput.base_color` compatibility
field. The critical architectural rule is that the legacy string must not become a
second color authority.

## 2. Starting point and provenance

The implementation started from the V1.27 certified checkpoint archive available in
the working environment. The archive was extracted into the V1.28 work tree and its
V1.27 source, tests, contracts and release evidence were inspected before modification.

The V1.27 implementation history itself recorded that the earlier V1.26 source ZIP was
not mountable in that environment. V1.28 does not silently claim a V1.26 archive was
revalidated; the current codebase is treated as the V1.27 certified baseline.

## 3. Architecture implemented

```text
V1.27 AppearanceComposition
        |
        v
AppearanceRoleContribution
  role
  source BASE | PALETTE
  canonical linear-sRGB RGBA
  authored_srgb when genuinely authored
  authority component
  source id
  authority fingerprint
  composition fingerprint
  lineage
  legacy_base_color (derived only)
        |
        v
AppearanceResolutionInput
```

The bridge performs selection/representation transfer only. It does not mix colors,
composite alpha, apply lighting, apply material response, or perform style transforms.

## 4. Provenance hardening

The first bridge draft exposed a real provenance gap: V1.27 retained authority IDs and
fingerprints but not the Palette source ID/lineage required for a lossless bridge.
Using the authority component ID as a substitute source ID would have been a false
provenance claim.

The correction extended `AppearanceCompositionProvenance` with:

- `base_source_id`
- `base_lineage`
- `palette_source_id`
- `palette_lineage`

The bridge now copies these fields directly.

## 5. Authored versus generated representation

Authored colors preserve the exact source spelling, including case and alpha bytes.
For example `#AaBbCc80` remains exactly `#AaBbCc80` in `authored_srgb` and in the
legacy compatibility value.

Generated colors have no authored representation. Their compatibility hexadecimal value
is encoded deterministically from canonical linear-sRGB. This is deliberately not
called authored data.

## 6. Legacy boundary rule

`bridge_to_appearance_input()` is the explicit migration/compatibility entry point.
It derives `AppearanceResolutionInput.base_color` from the typed contribution.

A second `AppearanceDomain.BASE` contribution is rejected. A direct
`AppearanceResolutionInput` can still be constructed by old callers for compatibility,
but when a typed role contribution is present the constructor verifies that the legacy
string exactly matches it.

## 7. Fingerprint and invalidation

The bridge fingerprint covers the typed role, selected source, canonical color,
authored representation, authority identity, source identity, provenance lineage,
V1.27 composition fingerprint and derived legacy value.

Geometry, transform, renderer state and unrelated siblings are absent.

Invalidation is delegated to the existing BASE and Palette authority resolvers and then
narrowed by composition mode. BASE-only requests do not acquire Palette dependencies;
Palette-only requests do not acquire BASE dependencies.
