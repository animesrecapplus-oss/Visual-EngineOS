## 6. Color-operation guard

The audit does identify existing color transformations elsewhere, but does not
silently reinterpret them as generic COLOR behavior.

If a future genuine COLOR consumer performs saturation, contrast, vibrance,
lightness, temperature, mixing, pattern-to-color conversion or another operation,
the next implementation must first define:

- input color space;
- calculation space;
- output color space;
- channel ranges and boundary behavior;
- alpha semantics;
- gamut policy;
- authored/inherited/generated provenance;
- authority and lineage;
- dependency fingerprint;
- invalidation;
- determinism;
- visual acceptance criteria;
- performance and cache implications.

No operation is added merely because the mathematical implementation would be easy.
