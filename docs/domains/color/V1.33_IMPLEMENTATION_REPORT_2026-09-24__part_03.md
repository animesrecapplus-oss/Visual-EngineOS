## 13. Next step — V1.34

V1.33 intentionally does **not** invent the next COLOR operation. The next brick must first re-run the closure audit whenever a new generic rendering path is introduced or an existing renderer integration is expanded.

If a genuine production caller is then found, V1.34 must proceed in this exact order:

1. identify the caller and exact result field consumed;
2. trace the complete source → COLOR resolver → consumer path;
3. classify the consumer as pass-through, conversion, palette operation, effect or color transformation;
4. if pass-through, migrate only that real consumer without altering the color value;
5. if transformation, stop and write its separate semantic contract before coding;
6. define input space, calculation space and output space;
7. define alpha participation and unassociated-alpha behavior;
8. define neutral, low, medium, high and extreme parameter behavior;
9. define gamut handling with fail-closed semantics unless a specific mapping contract is justified;
10. preserve authored/inherited/generated provenance and lineage;
11. define dependency fingerprint and targeted invalidation;
12. define cache identity and deterministic serialization;
13. define performance expectations and avoid repeated color-space conversions;
14. generate real runtime samples covering dark, light, saturated, neutral and alpha-bearing colors;
15. inspect those samples visually and reject any result that is mathematically valid but visually inconsistent with the declared semantics;
16. only then migrate that single genuine consumer.

No lighting, shading, BRDF, material response, compositing, renderer post-processing or unrelated color feature belongs in that step unless the proven consumer's existing semantics explicitly require it.
