# V1.24 — Canonical Color-Space Foundation

## Objective

Establish one renderer-neutral color representation and explicit conversion boundaries
before any future palette, shading, lighting, material or appearance-composition algorithm
is allowed to perform color arithmetic.

## Canonical representation

The internal representation is:

```text
ColorRGBA
├── red   : linear sRGB [0,1]
├── green : linear sRGB [0,1]
├── blue  : linear sRGB [0,1]
└── alpha : unassociated [0,1]
```

The RGB channels are **not** premultiplied by alpha.

## Supported spaces

- `sRGB`: display/encoded RGB channels in `[0,1]`;
- `linear-sRGB`: canonical internal RGB representation;
- `XYZ-D65`: standards-oriented connection space;
- `HSL`: explicit display-oriented cylindrical representation for authoring/inspection;
- `OKLab`: perceptual-oriented representation for diagnostics and future appearance work.

HSL hue is normalized to `[0,1]`; for achromatic colors hue is canonically `0` because
hue is undefined when saturation is zero.

## Conversion policy

```text
hex sRGB
   ↓ IEC sRGB transfer
linear sRGB  ← canonical storage
   ↕
XYZ D65
   ↕
future color systems

linear sRGB ↔ OKLab
sRGB ↔ HSL
```

All conversion paths are deterministic and renderer-neutral.

## Gamut policy

There is deliberately **no implicit gamut mapping or clipping**.

If XYZ D65 or OKLab coordinates convert to linear sRGB outside `[0,1]`, the conversion
is rejected. Only tiny floating-point excursions around `0` and `1` attributable to
the published conversion matrices are normalized back to the exact boundary.

This prevents an apparently successful conversion from silently changing the requested
color.

## Alpha policy

Alpha is carried independently from RGB transfer functions. This checkpoint does not:

- premultiply alpha;
- composite foreground/background;
- blend colors;
- infer opacity from RGB;
- interpret transparency physically.

Those operations require separate contracts.

## BASE integration

`resolve_base_domain()` now passes its validated hexadecimal color through the canonical
color boundary before returning the same engine hexadecimal representation. This is an
identity for valid 8-bit sRGB channels apart from deterministic lowercase normalization.
It makes the canonical boundary executable without changing the existing BASE semantic
contract.

## Visual QA

The V1.24 visual QA produces:

- a deterministic multi-color contact sheet with source and conversion round-trip swatches;
- HSL, OKLab, XYZ D65 and linear-sRGB coordinates for the same colors;
- an sRGB transfer sanity board showing the non-linear relationship between encoded and
  linear-light values;
- machine-readable round-trip evidence and SHA-256 manifest.

The QA is diagnostic evidence, not a claim of production colorimetric certification.

## Verification

V1.24 tests cover:

- exact sRGB transfer reference values;
- canonical linear-sRGB storage;
- representative 8-bit RGB round-trips;
- all 256 alpha values for a fixed RGB sample;
- XYZ D65 reference primaries/white;
- OKLab reference red;
- HSL round-trips;
- OKLab and XYZ round-trips;
- out-of-gamut rejection;
- finite/range validation;
- achromatic HSL hue canonicalization;
- alpha independence;
- deterministic hexadecimal canonicalization.

## Explicit non-claims

V1.24 does **not** implement:

- palette generation;
- base-color composition/layer blending;
- shadows;
- highlights;
- lighting;
- BRDF/material shading;
- transparency/transmission compositing;
- reflection;
- style response;
- production color management/ICC profiles;
- HDR transfer functions;
- tone mapping;
- automatic gamut mapping.

Those remain separate future bricks.
