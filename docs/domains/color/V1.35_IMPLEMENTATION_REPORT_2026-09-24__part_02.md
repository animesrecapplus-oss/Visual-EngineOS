## 6. Scalar effects are not COLOR operations

The audit verified that:

```text
opacity
visibility
occlusion
```

leave RGB untouched.

Their behavior is limited to scalar resolution fields:

```text
opacity       → opacity
visibility    → visibility
occlusion     → visibility + opacity
```

Therefore they are not promoted into the COLOR architecture simply because they coexist
with color effects in `VisualEffect`.

## 7. Direct RGB arithmetic audit

A production search/AST audit was performed for direct encoded RGB arithmetic.

Before cleanup, the only direct duplicate RGB implementation outside the canonical color
boundary was:

```text
src/visual_engine/runtime/contract.py::_apply_shadow
```

The helper contained:

```text
hex → RGB bytes → interpolation → hex
```

It duplicated the already canonical V1.34 effect operation.

### Proof before deletion

The pre-cleanup evidence established:

```text
function definition = present
internal call sites = 0
repository call sites = 0
```

Evidence:

`artifacts/v135_effect_color_surface/V1.35_DEAD_HELPER_PRE_CLEANUP_EVIDENCE.json`

Only after this proof was the helper removed.

### Post-cleanup result

```text
DIRECT_RGB_ARITHMETIC_OUTSIDE_CANONICAL_BOUNDARY = 0
```

The remaining encoded RGB arithmetic is owned by the explicit color operation and the
canonical color-space implementation.

## 9. Version policy

No runtime algorithm was added or changed by V1.35.

Therefore the version policy intentionally remains:

```text
ENGINE_VERSION     = 1.3.8
PACKAGING_VERSION  = 1.3.8
RESOLUTION_VERSION = 18
SCHEMA_VERSION     = 2
```

Bumping the version merely because the audit has a new checkpoint would incorrectly
claim new runtime semantics.
