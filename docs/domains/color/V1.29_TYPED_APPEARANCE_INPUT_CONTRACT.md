# V1.29 — Typed Appearance Input Contract

**Date:** 2026-09-23  
**Checkpoint:** `V1.29_TYPED_APPEARANCE_INPUT_PROMOTION`

## 1. Purpose

V1.29 promotes the V1.28 `AppearanceRoleContribution` into the canonical renderer-neutral
appearance input envelope. The selected typed role is authoritative for BASE-domain color
resolution. The old `AppearanceResolutionInput.base_color` remains only as a derived
compatibility representation.

## 2. Canonical path

```text
BASE / Palette authority
        ↓
V1.27 composition
        ↓
V1.28 AppearanceRoleContribution
        ↓
V1.29 TypedAppearanceInput
        ↓
DomainResolutionInput(role_contribution=...)
        ↓
BASE domain resolver
        ↓
DomainResolutionResult + role provenance
```

No step in this path mixes colors, composites alpha, applies lighting or performs gamut mapping.

## 3. Typed input invariants

- one target ID;
- one selected `AppearanceRoleContribution`;
- role target must equal input target;
- no second BASE `AppearanceContribution` is allowed;
- active states are canonicalized;
- contribution IDs are unique;
- fingerprint is content-based and deterministic;
- geometry, transforms, renderer state and unrelated siblings are absent.

## 4. Legacy compatibility rule

`TypedAppearanceInput.legacy_base_color` is derived directly from the typed role.
`AppearanceResolutionInput.base_color` may still be populated for old callers, but when a
role contribution is present it must exactly equal the derived value. It is not an independent
source of truth.

The legacy `AppearanceContribution(domain=BASE)` path remains available only so historical
callers do not break before migration. The canonical V1.29 BASE path does not use it.

## 5. BASE domain contract

`build_base_resolution_input_from_role()` creates a BASE `DomainResolutionInput` with the typed
role and no legacy BASE contribution. The generic factory adds an explicit dependency named
`appearance_role_bridge` whose digest equals the role fingerprint.

The BASE resolver reads the typed role's compatibility representation only after the role object
has passed its own fingerprint and canonical-color invariants. The resolved domain field is then
validated through the existing BASE domain contract.

## 6. Provenance

`DomainResolutionProvenance` carries:

- `role_bridge_fingerprint`;
- `role_authority_component_id`;
- `role_source_id`;
- `role_lineage`.

The result validator compares all four values against the input role. A result cannot claim role
provenance if the input did not contain a typed role.

## 7. Invalidation and identity

The typed input fingerprint and the domain input digest change when the selected role authority
changes. Geometry-only mutations do not change the typed appearance fingerprint. The explicit
role-bridge dependency is included in domain dependency identity. No unrelated sibling dependency
is introduced by this brick.

## 8. Persistence and tampering

The component BASE authority remains the persisted source. A persistence round-trip must rebuild
the same role and typed-input fingerprints. Tampering with a persisted BASE fingerprint is rejected
before a typed input can be rebuilt from it.

## 9. Visual evidence

`artifacts/v129_typed_appearance_input/V1.29_TYPED_INPUT_SOURCE_TO_DOMAIN.png` shows actual runtime
values for object, hand and plant targets. The geometry is intentionally diagnostic, not production art.
The displayed color swatches are derived from the actual typed canonical color, and the BASE-domain
output is read from the actual resolver result.

## 10. Explicit non-goals

No lighting, shading, BRDF, metallic/roughness response, transmission compositing, reflection,
style response, gamut mapping or renderer-specific post-processing is part of V1.29.
