## Versioning decision

`RESOLUTION_VERSION` advanced from `12` to `13` because composition semantics participate in resolution
identity and therefore cache compatibility. Engine/package version remains `1.3.5`; schema remains `2`.

## Self-critique

The most important failure mode here is a visually plausible but semantically false result. Three
controls were therefore deliberately added:

1. duplicate slots are rejected before resolution;
2. missing slots never fall through to another semantic slot or ancestor authority;
3. composition returns an existing canonical color instead of constructing a blended color.

A second important blind spot is invalidation. A naive hierarchy fingerprint would invalidate every
child when an ancestor palette changes. V1.27 instead records only authorities that can change the
requested target's outcome.

The checkpoint also explicitly records that the active filesystem did not contain the previous V1.26
source archive. The palette layer was reconstructed from the preserved V1.26 implementation report
rather than silently treating a missing artifact as verified source.

## Explicit non-goals

V1.27 does not implement:

- shadows/highlights;
- ambient/key/fill/rim/bounce lighting;
- BRDF;
- metallic/roughness response;
- transmission compositing;
- reflection;
- style response;
- gamut mapping;
- renderer-specific post-processing;
- production color-management certification.

## Next step — V1.28 Renderer-neutral Appearance Role Bridge

1. Define a typed role-contribution envelope for BASE and Palette-selected canonical colors.
2. Bridge the legacy `AppearanceResolutionInput.base_color` hex field explicitly rather than silently replacing it.
3. Preserve source/provenance through the compatibility adapter.
4. Separate role-level invalidation from geometry and future lighting/material caches.
5. Add persistence/tampering/stale-provenance tests for the role envelope.
6. Sample generic object, hand and another non-ocular component family.
7. Produce a visual role-bridge board before any renderer integration.

Lighting, shading, BRDF, reflection, transmission, style response and renderer-specific post-processing
remain explicitly deferred.
