## 14. Next step — V1.33 micro-scope

The next runtime brick is conditional on a real downstream COLOR consumer becoming
identifiable.

### Micro-step 1 — establish the caller

- find the first production path that receives the typed COLOR result;
- prove its call path rather than inferring it from a field name;
- identify exactly which component/domain owns the call;
- record current legacy behavior before changing it.

### Micro-step 2 — freeze semantics

If the consumer transforms color, define:

- source `ColorRGBA` semantics;
- calculation color space;
- destination representation;
- alpha handling;
- parameter units/ranges;
- neutral parameter behavior;
- extreme values;
- out-of-gamut values;
- authored vs generated provenance;
- dependency identity;
- invalidation;
- cache key;
- deterministic serialization.

### Micro-step 3 — implement only one operation

Do not bundle saturation + contrast + vibrance + temperature into one generic
"color effects" layer. Implement the smallest operation actually required by the
real consumer.

### Micro-step 4 — visual acceptance

Generate source→operation→output samples using real runtime values. Inspect neutral,
mid-range, extreme and alpha-bearing cases. The visual result must agree with the
mathematical contract; mathematical correctness alone is not sufficient.

### Micro-step 5 — migrate one caller

Only after the operation contract and visual evidence are stable should one actual
consumer be migrated. No speculative migration is allowed.
