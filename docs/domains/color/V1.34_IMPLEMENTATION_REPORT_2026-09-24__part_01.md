# V1.34 — First Real Downstream COLOR Operation — Implementation Report

**Date:** 2026-09-24  
**Checkpoint:** V1.34 First Real Downstream COLOR Operation  
**Baseline:** V1.33 certified checkpoint  
**Runtime version:** 1.3.8  
**Resolution version:** 18  
**Schema version:** 2

## 1. Objective

V1.33 proved that the typed COLOR resolver itself had no downstream production
caller. The next brick therefore had to avoid inventing a consumer.

A second production-level trace found a real existing color transformation in the
generic component resolver:

```text
resolve_component()
    ↓
resolve_effects()
    ↓
shadow / tint
    ↓
legacy encoded-RGB interpolation
```

This is a genuine downstream color operation, although it is **not** a caller of
the typed `AppearanceDomain.COLOR` resolver. That distinction remains explicit.

The V1.34 migration therefore moves exactly this one operation behind an explicit
canonical `ColorRGBA` boundary and does not add any other color transformation.

## 2. What was found before coding

The existing operation was in `src/visual_engine/runtime/effects.py` as
`apply_shadow_color()` and was called by `resolve_effects()` from the generic
component resolver.

Its actual pre-V1.34 law was:

1. read RGB bytes directly from a `#RRGGBB[AA]` string;
2. linearly interpolate the encoded 8-bit RGB integer channels using
   `round((1-alpha)*source + alpha*target)`;
3. return a six-digit RGB string;
4. ignore the effect-color alpha byte;
5. silently strip the base-color alpha byte from the transformed result.

The fifth point was an actual semantic loss for the existing generic visual
contract, which already accepts `#RRGGBBAA` colors.

The operation was not saturation, contrast, vibrance, temperature, HSL grading,
OKLab grading, palette mixing, lighting or material response.

## 3. Semantic contract frozen before implementation

### Input representation

`ColorRGBA`, canonical linear-sRGB RGB plus unassociated alpha.

### Effect representation

`ColorRGBA` for the effect color plus independent `VisualEffect.alpha`.

### Calculation space

**Encoded sRGB 8-bit RGB.**

This is deliberate. Replacing the existing artistic effect with linear-light or
OKLab interpolation would be a visual redesign rather than a consumer migration.

### Output representation

`ColorRGBA`, canonical linear-sRGB RGBA.

### Alpha

- `VisualEffect.alpha` is the sole effect-strength parameter.
- base/target alpha is preserved unchanged;
- effect-color alpha is ignored, preserving the historical single-opacity
  authority;
- no premultiplied alpha;
- no hidden alpha compositing.

### Bounds and edge cases

- malformed/non-finite/out-of-range effect alpha: rejected;
- `alpha == 0`: strict identity, without quantizing the canonical base;
- `alpha == 1`: effect RGB replaces base RGB, while base alpha survives;
- intermediate alpha: established sRGB8 interpolation;
- effect colors remain inside sRGB gamut;
- no clipping or gamut mapping.

### Provenance / lineage / fingerprint

`EffectColorResult` records:

- operation ID;
- operation version;
- calculation space;
- base fingerprint;
- effect fingerprint;
- result fingerprint;
- ordered lineage.

Component-level `ResolutionProvenance` also names the operation ID/version and
calculation space for each shadow/tint application.

### Dependencies / invalidation / cache

The complete component resolution fingerprint already contains the relevant
hierarchy/component data and target-filtered effect context. V1.34 therefore
reuses the existing dependency/invalidation architecture instead of creating a
second cache.

Because runtime color semantics changed, `RESOLUTION_VERSION` was correctly
bumped from `17` to `18`. `ENGINE_VERSION` and package version moved from `1.3.7`
to `1.3.8`.

Unrelated sibling-targeted effects remain excluded from another component's
context fingerprint.

## 4. Implementation

### New module

`src/visual_engine/runtime/effect_color.py` — **128 lines**

Affected lines:

- 31–33: operation identity/version/calculation-space constants;
- 36–51: immutable result/provenance envelope;
- 54–58: alpha validation;
- 61–71: explicit sRGB8 interpolation law;
- 74–128: canonical operation, fingerprints and lineage.
