# V1.34 — First Real Downstream COLOR Operation Contract

## 1. Purpose

V1.33 proved that the typed `AppearanceDomain.COLOR` resolver has no downstream
production caller. V1.34 therefore does not fabricate one. It identifies the
first **actually reachable production color transformation** already present in
the generic runtime:

```text
resolve_component
    ↓
resolve_effects
    ↓
shadow / tint branch
    ↓
apply_effect_color
```

This is a downstream visual-effect operation, not a new caller of the typed
COLOR resolver.

## 2. Authority and boundary

The operation accepts two canonical colors:

- base color: `ColorRGBA` in canonical linear-sRGB RGBA;
- effect color: `ColorRGBA` in canonical linear-sRGB RGBA.

The legacy `#RRGGBB[AA]` strings are decoded only at the explicit compatibility
boundary in `resolve_effects` / `apply_shadow_color`.

The operation returns canonical `ColorRGBA`.

## 3. Calculation space

The existing production law interpolated **encoded 8-bit sRGB RGB channels**.
That law is retained intentionally because changing it to linear-light or OKLab
would be a visual behavior change, not a migration-only change.

```text
canonical linear-sRGB RGBA
        ↓
encoded sRGB 8-bit RGB
        ↓
weighted RGB interpolation
        ↓
canonical linear-sRGB RGBA
```

Python's existing `round()` behavior is preserved because changing the rounding
law would change some established 8-bit outputs.

## 4. Alpha

- `VisualEffect.alpha` is the sole effect-strength parameter.
- Base/target alpha is preserved unchanged.
- `VisualEffect.color` alpha, when present, is intentionally ignored. It is not
a second opacity authority.
- No premultiplied-alpha conversion occurs.
- No alpha compositing is performed by this operation.

## 5. Gamut

Both inputs must be valid canonical sRGB colors. The RGB result is a convex
interpolation of two in-gamut encoded sRGB values, so it remains representable
in sRGB. `ColorRGBA` remains fail-closed and no clipping or gamut mapping is
introduced.

## 6. Parameter behavior

- `alpha = 0`: strict identity; the canonical base color is returned without
quantization.
- `alpha = 1`: effect RGB replaces base RGB; base alpha remains unchanged.
- `0 < alpha < 1`: encoded-sRGB 8-bit interpolation.
- non-finite/out-of-range alpha: reject.
- malformed colors: reject through `ColorRGBA` / existing effect validation.

## 7. Provenance and lineage

Each operation result carries:

- operation ID: `effect.color.srgb8-interpolation`;
- operation version: `1`;
- calculation space;
- base fingerprint;
- effect fingerprint;
- result fingerprint;
- ordered lineage identifiers.

At component-resolution level, `ResolutionProvenance` records the operation ID,
version and calculation space for each shadow/tint application.

## 8. Dependencies, invalidation and cache

The operation fingerprint depends on:

- base color;
- effect color;
- effect alpha;
- operation identity/version;
- lineage;
- resulting color.

The existing component `resolution_fingerprint` remains the cache identity for
the complete resolved component. Its graph/context dependency model already
includes the relevant component visual data and targeted effects. V1.34 bumps
`RESOLUTION_VERSION` from `17` to `18` because runtime semantics changed.
Unrelated sibling-targeted effects remain filtered from another component's
context dependency.

## 9. Performance contract

- No color-space conversion is performed for components with only scalar
opacity/visibility/occlusion effects.
- A color effect materializes base fill/contour colors lazily.
- Each effect color is decoded once and reused for fill and contour.
- No global palette conversion or renderer-wide color pass is introduced.

## 10. Compatibility

`apply_shadow_color(base: str, effect)` remains as an explicit legacy adapter.
Internal `resolve_effects()` no longer uses it. This keeps the compatibility seam
visible and prevents a second hidden color implementation from becoming active.

## 11. Non-goals

V1.34 does not implement:

- saturation;
- contrast;
- vibrance;
- temperature;
- lightness grading;
- palette mixing;
- pattern generation;
- lighting;
- shading;
- BRDF/material response;
- tone mapping;
- gamut mapping;
- generic compositing.
