## 16. Next step — V1.31 micro-scope

V1.31 should **not** start by implementing a renderer or lighting model. The next
engineering target is the first genuinely typed COLOR-domain consumer, but only
after a separate COLOR contract is made explicit.

Required micro-steps:

1. define the semantic distinction between BASE and COLOR outputs;
2. decide whether COLOR consumes the selected role, a color pattern, or another
   typed source without duplicating BASE authority;
3. define allowed COLOR fields and their value spaces before implementing an algorithm;
4. decide exactly which provenance fields survive into COLOR resolution;
5. define COLOR dependencies and invalidation without geometry/transform leakage;
6. reject BASE/MATERIAL/LIGHTING fields smuggled into COLOR contributions;
7. implement the smallest deterministic COLOR resolver that the contract actually
   supports — no guessed interpolation or style behavior;
8. add object, hand and plant tests plus a Palette-selected case;
9. produce a visual source → typed COLOR input → COLOR-domain artifact and inspect it;
10. only after the contract and visual evidence agree, consider migrating the next
    legacy color consumer.

The legacy `AppearanceResolutionInput.base_color` field should remain compatibility-only
until an actual caller inventory demonstrates that its external/internal consumers have
migrated. No deprecation claim is made by V1.30.
