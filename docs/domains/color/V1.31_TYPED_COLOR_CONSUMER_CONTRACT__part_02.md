## 8. What COLOR does not do

V1.31 deliberately does **not** implement:

- color mixing;
- palette interpolation or generation;
- saturation/contrast/vibrance/temperature application;
- pattern generation;
- alpha compositing;
- lighting;
- shading or BRDF evaluation;
- material response;
- transmission/reflection;
- tone mapping or color grading;
- gamut mapping;
- renderer-specific post-processing.

These are separate semantic operations and must receive their own contracts before
being implemented.

## 9. Visual evidence boundary

The V1.31 visual board is generated from actual COLOR resolver outputs for:

- authored BASE with alpha;
- inherited BASE;
- authored Palette ACCENT;
- generated BASE.

The diagnostic shapes are not production artwork. The alpha-bearing case is shown
on a checkerboard for display only; runtime alpha remains unassociated. The board
prints the actual canonical output, source, role and authored representation so the
visual artifact can be compared directly with the runtime claim.

## 10. Definition of done

V1.31 is complete only when:

- the typed COLOR path is executable end-to-end;
- COLOR identity excludes unrelated domains and geometry;
- provenance survives intact;
- duplicate authority and domain leakage fail closed;
- generated colors do not falsely claim authored provenance;
- alpha remains data rather than compositing;
- targeted invalidation is covered;
- deterministic unit tests pass;
- the visual artifact has been manually inspected and corresponds to actual runtime outputs;
- release documentation and checkpoint evidence are synchronized.
