## 13. Self-critique and corrections

### 13.1 Dynamic effect kinds

The first audit version treated all non-literal `VisualEffect(kind=...)` construction as a
possible unresolved dynamic dispatch.

That was too coarse. Relation and consequence bindings already validate the kind through
the canonical `VisualEffect` contract.

The final audit therefore distinguishes:

```text
validated dynamic passthrough
        ≠
unresolved dynamic dispatch
```

The gate fails if the validation policy is absent.

### 13.2 Canonical effect operation detection

The first call-site detector looked only for attribute calls and therefore missed the direct
imported call to `apply_effect_color`.

The final detector handles both:

```text
apply_effect_color(...)
module.apply_effect_color(...)
```

The final audit reports two legitimate call sites: the compatibility adapter and the internal
canonical resolution path.
