# V1.36 — COLOR Downstream Audit — Implementation Report

**Date:** 2026-09-24  
**Checkpoint:** V1.36 COLOR Downstream Audit  
**Runtime change:** none by design  
**Previous certified checkpoint:** V1.35 VisualEffect COLOR Surface Audit

## Executive result

V1.36 was implemented as a strict audit brick, not as a speculative color-feature brick.
The audit enumerated canonical `ColorRGBA` consumers outside `color_spaces.py` and
`effect_color.py`, traced them to their actual owner, separated representation/persistence/
palette/compatibility/rendering from true color transformation, audited eye-specific color
separately, and searched for RGB/HSL/OKLab/XYZ operations outside the canonical color-space
boundary.

**Result: zero distinct new generic COLOR transformations were found.** Therefore no runtime
algorithm was added and engine/package/resolution versions remain unchanged at `1.3.8 / 18`.

## 1. Baseline verification before implementation

The V1.35 checkpoint was first verified with A10 and the relevant color/effect regression
suite. The pre-change evidence passed with no failure. This established a clean starting
point before V1.36 files were added.

## 2. Canonical `ColorRGBA` consumer inventory

171 production Python files were parsed. Outside the two canonical color modules, six files
contain direct `ColorRGBA` references:

| File | Actual owner | Classification | Transformation? |
|---|---|---|---|
| `components/common/base_color.py` | `BaseColor` authority | authority + representation conversion | No |
| `components/common/palette.py` | `PaletteEntry` / Palette authority | palette + representation conversion | No |
| `persistence/serialization.py` | persisted BASE/Palette reconstruction | serialization/deserialization | No |
| `runtime/appearance_contract.py` | domain validator | type validation | No |
| `runtime/appearance_role_bridge.py` | typed role bridge + legacy compatibility | compatibility/representation conversion | No |
| `runtime/effects.py` | existing shadow/tint path | already closed V1.34/V1.35 operation | No new operation |

The sixth entry is intentionally retained in the audit because it is a previously closed
operation path. It is not allowed to masquerade as a V1.36 discovery.

## 3. True downstream tracing

### BASE

`BaseColor.from_srgb()` decodes authored sRGB hex into canonical linear-sRGB `ColorRGBA`
and stores the authored spelling separately. `resolve_base_color()` and the role bridge carry
the same canonical object forward. No channel editing occurs.

### Palette

`Palette.from_srgb()` constructs `PaletteEntry.canonical_color`. Palette resolution selects
a slot and carries its canonical value. Slot selection is authority resolution, not channel
transformation.

### Typed COLOR

`TypedAppearanceInput -> TypedColorInput -> resolve_color_domain()` projects the selected role.
The resolver returns `role.canonical_color` directly. No linear/sRGB round-trip is inserted,
and no channel is modified.

### Compatibility bridge

`AppearanceRoleContribution` validates that authored/legacy hex represents the same canonical
value and derives a legacy string only when required. This is representation compatibility,
not a color transform.

### Persistence

`serialization.py` writes canonical channels and rehydrates `ColorRGBA` from the same numeric
channels. Fingerprints are checked after reconstruction. This is persistence, not color editing.

## 4. RGB/HSL/OKLab/XYZ audit

No HSL, OKLab, XYZ or sRGB-space operation was found outside the canonical color-space module
(except the already closed V1.34 effect seam, which is isolated in `effect_color.py`).

`ColorRGBA.distance_oklab()` computes a diagnostic distance. It does not mutate either input,
construct a transformed output color, or feed a color-changing downstream operation. It is
therefore classified as measurement, not transformation.

The audit also found no generic runtime RGB arithmetic candidate outside the canonical modules,
effect path, eye reference-analysis code and renderer code.

## 5. Renderer audit

`render/canvas.py` performs actual normalized RGBA arithmetic:

- source RGB is multiplied by source alpha;
- destination RGB is multiplied by `(1-alpha)`;
- alpha is accumulated;
- output is quantized to uint8.

This is a real rendering operation, but it does not consume `ColorRGBA` and belongs to the
renderer boundary. Promoting it into generic COLOR would conflate rendering with semantic
appearance resolution. V1.36 therefore records it as a renderer-owned operation and makes no
runtime change.

No production-art or color-management certification is claimed for this renderer seam.

## 6. Eye-specific audit

The eye production tree was scanned separately. It imports generic `ColorRGBA` zero times.
Eye appearance colors are explicit hex strings in sclera, iris, pupil, lashes, brows, eyelids,
reflections, caruncle and related structures. Eye SVG code consumes those authored strings
without entering generic COLOR resolution.

Eye reference acquisition/trace code performs RGB image analysis for segmentation and source
measurement. Those calculations operate on reference pixels and are not appearance color
transformations. They remain in the eye reference-analysis domain.

An actual eye SVG was generated and rasterized during V1.36 visual QA. The artifact is included
only to prove that the eye-specific color path still produces a visible, coherent result after
the audit; it is not a claim of anatomical or production-art fidelity.

## 7. Runtime immutability proof

The V1.36 verifier compared all 171 production Python files under `src/visual_engine` with the
V1.35 certified ZIP. The comparison was byte-for-byte:

- changed runtime files: 0;
- added runtime files: 0;
- missing runtime files: 0;
- runtime source unchanged: true.

Therefore the audit cannot accidentally introduce a hidden runtime semantic change.
