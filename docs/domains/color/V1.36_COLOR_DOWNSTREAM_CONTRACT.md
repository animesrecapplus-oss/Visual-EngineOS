# V1.36 — COLOR Downstream Audit Contract

**Checkpoint:** V1.36 COLOR Downstream Audit  
**Date:** 2026-09-24  
**Runtime semantic change:** none  
**Engine/package/resolution version:** unchanged from V1.35 (`1.3.8` / `18`)

## 1. Objective

V1.36 audits the remaining COLOR-bearing production surface outside:

- `src/visual_engine/runtime/color_spaces.py`
- `src/visual_engine/runtime/effect_color.py`

The purpose is to identify a **real downstream color transformation** before any new
algorithm is introduced. A field or conversion is not promoted to a COLOR operation
merely because it contains the word `color`, `RGB`, `HSL`, `OKLab` or `XYZ`.

## 2. Classification contract

Every observed canonical `ColorRGBA` use must be classified as one of:

1. **serialization/deserialization** — persistence of canonical channels and reconstruction;
2. **compatibility** — validation or derivation of a legacy representation from the canonical value;
3. **representation conversion** — conversion between explicitly declared color coordinate spaces;
4. **palette** — storage, authority, inheritance or slot selection without channel arithmetic;
5. **rendering** — renderer-owned color/alpha behavior after the generic semantic boundary;
6. **true color transformation** — a caller changes color coordinates and emits a changed color value.

A V1.36 PASS requires that any true transformation be either already closed by an
existing contract or explicitly frozen as a new operation before implementation.

## 3. Proven V1.36 result

The audit found the following canonical `ColorRGBA` consumers outside the two canonical
color modules:

- `components/common/base_color.py` — BASE authority and sRGB-to-canonical representation conversion;
- `components/common/palette.py` — palette authority/slot storage and representation conversion;
- `persistence/serialization.py` — persistence reconstruction;
- `runtime/appearance_contract.py` — canonical type validation;
- `runtime/appearance_role_bridge.py` — typed role bridge and legacy representation compatibility;
- `runtime/effects.py` — the already-closed V1.34/V1.35 shadow/tint operation path.

No HSL, OKLab, XYZ or other color-space operation was found outside the canonical
color-space module. `ColorRGBA.distance_oklab()` is a diagnostic distance measurement,
not a color transformation and has no downstream production transformation caller.

The typed COLOR resolver returns the selected canonical color unchanged. BASE and Palette
select authorities; they do not perform channel arithmetic.

## 4. Renderer boundary

`render/canvas.py` contains normalized RGBA arithmetic for alpha compositing and 8-bit
output conversion. This is renderer-local behavior over its own RGBA array and is not a
`ColorRGBA` consumer. V1.36 therefore records it explicitly but does **not** promote it
into the generic COLOR runtime.

This checkpoint does not claim that the renderer has a complete color-management model.
The renderer operation remains a separate future rendering/color-management concern.

## 5. Eye-domain isolation

The eye domain and eye SVG renderer are audited separately. Eye appearance fields remain
hex strings such as sclera, iris, pupil, lash, crease and reflection colors. Reference
acquisition may perform image RGB analysis for segmentation/calibration; those operations
are reference-analysis tools, not generic COLOR appearance transformations.

The eye production tree imports `ColorRGBA` zero times in V1.36. No HSL/OKLab/XYZ operation
exists in the eye production tree outside the canonical color-space module, and no eye
stylistic color behavior is promoted into generic runtime COLOR semantics.

## 6. No-new-algorithm rule

Because no distinct new generic COLOR transformation exists, V1.36 makes **no runtime
algorithm change**. In particular, this checkpoint does not add:

- saturation;
- contrast;
- vibrance;
- lightness adjustment;
- temperature/tint grading;
- palette mixing;
- pattern-to-color generation;
- lighting/shading;
- material response;
- gamut mapping;
- renderer color management.

## 7. Runtime immutability gate

The V1.36 gate compares every production Python file under `src/visual_engine` against the
trusted V1.35 checkpoint. Packaging performs a direct byte-for-byte comparison against the
V1.35 certified ZIP; the released checkpoint retains the resulting immutable SHA-256 file
fingerprint in `artifacts/history/v1.36/color_downstream/V1.35_RUNTIME_BASELINE_SHA256.json`. A PASS
requires all 171 production Python files to match, with no additions, removals or changes.

## 8. Visual acceptance

Actual runtime evidence must demonstrate:

- BASE-selected canonical COLOR reaches the resolver unchanged;
- Palette-selected canonical COLOR reaches the resolver unchanged;
- renderer-local RGBA compositing remains visibly separate from generic COLOR;
- an actual eye SVG sample renders its eye-domain colors without importing generic `ColorRGBA`.

The visual board is diagnostic evidence, not production-art, ICC, browser or final raster
quality certification.

## 10. Exit condition and next micro-scope

V1.36 exits with the generic COLOR surface intentionally unchanged. The next brick is
**not** “invent the next color feature”. It is to identify and prove one distinct real
production transformation, if one later appears.

If such a transformation is found, the next contract must freeze, before coding:

1. exact production caller and data path;
2. input representation and color space;
3. calculation space and quantization law;
4. output representation and color space;
5. alpha participation and premultiplication semantics;
6. channel bounds and neutral identity;
7. extreme values and failure behavior;
8. gamut policy and fail-closed behavior;
9. provenance and lineage;
10. dependency names and fingerprints;
11. invalidation causes;
12. cache identity and invalidation scope;
13. deterministic ordering/rounding;
14. performance and allocation behavior;
15. runtime samples and visual acceptance criteria;
16. adversarial tests and regression coverage;
17. documentation/history and exact source-line impact.

Only after this contract is frozen may **one** new operation be implemented.
