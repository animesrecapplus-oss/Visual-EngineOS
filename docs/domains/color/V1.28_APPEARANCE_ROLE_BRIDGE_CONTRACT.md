# V1.28 — Appearance Role Bridge Contract

## Purpose

V1.28 makes the boundary between the typed V1.27 appearance composition model and
the pre-existing `AppearanceResolutionInput.base_color` field explicit.

The legacy string is a **derived compatibility representation**. It is not a
second authority and it must never be resolved independently when a typed role
contribution is present.

## Contract shape

```text
AppearanceComposition
        ↓
AppearanceRoleContribution
├── role
├── source (BASE | PALETTE)
├── canonical_color (linear-sRGB RGBA)
├── authored_srgb (optional, exact)
├── authority_component_id
├── source_id
├── authority_fingerprint
├── composition_fingerprint
├── lineage
└── legacy_base_color (derived compatibility value)
        ↓
AppearanceResolutionInput
```

## Rules

1. Only a **resolved** V1.27 composition can cross the bridge.
2. `BASE` and `PALETTE` remain separate provenance sources.
3. No color mixing, alpha compositing, lighting, material shading or gamut mapping occurs.
4. If an authored sRGB representation exists, the exact authored spelling is retained and becomes the legacy compatibility value.
5. Generated colors have no authored representation; their legacy value is deterministically encoded from canonical linear-sRGB.
6. A second BASE contribution in the legacy contribution list is rejected rather than merged.
7. `AppearanceResolutionInput.base_color` must equal the bridge's derived compatibility value.
8. The typed contribution fingerprint covers all bridge inputs and is independent of geometry, transforms and renderer state.
9. Bridge invalidation delegates to the existing BASE and Palette dependency owners and narrows dependencies according to composition mode.
10. A sibling or unrelated geometry mutation is not a bridge dependency.
11. Tampered bridge fingerprints and contradictory legacy values fail closed.
12. The bridge does not persist a new independent color authority; persistence remains owned by the component/composition models.

## Legacy compatibility

Existing callers may continue to construct `AppearanceResolutionInput` directly.
They are not silently migrated. New bridge-aware callers use
`bridge_to_appearance_input()` so the old `base_color` field is derived from the
typed composition rather than authored independently.

## Explicit non-goals

- no palette mixing;
- no shadows/highlights;
- no lighting or BRDF;
- no material response;
- no transmission compositing;
- no reflection;
- no style response;
- no renderer-specific post-processing;
- no automatic gamut mapping;
- no PostgreSQL schema migration solely for this bridge.

## Definition of done

V1.28 is complete only when the typed bridge, legacy compatibility boundary,
provenance, targeted invalidation, adversarial tests, visual source→bridge
artifact and repository-wide release gates all pass. A class existing without
those proofs is not considered implementation completion.
