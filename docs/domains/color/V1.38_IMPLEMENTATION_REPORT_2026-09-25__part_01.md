# Visual Engine V1.38 — Implementation Report

**Date:** 2026-09-25  
**Checkpoint:** `V1.38_EFFECT_COLOR_SEMANTIC_CLOSURE`

## 1. Executive result

V1.38 completed the requested descent inside the existing `effect_color` path.

**No new color space and no new RGB transformation were introduced.** Instead, the audit
found two real closure issues inside the existing operation boundary and corrected them:

1. successive color effects were not carrying their complete prior color-effect lineage
   into the next `apply_effect_color()` call;
2. a caller-supplied `effect_fingerprint` could, in the old implementation, replace the
   actual effect-color dependency and therefore mask a color mutation if the external
   fingerprint stayed unchanged.

The corrections are metadata/invalidation/provenance semantics around the same
`effect.color.srgb8-interpolation` RGB law. They do not change the established sRGB8 visual
algorithm.

## 3. Alpha audit

All production calls use:

```text
effect_alpha = effect.alpha
```

The audit found **zero production uses of `effect.color.alpha` or equivalent implicit
color-alpha access**.

The runtime operation still:

- ignores effect-color alpha;
- preserves base alpha;
- uses `VisualEffect.alpha` as the sole RGB-effect strength;
- keeps opacity/visibility/occlusion outside the RGB operation.

## 4. Lineage correction

Before V1.38, each successive operation received only the current `(source_id, effect_id)`.
That was insufficient to distinguish different multi-effect histories that converged to the
same intermediate color.

V1.38 now accumulates:

```text
(source-A, effect-A)
(source-A, effect-A, source-B, effect-B)
(source-A, effect-A, source-B, effect-B, source-C, effect-C)
...
```

The same cumulative lineage is passed to both fill and contour. A deterministic lineage
fingerprint is computed once per effect step and shared by the two channels.

## 5. Fingerprint correction

The previous implementation allowed:

```text
effect_fingerprint = external fingerprint
```

to replace the actual `ColorRGBA` dependency.

V1.38 changes this to:

```text
actual effect color + optional external identity
```

The actual color is therefore always represented in the effective dependency fingerprint.
Tests prove that a color mutation changes both `effect_fingerprint` and the final operation
fingerprint even when the external fingerprint remains unchanged.

Fingerprint invalidation was tested for:

- base/effect color;
- effect alpha;
- ordered lineage/order;
- source ID;
- effect ID;
- operation version.

## 6. Effect ordering and duplicate IDs

The authoritative order remains:

```text
(priority, effect_id, source_id)
```

The tests prove:

- reversing input order does not change the resolved result;
- changing priority can change the result for non-commutative color effects;
- equal priority is deterministic;
- duplicate effect IDs fail closed.

The four requested successive combinations are covered:

```text
shadow → shadow

tint → tint

shadow → tint

tint → shadow
```

Each result is produced by the real runtime and checked against sequential application of
the same canonical operation.
