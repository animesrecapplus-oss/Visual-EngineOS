## 14. Explicit nonclaims

- a typed COLOR resolver downstream caller now exists;
- a generic color-intelligence engine;
- saturation/contrast/vibrance/temperature operations;
- linear-light shadowing;

- lighting/shading/BRDF;
- material response;
- production renderer color management;
- live PostgreSQL verification;
- production art quality.

## 15. Next step — V1.35

V1.35 should not automatically add another color algorithm.

The next brick should audit the remaining real color-effect surface and establish
whether any **distinct** production operation actually exists beyond the migrated
shadow/tint seam.

Micro-scope:

1. enumerate every remaining production consumer of `VisualEffect.kind` that can
   influence a color value;
2. distinguish `opacity`, `visibility` and `occlusion` from genuine RGB transforms;
3. verify that `shadow` and `tint` share one operation intentionally rather than
   hiding two different semantics;
4. inspect relation-generated effects and targeted effects for provenance and
   invalidation edge cases;
5. search for any remaining direct hex-RGB arithmetic outside the explicit
   compatibility/effect boundary;
6. if no new color transform is found, do not fabricate one;
7. if a distinct transform is found, write its semantic contract before coding;
8. preserve the same discipline for input/calculation/output space, alpha, gamut,
   provenance, lineage, dependency, invalidation, cache, determinism and visual
   acceptance;
9. generate runtime samples before claiming visual correctness.

The next checkpoint should therefore remain **one real operation at a time**.
