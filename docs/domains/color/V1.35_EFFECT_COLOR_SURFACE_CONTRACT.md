# V1.35 — VisualEffect COLOR Surface Audit Contract

**Checkpoint:** V1.35 VisualEffect COLOR Surface Audit  
**Date:** 2026-09-24

## Purpose

V1.35 closes the remaining ambiguity around the generic `VisualEffect` color surface after V1.34.
It is an audit/cleanup checkpoint, not a request to invent a second color algorithm.

The contract establishes exactly which effect kinds transform RGB and which operate only on scalar
visibility/opacity values.

## Classification contract

| `VisualEffect.kind` | Domain behavior | RGB operation |
|---|---|---|
| `shadow` | color effect | `effect.color.srgb8-interpolation` |
| `tint` | color effect | `effect.color.srgb8-interpolation` |
| `opacity` | scalar opacity | none |
| `visibility` | scalar visibility | none |
| `occlusion` | scalar visibility + opacity | none |

`shadow` and `tint` are two semantic entry kinds for one operation. They do not constitute two
independent algorithms.

## Effect creation paths

The audit covers all production paths that construct or inject `VisualEffect`:

1. direct `ResolutionContext.effects`;
2. the legacy `shadow_alpha` compatibility injection;
3. relation metadata `metadata["effect"]`;
4. consequence bindings.

Relation and consequence bindings may carry a dynamic `kind`, but the value is passed through the
canonical `VisualEffect` validator. An unresolved dynamic kind is not accepted as evidence.

## Color-space boundary

The only generic RGB transformation in this surface is:

```text
canonical linear-sRGB ColorRGBA
        ↓
encoded sRGB 8-bit RGB calculation
        ↓
canonical linear-sRGB ColorRGBA
```

The established V1.34 encoded-sRGB interpolation law remains versioned as:

- operation ID: `effect.color.srgb8-interpolation`
- operation version: `1`
- calculation space: `srgb-encoded-8bit`

No implicit gamut mapping, clipping, premultiplied-alpha compositing, lighting, material response,
or renderer-specific post-processing is introduced.

## Scalar-effect boundary

`opacity`, `visibility` and `occlusion` do not modify RGB. Their inputs affect only scalar resolution
fields. Their presence must not cause a COLOR operation to be inferred.

## Direct RGB arithmetic boundary

Direct encoded-RGB arithmetic is allowed only inside the explicit canonical color operation and the
canonical color-space implementation. Legacy helpers outside that boundary are prohibited.

V1.35 removes `runtime/contract.py::_apply_shadow` only after repository-wide proof that it has zero
call sites. The pre-cleanup proof is retained as checkpoint evidence.

## Provenance and invalidation

The existing V1.34 operation identity, effect lineage, effect fingerprint and resolution-level dependency
identity remain authoritative. V1.35 does not introduce a second cache namespace or invalidation rule.

## Visual acceptance

A runtime evidence board must demonstrate:

- shadow changes RGB;
- tint changes RGB;
- opacity leaves RGB unchanged and changes opacity;
- visibility leaves RGB unchanged and changes visibility;
- occlusion leaves RGB unchanged and changes scalar visibility/opacity.

The artifact is diagnostic runtime evidence, not a production-art quality claim.

## Explicit non-goals

V1.35 does not implement:

- saturation;
- contrast;
- vibrance;
- lightness adjustment;
- temperature adjustment;
- color mixing beyond the existing shadow/tint interpolation;
- pattern-to-color conversion;
- grading;
- lighting;
- shading;
- BRDF/material response;
- gamut mapping;
- renderer-specific color management.
