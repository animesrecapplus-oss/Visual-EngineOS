## 16. Next step — V1.29 Typed Appearance Input Promotion

V1.29 should promote the typed role contribution into the canonical renderer-neutral
appearance input and reduce the legacy hexadecimal field to a compatibility adapter.

Micro-functions:

1. define the canonical typed appearance input envelope;
2. make `AppearanceRoleContribution` the authoritative BASE/COLOR entry point;
3. explicitly mark legacy `base_color` as compatibility-derived;
4. make the BASE domain resolver consume typed role data;
5. reject typed/legacy divergence before domain resolution;
6. propagate role provenance into `DomainResolutionProvenance`;
7. include role-bridge dependency identity in domain fingerprints;
8. preserve geometry-independent invalidation;
9. add persistence/tampering coverage;
10. validate object, hand and another non-ocular component;
11. produce source → typed input → domain resolution visual evidence;
12. only then evaluate deprecating the legacy field.

No lighting/shading/material-physics/style system should be pulled into V1.29 merely to
make the bridge appear more complete.
