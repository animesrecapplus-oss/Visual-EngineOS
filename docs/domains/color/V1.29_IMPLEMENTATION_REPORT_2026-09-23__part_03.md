## 17. Next step — V1.30 micro-scope

### A. Legacy consumer inventory

1. search every `AppearanceResolutionInput.base_color` read;
2. classify each use as compatibility-only, genuine BASE-domain consumption, or future COLOR-domain
   consumption;
3. reject any consumer that treats the legacy string as a new authority.

### B. Canonical migration

1. migrate genuine BASE consumers to `TypedAppearanceInput` / `AppearanceRoleContribution`;
2. preserve authored-vs-generated semantics and source lineage;
3. retain the legacy field only at explicit adapters;
4. add fail-closed divergence tests for every migrated caller.

### C. First true COLOR-domain consumer

Only if the COLOR contract is explicitly ready:

1. define its non-mixing input/output vocabulary;
2. consume typed role data without copying authority into another field;
3. propagate role dependency/provenance;
4. prove invalidation and cache identity;
5. generate source→typed→resolved visual evidence and reject visually incorrect outputs.

### D. Regression/visual acceptance

1. render object, hand and plant before/after migration;
2. compare exact semantic values and visible swatches;
3. verify geometry-only changes do not invalidate appearance;
4. verify unrelated sibling changes do not invalidate appearance;
5. only then consider deprecating `AppearanceResolutionInput.base_color`.

No lighting/shading/BRDF/material-physics feature should be pulled into V1.30 merely to make the
pipeline appear more complete.
