# V1.30 — Typed BASE Consumer Migration Contract

**Date:** 2026-09-23  
**Checkpoint:** `V1.30_TYPED_BASE_CONSUMER_MIGRATION`

## 1. Purpose

V1.30 closes the remaining **internal consumer** gap after V1.29. The typed
appearance envelope already owned the selected role, but internal callers could
still theoretically fall back to the legacy appearance-input builder. V1.30
makes that compatibility path explicit and mechanically auditable.

## 2. Canonical path

```text
AppearanceComposition
        ↓
AppearanceRoleContribution
        ↓
TypedAppearanceInput
        ↓
TypedAppearanceInput.to_base_domain_input()
        ↓
DomainResolutionInput(role_contribution=...)
        ↓
BASE resolver
```

The typed role object is forwarded unchanged. The BASE resolver does not receive
a synthetic legacy `AppearanceContribution` on this path.

## 3. Compatibility path

```text
TypedAppearanceInput
        ↓
explicit as_legacy_appearance_input()
        ↓
AppearanceResolutionInput.base_color
```

This path exists only for callers that still require the historical envelope.
It is not a domain-consumer path.

## 4. Source-level invariant

`build_appearance_input()` is permitted inside `src/` only in these three
explicit boundaries:

1. `runtime/appearance_contract.py` — compatibility API definition;
2. `runtime/appearance_role_bridge.py` — typed role bridge;
3. `runtime/typed_appearance_input.py` — explicit legacy escape hatch.

A new internal source consumer fails the V1.30 static audit.

## 5. Provenance and identity

The migrated BASE path preserves:

- role fingerprint;
- authority component ID;
- source ID;
- lineage;
- `appearance_role_bridge` dependency digest;
- authored/generated distinction.

No geometry, transform, renderer state or unrelated sibling is included merely
because the target component changed spatially or because another sibling changed.

## 6. Compatibility semantics

The legacy `base_color` value remains derived from the typed role. Authored sRGB
spelling may preserve its original case and alpha bytes; resolver output may use
its canonical lowercase representation where the existing domain contract
requires canonical hexadecimal.

No color mixing, alpha compositing, gamut mapping, lighting or shading occurs.

## 7. Failure conditions

The implementation fails closed for:

- non-typed arguments passed to the typed BASE factory;
- contradictory `appearance_role_bridge` dependency fingerprints;
- a second legacy BASE contribution alongside a typed role;
- tampered role fingerprints;
- typed/legacy semantic divergence;
- hidden internal calls to the legacy builder.

## 8. Visual evidence boundary

The V1.30 visual board compares actual runtime values for object, hand, plant and
Palette-selected hand paths. It demonstrates semantic/path equivalence only. The
simple shapes are diagnostic proxies and are not presented as production artwork.

## 9. Explicit non-goals

V1.30 does not implement:

- a COLOR resolver algorithm;
- lighting;
- shading;
- BRDF;
- metallic/roughness response;
- transmission compositing;
- reflection;
- style response;
- gamut mapping;
- renderer-specific post-processing;
- deprecation/removal of the legacy public field.
