## 16. Final conclusion

V1.35 closes the remaining generic `VisualEffect` COLOR ambiguity without expanding the
architecture speculatively.

There is exactly one distinct color operation in this surface. `shadow` and `tint` are two
entry kinds for that operation. `opacity`, `visibility` and `occlusion` are scalar effects.
The duplicate unreferenced RGB helper is removed after proof, and no direct RGB arithmetic
remains outside the canonical boundary.

No second color algorithm is warranted by the current production code.

## 17. Next step — V1.36

V1.36 must not invent another effect-color operation.

The next micro-scope is a **non-effect downstream COLOR surface audit**:

1. enumerate every production read of canonical `ColorRGBA` outside `runtime/effect_color.py`
and `runtime/color_spaces.py`;
2. trace each result to its actual consumer rather than classifying every `ColorRGBA` reference
as a consumer;
3. distinguish renderer serialization/compatibility from real color transformation;
4. inspect palette resolution and appearance composition only for downstream transformations,
not for their already-closed authority-selection semantics;
5. audit eye-specific color/pattern code separately from the generic runtime so ocular style code
is not promoted into the generic COLOR architecture;
6. search for any remaining RGB/HSL/OKLab arithmetic that actually changes a color value;
7. if no distinct real transformation is found, make no runtime algorithm change;
8. if a distinct transformation is found, freeze before coding:
   - input representation;
   - input color space;
   - calculation space;
   - output representation;
   - alpha semantics;
   - channel bounds;
   - neutral case;
   - extreme cases;
   - gamut policy;
   - provenance;
   - lineage;
   - dependency fingerprint;
   - invalidation;
   - cache identity;
   - determinism;
   - performance budget;
   - visual acceptance criteria;
9. produce actual runtime samples before claiming the operation is visually correct.

The rule remains: **one real operation at a time; no feature is added merely to advance the version.**
