## 8. Cache contract

The first real request lifetime now justifies use of the existing caller-owned
`ResolutionCache`.

Observed real session behavior:

- first render: 3 geometry builds / 3 resolution stores;
- subsequent renders: geometry hits and resolution hits without rebuilding;
- 3 retained geometry entries;
- no eviction in the measured slice.

`ResolutionFingerprint.cache_identity` remains the only semantic resolution-cache identity.
No new cache key or invalidation law is introduced.

## 9. Memory policy

One actual session snapshot measured approximately:

- current traced allocations: **451,712 bytes**;
- peak traced allocations: **590,170 bytes**.

This is evidence for the selected slice, not a global engine memory budget. No new byte budget
is introduced in V1.45 because the existing cache bounds are sufficient for the measured
workload.

## 10. Persistence policy

No production restart/persistence consumer was discovered for rendered geometry or resolved
results. No serialized render cache is introduced.

## 11. COLOR boundary

The following canonical COLOR files are byte-identical to V1.44:

- `src/visual_engine/runtime/effect_color.py`;
- `src/visual_engine/runtime/effects.py`;
- `src/visual_engine/runtime/color_spaces.py`.

No new color transformation was added.

## 12. Teardown

The session is the explicit destruction boundary. Tests verify:

- caches are empty after `close()`;
- graph/root references are released from the session;
- rendering after close fails;
- stale topology fails before rendering;
- `refresh()` rebuilds the graph before another render.

## 13. Visual acceptance

Acceptance is not based on geometry hashes alone. Three actual PNG renders are generated
from the production session:

- front;
- +12° placement rotation;
- -12° placement rotation.

The board was manually inspected after generation. The first implementation was rejected
because the head painted over the eyes; the renderer paint-order fix was applied and the
board regenerated.

The accepted visual scope is explicitly limited to the geometry that exists today:
**head + two eyes**. Nose, mouth, ears and hair are not falsely represented as rendered
components because no production geometry generator exists for them yet.

## 14. Version boundary

`ENGINE_VERSION=1.3.8`  
`SCHEMA_VERSION=2`  
`RESOLUTION_VERSION=20`

The existing semantic/version contracts remain unchanged. V1.45 is a production-orchestration
checkpoint rather than a resolution-identity or schema migration.
