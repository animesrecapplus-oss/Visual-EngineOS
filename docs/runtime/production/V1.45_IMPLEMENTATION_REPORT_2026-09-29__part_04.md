## 13. Runtime cache evidence

The real production session was rendered repeatedly.

First request:

```text
GeometryCache
  builds = 3
  hits   = 0
  entries = 3
  bytes   = 47,468

ResolutionCache
  stores = 3
  hits   = 0
  misses = 3
```

After repeated requests:

```text
GeometryCache
  builds = 3
  hits   = 12
  entries = 3
  bytes   = 47,468

ResolutionCache
  stores = 3
  hits   = 12
  misses = 3
```

This is the first measured cache reuse on a real production caller rather than a diagnostic
frame-style loop.

## 15. Memory measurement

One actual session render was traced with `tracemalloc`:

```text
current = 451,712 bytes
peak    = 590,170 bytes
```

No global memory budget was introduced because this first real workload is small and the
existing bounded caches already provide an explicit entry/byte geometry bound plus an entry
bound for resolution.

## 16. Teardown

The session close boundary was tested.

Before close:

```text
RuntimeGraph retained by session
GeometryCache entries > 0
ResolutionCache entries > 0
```

After close:

```text
session._graph = None
session._root = None
GeometryCache entries = 0
ResolutionCache entries = 0
```

Rendering after close is rejected.

The test also confirms the session itself does not retain the authoring graph after teardown.

---

## 17. Stale topology

A real session was rendered, then the authoring root was mutated by adding a child.

The next render failed closed with the existing stale-graph rule.

`refresh()` then rebuilt the graph and the render succeeded.

This confirms the production owner did not bypass `RuntimeGraph.is_current()` semantics.

## 18. Determinism

Two fresh production sessions rendering the same authored face produce byte-identical SVG.

The benchmark's same-session deterministic SVG digest is also recorded in its artifact.
