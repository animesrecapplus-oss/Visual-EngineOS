### 4. Establish real geometry/appearance/render coupling

The slice must demonstrate an actual chain such as:

```text
production request
→ entity/component graph
→ RuntimeGraph
→ appearance resolution (if required)
→ geometry generation
→ spatial transform
→ renderer
→ real SVG/PNG artifact
```

Every arrow must be an actual runtime call, not a test harness shortcut.

### 5. Visual acceptance

At minimum the produced asset must be inspected for:

- correct geometry placement;
- correct bilateral/child relationships where applicable;
- correct appearance application;
- no clipping introduced by orchestration;
- no accidental coordinate-space inversion;
- no disappearance of generated geometry;
- deterministic repeatability;
- output file validity.

A mathematically valid contract with a visibly broken asset is a failed slice.

### 6. Cache/lifetime measurement after wiring

Only after the real request exists:

- measure repeated request reuse;
- measure graph rebuild cost;
- measure retained memory;
- measure cache cardinality;
- inspect LRU pressure;
- inspect teardown;
- decide whether `ResolutionCache` should be request-, scene- or another
  explicitly owned lifetime.

No partitioning or byte budget is added without evidence.

### 7. Cross-surface regression

After integration rerun:

- stale `RuntimeGraph` rejection;
- single-flight same-key behavior;
- resolution/geometry invalidation separation;
- cache identity stability;
- renderer determinism;
- visual regression;
- COLOR regression.

### 8. Scope discipline

V1.45 must not simultaneously introduce:

- a global scene manager;
- a generalized renderer framework;
- persistence for render caches;
- new COLOR transforms;
- animation;
- prompt compilation;
- speculative GPU infrastructure.

The goal is one real production slice that proves the architecture can leave the
library/test domain and become an actual engine execution path.
