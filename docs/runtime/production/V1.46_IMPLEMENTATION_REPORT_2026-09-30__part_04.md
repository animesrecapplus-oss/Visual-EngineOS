## 10. Visibility became a real production input

V1.45 already resolved visibility and opacity into `ResolvedVisualContract`. The generic renderer,
however, did not yet use zero visibility as an emission decision.

V1.46 closes that concrete seam in:

`src/visual_engine/render/geometry_svg.py:177–195`

For every owned path and primitive:

```text
resolved visibility <= 0 → omit geometry
resolved opacity <= 0    → omit geometry
otherwise                → emit normally
```

This is intentionally implemented at the renderer-neutral style boundary. The renderer does not
inspect `Component`, legacy appearance layers or domain-specific anatomy.

### 10.1 Actual visual evidence

Before changing visibility:

- six eye ellipses are emitted;
- both eyes are visible.

After setting the left eye's `VisualOverrides(visibility=0.0)`:

- three eye ellipses remain;
- the right eye remains visible;
- the left eye geometry is absent.

Artifacts:

- `V1.46_VISIBILITY_BEFORE.svg/.png`;
- `V1.46_VISIBILITY_AFTER.svg/.png`.

The board shows this before/after result directly.

### 10.2 What was deliberately not claimed

This is not yet full geometric occlusion integration.

The repository already contains a renderer-independent visibility/occlusion kernel, semantic
regions and depth relations. V1.46 does not wire that system into SVG draw order without a real
overlapping production component pair.

A draw-order heuristic would be a false positive: it could make a picture look correct while not
proving that the semantic blocked/visible regions are correct.

## 11. Fail-closed behavior preserved

The generic renderer still rejects unsupported geometry instead of silently dropping or guessing.

Tests cover:

- `GeometryContract.masks` → `ValueError`;
- unknown primitive kind → `ValueError`;
- invalid ellipse radii/non-finite ellipse data → existing fail-closed path;
- XML parse validation → existing `ElementTree.fromstring()` gate.

The nose deliberately does not require any of these unsupported mechanisms.

---

## 12. Cache identity and invalidation

`ResolutionFingerprint.cache_identity` was not changed.

Direct mutation of the nose width parameter changes the content-based geometry key without a graph
topology rebuild. `tests/unit/test_v146_production_slice.py:155–165` verifies that the resulting
geometry key changes and the second generation is not a cache hit.

This preserves the existing separation:

```text
topology freshness → RuntimeGraph
resolution identity → ResolutionFingerprint.cache_identity
geometry identity   → GeometryCacheKey / geometry fingerprint
```

No session identifier is inserted into either semantic identity.
