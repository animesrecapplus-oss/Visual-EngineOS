## 2. Why V1.46 was the next brick

V1.45 had proven that the repository could leave the library/test-only state and execute a real
entity-to-render request. It deliberately stopped before generalizing that owner.

The V1.45 roadmap identified five concrete questions:

1. Can more than one production session be alive safely?
2. What actually happens when sessions share a cache?
3. Does the workload justify cache partitioning?
4. Does multi-instance memory justify a new byte budget?
5. What is the next missing HumanFace geometry family that can be added using existing generic
   contracts rather than a new architecture?

There was also a small real seam in visibility: `ResolvedVisualContract` already carried
`visibility` and `opacity`, but the generic SVG renderer did not yet suppress zero-visibility
geometry.

V1.46 therefore addressed those questions directly rather than inventing a cache manager or
expanding COLOR again.
