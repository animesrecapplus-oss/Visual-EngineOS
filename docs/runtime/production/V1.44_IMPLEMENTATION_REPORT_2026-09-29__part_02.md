### 5.2 ResolutionCache

The cache remains a caller-owned optional dependency.

No production `ResolutionCache(...)` construction is introduced or discovered.

The V1.43 lifetime/ownership conclusion therefore remains valid.

### 5.3 Geometry generation

`CachedGeometryGenerator` and the geometry registry are real production library
classes/functions, but there is no downstream production module constructing or
owning the generation service.

The geometry generator tests and A8 harness exercise the API, but those are not
production call edges.

### 5.4 Entity factories

`visual_engine.entities` exports:

- `build_human_face`;
- `build_eye`.

No production module imports these factories.

This is strong evidence that the current entity factory layer is still an API
surface awaiting a production orchestration boundary rather than an already
wired production request path.

### 5.5 Renderer

`visual_engine.render` exports:

- `render_eye_svg`;
- `render_eye_pair_svg`.

No production module calls either renderer.

The renderer is therefore available and visually executable, but its current
callers are tests/tools rather than a production request owner.

## 6. Spatial layer: real production consumers, but not the missing vertical slice

The audit deliberately did not report zero production geometry/spatial activity.
There are real production calls to `resolve_geometry_contract()`.

They occur in spatial subsystems, including:

- `runtime/region_maps.py`;
- the ocular reference transform path.

Those calls transform already supplied geometry. They do not establish the missing
entity → generic resolution → geometry generation → renderer orchestration.

This distinction is important because reporting every geometry call as a
"vertical slice" would create a false positive.

## 7. Scene layer

`scene.composition` exposes:

- `Frame`;
- `Camera`;
- `Placement`;
- `CompositionPolicy`;
- `compose()`.

`scene.shot` exposes shot metadata.

The scene package does not import runtime resolution and does not own a generic
resolution request.

Two runtime modules import scene composition data. This is a data dependency,
not evidence that scene owns rendering or generic resolution.

## 8. A8: the crucial false-positive trap

The repository already contains a strong cross-layer verifier:

`tools/verify_a8_e2e.py`

It drives a small graph through:

```text
authoring graph
→ RuntimeGraph
→ generic appearance resolution
→ geometry generation/cache
→ spatial transform
→ renderer-neutral SVG evidence
→ persistence serialization
```

This could superficially look like the missing production vertical slice.
It is not.

Its own source contract explicitly calls it an integration **verification**
harness and states that it is not a second rendering engine.

V1.44 therefore keeps it outside `src/` and records it as verification evidence
only.

This is a deliberate fail-closed architectural decision.

---

## 9. A8 reproducibility evidence

V1.44 executed the A8 verifier twice from independent clean output directories.

Both runs produced identical values for:

- graph node count: `3`;
- second geometry-generation cache hit: `true`;
- generated geometry hash;
- generated geometry cache identity;
- resolution fingerprint identity;
- camera geometry hash;
- serialized component digest;
- SVG digest.

The two `REPORT.json` byte streams were identical.

The V1.44 visual QA tool removes the temporary A8 run directories after capturing
this evidence, preventing stale run data from being packaged as current evidence.
