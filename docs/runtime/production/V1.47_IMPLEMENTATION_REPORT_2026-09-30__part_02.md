## 6. Explicit depth

The head surface is authored at `depth_layer=0`.
The nose silhouette and its detail strokes are authored at `depth_layer=1`.

These values are not disguised physical coordinates. They define the local production ordering
needed by this one pair.

`render_geometry_svg()` consumes the optional layer when it exists. Legacy ocular paths without the
metadata continue to use the existing semantic paint-priority table.

This avoids changing unrelated eye rendering merely to support V1.47.

## 7. Production request integration

`ProductionVisibilityResolution` was added to `runtime/production_slice.py`.

The session now performs the following after generating and transforming the real geometry:

```text
camera GeometryContract
       ↓
extract exact head surfaces
       ↓
extract exact nose surfaces
       ↓
semantic RegionMap for head
semantic RegionMap for nose
       ↓
Occluder(nose, z=1)
       ↓
resolve_visibility(head, nose)
       ↓
resolve_visibility_attribution(head, nose)
```

The occluder geometry passed to the visibility kernel is the semantic-region polygon contract, not
the raw renderer path. This is the explicit bridge described above.

The production boundary rejects a nose with zero or multiple area regions. That prevents a future
geometry change from silently producing an incomplete visibility result.

## 8. Exact result on the production sample

Front sample:

- head area: `477069.0254120373`;
- nose area: `5856.446487016294`;
- blocked area: `5856.446487016296`;
- coverage: `0.012275889179680385`;
- remaining visibility: `0.98772411082032`;
- depth relation: `front`;
- target depth: `0`;
- occluder depth: `1`.

The tiny area discrepancy is floating-point noise; the public values are bounded by the existing
[0,1] contracts.

The same semantic relation survives +12° and -12° placement rotations.

## 9. Causal attribution

The existing attribution kernel reports the nose as the dominant occluder for the head region.
Because there is only one front occluder in V1.47, there is no shared-coverage competition yet.

This is intentionally not presented as a multi-occluder generalization. That is V1.48 territory,
only if another real production overlap exists.

## 10. Visual QA

The visual QA tool renders the actual production SVG/PNG and builds a diagnostic projection from
the exact semantic regions used by the kernel.

The board contains:

1. actual production render;
2. diagnostic head region;
3. diagnostic nose region;
4. blocked intersection region.

The diagnostic colors are not part of the production renderer.

### Visual acceptance

For front, +12° and -12°:

- front depth relation = true;
- coverage is strictly between 0 and 1;
- blocked fraction of nose ≈ 1;
- kernel blocked/nose raster IoU = 1.0.

Manual inspection found no eye clipping, no nose displacement relative to the head, and no
orientation inversion.

## 11. Performance and optimization

### 11.1 Before optimization

Recorded pre-optimization median visibility resolution:

`4,218,946.5 ns`

### 11.2 Hot-path defect

Inside `resolve_visibility()`, each planar arrangement cell repeatedly converted every front
occluder from `GeometryContract` to Shapely geometry. The same geometry was therefore rebuilt many
times during one resolution.

### 11.3 Optimization

The final implementation creates `front_regions` once per target region and reuses those objects
for intersection and cell membership.

### 11.4 After optimization

Final median:

`3,476,087.0 ns`

Measured improvement:

`17.6077%`

Warm full production render median:

`16,191,598.5 ns`

No visibility cache was added. The workload does not yet justify a separate cache lifetime,
identity, invalidation or partitioning contract.
