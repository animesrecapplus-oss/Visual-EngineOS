# V1.47 — Production Visibility Contract

## 1. Purpose

V1.47 is the first production consumption of the renderer-independent visibility and causal
attribution kernels. It does not generalize visibility to every face component. It proves one real
overlap: **HumanFace head as target, Nose as front occluder**.

The contract is deliberately narrow so that a mathematically valid but visually wrong result cannot
be hidden behind a generic abstraction.

## 2. Roadmap gate

The roadmap was checked before implementation. V1.46 completion required the next step to be one
real overlapping production visibility path. V1.47 therefore must not add another missing face
geometry family. Mouth, ear and hair remain outside this checkpoint.

## 3. Production ownership

The request owner remains `ProductionRenderSession`. The session already owns the RuntimeGraph and
caller-owned/session-owned cache semantics from V1.45/V1.46. Visibility does not introduce a global
manager or a second request lifetime.

`render_face()` produces the exact camera-space `GeometryContract` that is sent to the SVG renderer.
V1.47 derives the target and occluder regions from that exact contract before calling the visibility
kernel.

## 4. Geometry boundary

The generic visibility kernel continues to consume area primitives. It does **not** globally interpret
closed renderer paths as filled areas.

A semantic-region provider may explicitly promote a surfaced closed path to an area region:

```text
GeometrySurface(path_index, semantic_region)
        ↓
closed-path validation
        ↓
deterministic Bézier flattening
        ↓
Shapely region validation
        ↓
polygon primitive(s)
        ↓
existing visibility kernel
```

Open paths, including the nose nostril strokes, are not area regions. Paths with unsupported holes
are rejected rather than approximated.

## 5. Curve flattening

Cubic and quadratic Bézier paths are sampled deterministically. The flattening is used only for
semantic planar boolean geometry. The production SVG renderer continues to receive the original
Bézier commands, so the semantic region and visible curve are derived from the same source path
without replacing the actual render geometry.

This is not claimed to be a physical curve tessellation or a 3D surface reconstruction.

## 6. Depth contract

The production pair carries explicit integer `depth_layer` metadata:

| Surface | Layer | Meaning |
|---|---:|---|
| `head:head` | 0 | target/underlay |
| `nose:nose` | 1 | front occluder |
| nose detail strokes | 1 | same owner layer |

`depth_layer` is an ordering layer, not a physical z distance. V1.47 does not claim a z-buffer,
ray intersection or continuous 3D depth solution.

The same authored layer is consumed by SVG path ordering when present, so the visibility proof and
rendered paint order share the same explicit relation.

## 7. Visibility result

The production result contains:

- target component ID;
- occluder component ID;
- target/occluder depth layers;
- target semantic RegionMap;
- occluder semantic RegionMap;
- `VisibilityResult`;
- `VisibilityAttributionResult`.

The proof must report:

- blocked area;
- visible area;
- geometric coverage;
- depth relation;
- dominant occluder attribution.

For V1.47 the sole occluder is the nose, so its dominant coverage is expected to coincide with its
pairwise coverage up to floating-point tolerance.

## 8. Visual truth requirement

A PASS requires more than a boolean intersection result. The exact camera-space semantic region is
rasterized beside the actual production SVG/PNG. The blocked region is compared with the exact nose
region. The final samples are visually inspected at front, +12° and -12° placement rotation.

The diagnostic colors are not production colors. They exist only to make region mismatches visible.

## 9. Performance contract

No visibility cache is allowed merely because the kernel now exists. The real production cost must
be measured first. V1.47 measures repeated visibility resolution and warm render timing.

The hot path must not rebuild an identical Shapely region for every arrangement cell. Front
occluder regions are therefore materialized once per target region and reused for cell membership.

## 10. Fail-closed rules

- malformed/unsupported path commands cannot silently become areas;
- open paths cannot become semantic area regions;
- holes not representable by the generic polygon primitive are rejected;
- missing depth layer for the production pair is an error;
- inconsistent depth layers for one owner are an error;
- missing nose or multiple nose semantic regions are errors;
- duplicate/ambiguous attribution IDs remain rejected by the existing kernel;
- floating-point aggregate visibility is clamped only at the public [0,1] boundary.

## 11. Explicit non-goals

V1.47 does not implement:

- mouth/ear/hair geometry;
- physical 3D z-buffering;
- ray tracing;
- continuous orbital depth;
- global visibility manager;
- visibility persistence;
- visibility cache;
- spatial index;
- COLOR transformations;
- new appearance authority;
- automatic inference of semantic regions from arbitrary renderer paths.

## 12. Release evidence

The current evidence directory is `artifacts/current/v1.47/` and contains raw production
SVG/PNG samples, diagnostic boards, the visibility benchmark, test matrix, static audit,
optimization record and release gate.

The V1.47 gate is PASS only when all those evidence checks agree.
