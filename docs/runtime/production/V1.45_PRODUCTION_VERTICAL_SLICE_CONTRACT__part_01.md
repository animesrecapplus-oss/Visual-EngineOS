# V1.45 — First Production Generation/Render Slice Contract

**Date:** 2026-09-29  
**Baseline:** V1.44 certified checkpoint  
**Status:** **ENGINEERING PASS — FIRST REAL PRODUCTION VERTICAL SLICE**

## 1. Purpose

V1.44 proved that the repository had no production-owned end-to-end generation/render
caller. V1.45 deliberately closes that gap with one explicit, caller-owned production
boundary rather than another global orchestration layer.

The selected slice is the existing `HumanFace` entity family because it already has:

- a production entity builder (`build_human_face`);
- a validated `RuntimeGraph`;
- a real composite geometry generator (`face.human_with_eyes`);
- the existing geometry cache and dependency machinery;
- the existing spatial transform/placement/camera contract;
- a renderer-neutral `GeometryContract`.

The missing production seam was the generic renderer for that renderer-neutral contract.
V1.45 therefore adds a small fail-closed SVG renderer and one explicit render session.

## 2. Production owner and lifetime

`ProductionRenderSession` is the first real production owner.

Ownership is explicit:

```text
caller
  |
  +-- ProductionRenderSession
        |
        +-- RuntimeGraph
        +-- GeometryGeneratorRegistry
        +-- GeometryCache
        +-- ResolutionCache
        +-- render request(s)
        |
        +-- close()
```

There is no singleton, process-global cache, scene-global manager or hidden registry.

`close()` clears both caches and drops the session's graph/root/geometry-service references.
A returned `ProductionRenderResult` contains immutable render evidence and does not retain
the session graph.

## 3. Exact runtime chain

The production path is now:

```text
build_human_face()
      ↓
ProductionRenderSession
      ↓
RuntimeGraph.from_component()
      ↓
resolve_component(..., ResolutionCache)
      ↓
CachedGeometryGenerator.generate(...)
      ↓
face.human_with_eyes
      ↓
resolve_geometry_contract(... Placement/Camera)
      ↓
resolve child visual owners
      ↓
render_geometry_svg()
      ↓
validated SVG bytes
```

The AST audit identifies this exact chain in
`src/visual_engine/runtime/production_slice.py`.

## 4. Geometry composition correction

V1.45 exposed a real metadata defect in nested geometry composition:
child-local `path_index` values were being carried into the parent contract without a
global offset, and the original leaf owner could be overwritten by the parent merge key.

`merge_geometry_contracts()` now:

1. records the current path offset;
2. rebases every child surface `path_index` to the parent-global path index;
3. preserves the original leaf owner as `source_component_id`;
4. retains the parent merge owner as `component_id`.

No geometry coordinates or cache identity law are changed by this metadata correction.

## 5. Head ownership correction

The `face.human_with_eyes` preparation step previously produced the head geometry under a
synthetic `head` merge slot. V1.45 explicitly stamps the actual requested component id into
the head surface metadata before composition.

This prevents the renderer from having to guess which component owns the head surface.

## 6. Renderer contract

`render_geometry_svg()` supports only the primitives required by the current slice:

- `GeometryPath` commands already permitted by the generic geometry contract;
- `ellipse` primitives.

It rejects:

- any geometry mask;
- any unknown primitive kind;
- non-finite or non-positive ellipse radii;
- invalid SVG XML.

The renderer is intentionally fail-closed. It never drops unsupported geometry silently.

### Paint order

Composition order is not treated as a paint-order contract. The renderer explicitly paints:

1. head;
2. eye apertures;
3. eyelid contours;
4. crease/fold details;
5. caruncle details;
6. iris/pupil/reflection primitives.

This was required after visual inspection found that the original composite order caused the
head to cover the eye apertures.

## 7. Appearance boundary

Component appearance remains owned by the generic resolution contract.

The renderer receives `ResolvedVisualContract` values and does not inspect `Component`
objects or legacy appearance layers.

The renderer's fixed iris/pupil/reflection/caruncle values are explicit presentation defaults
for this first generic SVG backend. They are not COLOR-domain conversions, transformations,
palette resolution, grading, saturation, contrast, HSL, OKLab or XYZ operations.
