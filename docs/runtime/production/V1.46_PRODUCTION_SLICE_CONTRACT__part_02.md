## 7. Nose geometry contract

Generator: `face.nose`  
Composite: `face.human_with_eyes_nose`

The nose contains:

- one closed silhouette path;
- one left nostril open curve;
- one right nostril open curve;
- semantic surface labels `NOSE` / `NOSE_DETAIL`;
- local `center` and `tip` anchors;
- explicit width and height parameters.

The geometry is renderer-neutral. It contains no RGB transform, shading algorithm, texture
algorithm or renderer-specific primitive.

The generator deliberately does not claim full anatomical nasal morphology. It is a bounded
production slice chosen because the existing `GeometryContract`, `RegisteredGeometryGenerator`,
`GeometryCache`, `RuntimeGraph` and generic SVG renderer can consume it without inventing another
architectural layer.

## 8. Visibility contract

V1.45 already resolved `visibility` and `opacity` into `ResolvedVisualContract`, but the generic
SVG renderer did not yet consume the zero-visibility case as a production emission decision.

V1.46 closes that small real seam:

- owner visibility `<= 0` emits no owned path/primitive;
- owner opacity `<= 0` emits no owned path/primitive;
- normal visibility remains unchanged;
- child visibility can change independently through `VisualOverrides`;
- root visibility propagates through the existing resolver.

Visual evidence shows six eye ellipses before hiding the left eye and three afterwards.

This is **visibility**, not a fabricated occlusion solver. The repository already contains a
renderer-independent visibility/occlusion kernel; V1.46 does not silently infer occlusion from
SVG draw order. Actual overlapping-object occlusion remains a separate next production seam.

## 9. Fail-closed rules

The generic SVG renderer still rejects:

- non-empty `GeometryContract.masks`;
- unsupported primitive kinds;
- invalid ellipse radii/non-finite ellipse values;
- malformed XML.

The nose does not require masks or boolean subtraction, so no unsupported geometry was introduced
to make the sample look complete.

## 10. Determinism and lifecycle invariants

The following remain mandatory:

- fresh equivalent sessions produce byte-identical SVG;
- topology mutation makes the session stale until `refresh()`;
- default-owned caches are cleared by `close()`;
- injected shared caches survive the close of one session;
- direct visual/geometry parameter mutation changes content-based cache identity without requiring
a topology rebuild;
- `ResolutionFingerprint.cache_identity` remains unchanged;
- no global cache manager exists;
- no persistent render cache exists.

## 11. COLOR boundary

V1.46 does not modify the COLOR runtime. `effect_color.py`, `effects.py` and `color_spaces.py`
remain byte-identical to V1.45. No new color transform, palette resolver, gamut operation or
color-space conversion is introduced.

## 12. Acceptance gate

The V1.46 gate is PASS only when all of the following are true:

- static production audit passes;
- superseded V1.45 generated artifact directory is absent;
- shared and partitioned healthy-capacity workloads have equal reuse counts;
- undersized shared workload demonstrably shows LRU pollution;
- visibility mutation changes actual SVG output;
- visual board exists;
- repository tests pass with only the expected PostgreSQL skip;
- `compileall` passes;
- COLOR remains unchanged.

## 13. Next micro-scope — V1.47

The next step must **not** add several face parts at once. The next micro-scope is:

1. inspect the production visibility seam with one genuinely overlapping component pair;
2. select exactly one occluding family from the existing `Nose`, `Eye`, `Hair`, `Hand/Object`
   contracts only if an existing geometry/region contract can represent it without invention;
3. connect the existing renderer-independent visibility kernel to the production request boundary
   using explicit semantic regions and depth;
4. prove that the visible region, blocked region, dominant occluder and depth relation agree with
   actual rendered output;
5. generate before/after visual evidence for the overlap;
6. ensure masks/boolean geometry are used only when an existing contract truly requires them;
7. measure the cost of visibility resolution on real production geometry before caching it;
8. repeat multi-session, shared-cache, stale-graph, teardown and deterministic regression gates;
9. keep `ResolutionFingerprint.cache_identity` unchanged unless the resolution semantics really
   change;
10. keep COLOR frozen unless a real downstream consumer proves a missing contract.

Only after that evidence should the project consider a second non-ocular face family.
