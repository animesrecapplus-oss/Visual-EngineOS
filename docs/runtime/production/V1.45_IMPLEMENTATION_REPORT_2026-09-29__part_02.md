## 6. Generic renderer implementation

Created:

`src/visual_engine/render/geometry_svg.py` — **204 lines**

The renderer is intentionally fail-closed.

Supported now:

- `M`, `L`, `C`, `Q`, `Z` paths through the existing `GeometryPath` contract;
- `ellipse` primitives;
- resolved component fill/contour/opacity;
- explicit presentation defaults for iris/pupil/reflection/caruncle;
- deterministic XML assembly;
- final XML parse validation.

Rejected now:

- geometry masks;
- unknown primitive kinds;
- invalid ellipse radii;
- invalid SVG output.

This is deliberate. Unsupported geometry cannot silently disappear and still produce a
visually convincing but semantically false sample.

## 7. Geometry composition correction discovered during implementation

The first visual implementation exposed that nested surfaces carried child-local
`path_index` values into the composite geometry.

Example:

```text
left eye aperture = local path 0
right eye aperture = local path 0
```

After composition, both could incorrectly be interpreted as global path 0.

`src/visual_engine/components/common/geometry_composition.py` was therefore corrected.

New behavior:

```text
parent path count before child
        ↓
child local path index + parent offset
        ↓
global path index
```

The merge also preserves:

```text
source_component_id = original leaf owner
component_id        = current composite owner
```

This is metadata correctness, not a new geometry algorithm.

## 8. Head ownership correction

The composite face generator used the synthetic merge key `head` even though the actual
component could have an arbitrary id such as `face-01`.

The head surface is now explicitly stamped with the actual component id before composition.

This avoids a renderer-specific guess and keeps ownership information in the geometry
contract itself.

File:

`src/visual_engine/components/face/generators.py`

Affected final lines:

```text
177-193
```
