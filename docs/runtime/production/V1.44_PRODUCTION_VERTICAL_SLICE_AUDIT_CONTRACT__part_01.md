# V1.44 — Production Vertical-Slice Audit Contract

**Date:** 2026-09-29  
**Baseline:** V1.43 certified checkpoint  
**Status:** **AUDIT-ONLY — NO PRODUCTION VERTICAL-SLICE CALLER FOUND**

## 1. Purpose

V1.44 changes the question from cache ownership to the broader engine boundary:
where does a real production request enter the existing entity/component →
resolution → geometry → spatial → renderer path?

The audit must not confuse three different things:

1. a public library API;
2. a test/verification harness that drives several APIs together;
3. a production-owned orchestration path.

Only (3) can establish a real production lifetime or cache owner.

## 2. Production source boundary

The audit covers every `src/**/*.py` file and excludes tests, tools, generated
artifacts and historical documentation from the production call graph.

The scanner is AST-based. It resolves direct imports and import aliases, excludes
calls inside the module that defines the audited symbol, records public exports
separately, and fails closed if an ambiguous star import or dynamic import is found.

## 3. Vertical-slice surfaces audited

The following surfaces are explicitly tracked:

- `build_human_face()` / `build_eye()` entity factories;
- `RuntimeGraph.from_component()`;
- `resolve_component()` / `resolve_component_contract()`;
- `CachedGeometryGenerator` / `GeometryCache`;
- `resolve_geometry_contract()`;
- `Frame`, `Camera`, `Placement`, `compose()` and `Shot`;
- `render_eye_svg()` / `render_eye_pair_svg()`;
- `tools/verify_a8_e2e.py` as a separately classified verification harness.

## 4. Finding

The V1.44 source graph contains **172 production Python files** and no parse
errors.

External production call sites:

- generic resolver: **0**;
- `CachedGeometryGenerator` / geometry service ownership: **0**;
- renderer calls: **0**;
- entity-factory calls: **0**;
- ambiguous star imports from audited surfaces: **0**;
- dynamic `__import__` / `eval` / `exec` calls in production: **0**.

The existing production calls to `resolve_geometry_contract()` belong to spatial
subsystems (`region_maps` and the ocular reference transform). They are not a
component-to-render production entry point and are therefore retained as spatial
consumers rather than misclassified as vertical-slice orchestration.

## 5. A8 boundary

`tools/verify_a8_e2e.py` is an explicit integration verification harness. Its
source describes it as verification-only and not as a second rendering engine.
It drives authoring graph → runtime graph → appearance resolution → geometry
cache/generation → spatial transform → renderer-neutral SVG evidence.

It is therefore valuable evidence that the contracts can be connected, but it is
**not** evidence that a production owner currently performs that connection.

V1.44 never imports the A8 harness into `src/` and never promotes its local
renderer into a production backend.

## 6. Entity/renderer boundary

`visual_engine.entities` publicly exports `build_human_face` and `build_eye`, but
no production module imports those factories.

`visual_engine.render` publicly exports `render_eye_svg` and
`render_eye_pair_svg`, but no production module calls them.

This is an important architectural gap for the next engine-wide phase: the
libraries exist, but the repository does not yet contain a production-owned
request that consumes them end-to-end.

## 7. Generic resolution boundary

`resolve_component()` remains a production library API. Its implementation is
not counted as its own downstream consumer, and its compatibility wrapper is not
counted as an external caller.

No production module currently calls it.

Consequently, V1.44 does not create a renderer/frame/scene/request manager and
does not change `ResolutionCache` ownership.

## 8. Scene dependency direction

The scene package does not import the runtime package. Two runtime modules use
scene composition data (`Camera` / placement-related types), which is a dependency
on scene data rather than scene-owned generic resolution.

No scene → resolver → geometry → renderer orchestration is present.

## 9. Cache and lifetime policy

Because no production vertical-slice owner exists:

- no real frame lifetime is measured;
- no real scene lifetime is measured;
- no production cache cardinality is claimed;
- no production LRU pollution is claimed;
- no byte budget is added;
- no partitioning API is added;
- no persistence envelope is added.

The V1.43 `ResolutionCache` contract remains unchanged and
`ResolutionFingerprint.cache_identity` remains its sole semantic identity.

## 10. COLOR boundary

V1.44 introduces no COLOR runtime change and no new color transformation.

`effect_color.py`, `effects.py` and `color_spaces.py` remain outside the
vertical-slice orchestration change.

COLOR will only be reopened when a real downstream consumer demonstrates a
specific missing capability.

## 11. Visual evidence rule

The V1.44 board contains an actual renderer output produced by the existing
ocular renderer. It is explicitly labeled as a **library API sample**, not a
production render.

A8 is executed twice from clean output directories. The resulting report bytes,
geometry identity, resolution identity and SVG digest must match.

No synthetic geometry is painted into the evidence board as if it were production
output.
