# V1.3 — Semantic Relation Dependency Contract

## Why

The component hierarchy describes ownership, but visual resolution also depends on
cross-branch relations: a hand can cover an eye, a hand can deform a cheek, or an
object can occlude a face. Those dependencies must participate in invalidation before
any geometry cache is introduced.

## Direction

A relation normalizes to one of:

- `none`
- `source_to_target`
- `target_to_source`
- `bidirectional`

Known relation types are data-driven defaults. Unknown types are dependency-neutral
unless `metadata["dependency_direction"]` explicitly declares one. This avoids unsafe
guesses for application-specific relation names.

Current defaults:

| Relation | Direction |
|---|---|
| STRUCTURAL | source → target |
| SPATIAL | source → target |
| ANATOMICAL | source → target |
| GEOMETRIC | source → target |
| CONTACT | bidirectional |
| OCCLUSION | source → target |
| ATTACHMENT | source → target |
| DEFORMATION | source → target |
| CAUSAL | source → target |
| EXPRESSIVE | source → target |
| SEMANTIC | source → target |

The direction means **which resolved component depends on which other component**;
it is not a claim about physical causality.

## Transitive invalidation

For target `T`, the dependency set is:

`ancestors(T) + transitive_relation_dependencies(T)`.

Therefore:

`HAND --COVERS--> EYE`

makes the eye depend on the hand. If the hand changes, the eye cache entry is stale.
If another component unrelated to that dependency graph changes, the eye remains valid.
Cycles are permitted in relations and are handled with visited-set traversal.

## Relation-derived effects

A relation may explicitly declare a visual effect through:

```python
Relation(
    "hand", "OCCLUSION", "eye",
    metadata={
        "effect": {
            "kind": "occlusion",
            "alpha": 1.0,
            "visibility_factor": 1.0,
        }
    },
)
```

The relation itself does not automatically become an effect. The explicit `effect`
declaration is compiled to a normal `VisualEffect`, preserving the existing typed
effect composition laws and provenance.

`metadata["effect_target"]` may be `source`, `target`, or `null` (global effect).

## Determinism

Relation IDs are SHA-256 digests of the relation payload. Dependency edges and closure
are sorted deterministically. The dependency fingerprint contains the ordered
hierarchy chain plus sorted transitive relation dependency fingerprints.

This is the correctness boundary required before production geometry caching.

## Version boundary

Because relation dependencies and relation-derived effects change the meaning of a
resolved component, the default `VersionStamp.resolution` is now `3`. Existing
resolution identities from resolution `2` are therefore intentionally incompatible.
