# V1.3.4 — Geometry Transform & Composition Resolver

Geometry is generated in component-local coordinates. Spatial placement is resolved separately:

`component local → hierarchy/world → entity scene placement → camera`

The resolver composes 2D affine matrices and accumulates z independently for the current 2D renderer. `Camera.rotation_deg` is supported; camera z remains depth metadata rather than perspective projection.

`transform_geometry_contract()` transforms paths, supported geometric primitives, bounds and anchors. Unknown geometric primitive encodings fail closed instead of silently producing invalid occlusion data.

Supported primitive transforms currently include `ellipse`/`circle`, `point`, `line`, and `polygon`. Surface/mask semantic metadata is preserved.

This is intentionally **not** a 3D renderer or perspective camera. The contract prepares deterministic frame conversion and depth metadata for the future occlusion system.


## V1.23 ownership correction

`LocalTransform` is a generic spatial contract and therefore contains only:

- x/y translation;
- 2D roll (`rotation_deg`);
- scale_x/scale_y;
- z metadata.

Ocular yaw, pitch and alignment-axis rotation are not generic transform fields. They are
component parameters interpreted by the eye-specific runtime adapter. This prevents the generic
transform resolver from importing or executing ocular 3D semantics for arbitrary components.

Legacy serialized V1.13–V1.22 transform metadata is migrated into component parameters during
rehydration. Conflicting duplicated values are rejected rather than silently reconciled.
