# V1.3.5 — Generic Spatial Relationship / Placement Solver

**Status:** IMPLEMENTED — renderer-independent geometry-to-geometry placement foundation.

## Why this phase exists

The visibility kernel can already answer:

> Which part of a target geometry is covered by an occluder that is already in a known position?

That is not enough for the intended visual language. A prompt can specify a relation such as an object covering part of a target, but the engine must first resolve where the source object belongs relative to the target's actual geometry.

This phase therefore introduces a separate problem:

```text
SOURCE GEOMETRY + TARGET GEOMETRY + RELATIONSHIP INTENT
                         ↓
              SPATIAL PLACEMENT SOLVER
                         ↓
                RESOLVED TRANSFORM
                         ↓
                VISIBILITY KERNEL
```

The placement layer does not know what an object is. It does not contain rules for eyes, glasses, hair, hands, fingers, bandages, clothing or any other category.

## Core invariant

A qualitative prompt descriptor is not itself a dimension.

For example, `large` is resolved by morphology/generation into actual geometry before a dependent object is dimensioned or positioned.

Therefore the dependency is:

```text
prompt semantics
  ↓
morphology resolution
  ↓
source/target geometry
  ↓
relationship intent
  ↓
placement resolution
  ↓
visibility resolution
```

A camera zoom is deliberately outside this calculation. Geometry is resolved in its own coordinate frame; camera projection happens later.

## Contracts

### `AnchorReference`

Names an explicit anchor in a geometry contract. Missing anchors fail closed.

### `DimensionConstraint`

Expresses source width/height as ratios of target bounds. Values are dimensionless ratios, not pixel constants.

Examples:

```text
source width = target width × width_ratio
source height = target height × height_ratio
```

Uniform scaling requires compatible width and height constraints. Incompatible constraints are rejected rather than silently prioritizing one axis.

### `CoverageIntent`

Requests a geometric fraction of the target area to be covered by the source.

The first implementation supports uniform scaling only. The source anchor and target anchor must belong to their respective positive-area geometries so the scale search has a monotonic/nested geometric interpretation. If the requested fraction is unreachable under the fixed anchor/orientation/offset, resolution fails rather than returning a false solution.

### `PlacementIntent`

Contains:

- source/target IDs;
- source and target anchors;
- orientation;
- coordinate offset;
- uniform/non-uniform scale mode;
- optional relative dimension constraint;
- optional geometric coverage intent;
- explicit depth relation/offset.

Dimension and coverage constraints are mutually exclusive in this phase. There is no hidden precedence rule.

### `PlacementSolution`

Contains:

- source/target IDs;
- resolved translation;
- rotation;
- scale X/Y;
- depth offset;
- source/target reference points;
- resolved coverage and error when requested;
- deterministic diagnostics;
- affine transform matrix;
- point transformation helper.

## Transform semantics

The resolved transform is:

```text
p' = R(S(p)) + T
```

where scaling and rotation are defined around the source anchor during geometric evaluation. The final affine translation is solved so the transformed source anchor coincides with the target anchor plus the requested offset.

This prevents a common error where rotation changes the anchor location but the translation is still computed as if the object were unrotated.

## Coverage solving

For a requested fraction `f`:

```text
coverage(scale) =
    area(transformed_source ∩ target)
    ---------------------------------
             area(target)
```

The solver searches a deterministic uniform scale until the measured fraction is within the declared tolerance.

This is a geometric measurement, not a bounding-box approximation.

The source anchor is required to lie in the source region and the target anchor in the target region. This explicit precondition prevents a binary-search implementation from making an unverified monotonicity assumption.
