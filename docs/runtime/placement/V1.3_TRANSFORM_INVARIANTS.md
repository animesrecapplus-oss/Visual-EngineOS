# V1.3 — Transform Invariants Contract

## Objective

The transform layer is a mathematical contract, not a renderer convenience. A hierarchy must produce a deterministic world transform without decomposing a composed matrix back into TRS.

## Representation

Every `LocalTransform` is represented by a homogeneous 3×3 matrix:

`M = T(x,y) · R(rotation) · S(scale_x,scale_y)`.

The runtime composes in ancestor order:

`M_world = M_root · M_parent · ... · M_target`.

`z` is independent and additive. `geometry.local_z` is added only at the resolved target boundary.

## Invariants now tested

- identity is an exact identity matrix;
- translation maps local origin to `(x,y)`;
- zero scales are rejected;
- non-finite transform values are rejected;
- negative scales remain valid and represent mirroring;
- rotations are periodic (`θ` and `θ + 360°` agree within floating-point tolerance);
- composition is associative within an explicit numerical tolerance;
- homogeneous matrices remain finite;
- determinant of the linear 2×2 part equals `scale_x * scale_y` (orientation/mirroring signal);
- deep chains remain finite;
- translation is never reconstructed from a decomposed matrix.

## Why tolerance matters

`sin(360°)` and `cos(360°)` are floating-point computations. Exact equality is therefore not a valid general invariant for arbitrary angles. Tests distinguish exact structural identities from numerical identities and use explicit `abs_tol`/`rel_tol` where appropriate.

## Non-claims

This is still a 2D in-plane transform contract. It does not provide 3D yaw/pitch/roll, perspective projection, camera-space depth, or physical 3D binocular geometry.
