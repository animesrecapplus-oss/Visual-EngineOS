# V1.3 — Appearance Resolution Contract

## Scope

This checkpoint defines the renderer-neutral boundary between resolved component
state/effects and future appearance, color, material, lighting, transmission and
reflection resolvers.

It does **not** implement color mixing, lighting, physical material shading,
reflection, refraction, or renderer-specific output.

## Contract

```text
Resolved visual inputs
        ↓
AppearanceResolutionInput
        ↓
AppearanceResolutionResult
        ↓
future domain resolvers
   ├── Color
   ├── Material
   ├── Lighting
   ├── Transmission
   ├── Reflection
   └── Emission
```

`AppearanceContribution` is explicitly typed by `AppearanceDomain`. Its payload
is preserved as semantic data until a resolver for that domain exists.

## Non-negotiable separation

```text
base color ≠ material ≠ lighting ≠ reflection ≠ transmission ≠ emission
```

The contract therefore does not interpret a dictionary key such as `strength`,
`pattern`, or `color` as a physical operation.

## Current generic quantities

Opacity and visibility already have established composition laws in the existing
resolution system. The contract exposes them unchanged and reports their product
as `effective_visibility`.

## Appearance layers

`Component.appearance` is carried as explicit local data. No new implicit
hierarchical inheritance rule is introduced by this checkpoint; existing
resolution documentation remains authoritative on that point.

## Fail-closed boundary

Domains not yet implemented are reported as unresolved:

- lighting
- color
- transmission
- reflection
- emission

No automatic conversion into a different domain is permitted.
