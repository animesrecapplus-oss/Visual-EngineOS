# V1.3.4 — Generic Interaction / Consequence Resolution

**Status:** IMPLEMENTED — declarative event-to-consequence kernel.

## Purpose

The visibility kernel now emits `AffectedRegionEvent`. This phase adds the
smallest downstream layer needed to interpret those events without embedding
anatomy, clothing, hand, eye, hair or object-specific logic into geometry.

The pipeline is:

```text
Geometry
  ↓
Visibility
  ↓
AffectedRegionEvent
  ↓
ConsequenceRule matching
  ↓
ConsequenceRequest
  ↓
future State / Geometry / Appearance / Interaction resolvers
```

## Rule model

A `ConsequenceRule` matches only generic event/region properties:

- event kind;
- semantic region kind;
- semantic region tags;
- coverage interval;
- residual visibility interval;
- transmitted visibility interval;
- depth relation.

The rule emits a declarative request with a consequence kind:

- `STATE`
- `EFFECT`
- `GEOMETRY`
- `APPEARANCE`

The resolver does **not** apply those consequences. This is deliberate: mutation
belongs to the corresponding downstream subsystem and must remain independently
testable and cacheable.

## Example

A rule may state:

```text
when coverage is between 0.30 and 0.70
and the region has tag "sensitive"
→ request state "covered-partially"
```

No occluder type is required.

The same rule can therefore apply to any object whose geometry produces the same
visibility event.

## Explicit non-goals

This phase does not claim to solve:

- anatomical deformation;
- facial expression inference;
- physical collision response;
- material shading;
- color intelligence;
- automatic semantic tagging;
- state mutation;
- geometry mutation;
- object-specific interaction semantics.

Those remain separate systems.

## Determinism

Rules are evaluated by priority and stable rule ID. Requests are canonically
sorted by target, region, source event and rule ID. Payloads include measured event
quantities rather than recomputing them downstream.
