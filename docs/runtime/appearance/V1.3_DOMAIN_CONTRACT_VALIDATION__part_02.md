## STATE and EFFECT

`AppearanceDomain.STATE` and `AppearanceDomain.EFFECT` remain in the global domain
taxonomy because they are useful resolution/control envelopes. They are **not**
validated by this rendering-domain registry. Their existing state/effect contracts
remain authoritative. This prevents a second state/effect schema from being created
inside appearance validation.

## Failure policy

Validation fails closed with `DomainContractError` when:

- a rendering-domain key is unknown;
- a required field is absent;
- a value has the wrong semantic kind;
- a bounded numeric value is outside its declared interval;
- a vector contains non-finite values or has the wrong dimensionality.

There is no fallback domain, coercion, silent clipping or guessed interpretation.

## Integration point

`resolve_appearance_contract()` now validates all contributions before producing
its immutable result envelope. Domain algorithms remain downstream. Existing layer
resolution still produces raw contributions; the bridge therefore exposes invalid
legacy payloads at the appearance-contract boundary instead of silently assigning
meaning to them.

## Determinism and immutability

Validation does not reorder or mutate contribution payloads. Domain definitions are
static data. The same contribution either passes or fails identically regardless of
caller order.

## Explicitly not implemented

This checkpoint does **not** implement:

- color mixing or color-space conversion;
- palette generation;
- material shading;
- lighting equations;
- shadows or global illumination;
- Fresnel/reflection sampling;
- refraction/transmission solving;
- emission propagation, bloom or tone mapping;
- renderer-specific behavior.

Those are subsequent algorithmic layers and must consume these validated semantic
payloads rather than redefining their vocabulary ad hoc.
