## Remaining V1.3 gates

### R1 — Property semantics

**Status: partially implemented.**

Transform, z, opacity, visibility and new visual overrides have defined policies. Appearance layers, constraints and relations still need explicit policies.

### R2 — Visual override model

**Status: implemented foundation.**

Field-level overrides exist. Partial contour/material overrides are supported. Full appearance-layer inheritance remains separate.

### R3 — Transform invariants

**Status: partially implemented.**

Matrix composition exists and is tested for basic hierarchy composition. A formal numerical tolerance/invariant suite for rotation, non-uniform scale and deep chains remains.

### R4 — State resolution

**Status: foundation only.**

State names merge deterministically. Conflict/precedence/transition semantics are not implemented.

### R5 — Effect context

**Status: foundation.**

External shadow/occlusion/state context is typed. Geometric effect resolution is not implemented.

### R6 — Resolved component envelope

**Status: implemented foundation.**

The envelope exists and is returned by `resolve_component`.

### R7 — Diagnostics

**Status: minimal foundation.**

A deterministic trace exists. Complete per-field provenance is not implemented.

### R8 — Cross-process determinism

**Status: not yet completed.**

Need subprocess/serialization tests proving equivalent canonical output across independent processes.

### R9 — Performance

**Status: not yet completed.**

Need measured benchmarks at 1 / 100 / 1,000 / 10,000 components and profiling of traversal versus resolution versus geometry.

### R10 — Version invalidation

**Status: not yet completed.**

The future cache must know exactly which changes invalidate transform, geometry, visual, state and profile results.

### R11 — Database migration compatibility

**Status: not yet completed for this checkpoint.**

Forward/rollback tests and live PostgreSQL verification remain separate gates.

## Explicit nonclaims

The following are not implemented merely because related data structures exist:

- true 3D ocular geometry;
- 3D binocular convergence;
- anatomical eyelid deformation;
- physical corneal optics;
- biological tear dynamics;
- true reflection projection;
- general polygonal occlusion;
- production geometry cache;
- quantitative visual regression;
- prompt-to-semantic compilation.

## State / Effect precedence audit — added checkpoint

The previous deterministic state-set merge was insufficient for a production generic component contract because it could not explain conflicts, exclusivity, or dependencies between states. It is now replaced by an explicit precedence resolver.

The previous scalar shadow context was also too specialized. It remains compatible, but resolution converts it into the generic effect system so future geometric occlusion/shadow solvers have one renderer-neutral effect boundary.

The current resolver still does not infer effects from relations or geometry. That omission is deliberate and remains a V1.5 geometric-occlusion responsibility.
