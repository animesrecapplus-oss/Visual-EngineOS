### Mathematical contract

The open contour traversal is:

`upper(inner→outer) → outer bridge → lower(outer→inner) → inner bridge → upper`.

The renderer's sampled cubic interpolation gives an endpoint derivative of
`(P2-P0)/2` at each open-curve endpoint (with the corresponding reversed-lower
ordering). A cubic bridge `B(P0,P1,P2,P3)` has derivatives `3(P1-P0)` and
`3(P3-P2)`. The bridge therefore uses `P1=P0+T_start/3` and
`P2=P3-T_end/3`, making both endpoint derivative vectors equal to the adjacent lid
vectors. This is **C1**, not merely G1. C2/curvature continuity is not claimed.

`opening == 0` is treated as an explicit degenerate state. It is not falsely promoted
to a non-degenerate C1 contour.

### Implementation

- Created `src/visual_engine/components/face/eyes/geometry/continuity.py`.
  - `ContourContinuityReport` records four canthus derivative errors, minimum tangent
    norm and maximum attachment/tangent error.
  - `_endpoint_tangent()` centralizes the renderer-compatible endpoint derivative
    convention.
  - `_bridge()` constructs C1 cubic bridges without renderer-specific logic.
  - `build_canthus_bridges()` owns outer/inner closure ordering.
  - `assess_contour_continuity()` checks finiteness, exact endpoint attachment and
    C1 derivative equality.
  - `closed_contour_samples()` produces deterministic bridge samples for topology
    checks.
- Extended `EyeGeometry` with geometry-owned `outer_canthus_bridge` and
  `inner_canthus_bridge` control tuples.
- Updated `geometry/builder.py` to build and validate bridges **after** gaze-follow,
  then run the complete closed-contour self-intersection check including the bridges.
- Updated `components/face/eyes/generator.py` so the renderer-neutral geometry
  contract contains the cubic bridge commands rather than a hidden straight closure.
- Updated `render/eye_svg_primitives.py` to serialize the geometry-owned bridge
  controls. The renderer no longer computes a canthus radius or invents a closure.
- Corrected the contour module documentation so it no longer claims a C1 closure that
  it does not own.
- Hardened `geometry/invariants.py`: default self-intersection tolerance is now
  scale-relative (`1e-12 * contour scale`) while explicit epsilon remains available.
  This was required by a real boundary false-positive discovered at `opening=1e-6`.

### Adversarial correction history

- **Correction 1 — false C1 documentation:** the old contour docstring claimed horizontal
  tangent/C1 closure although the geometry did not contain such a closure. The contract
  was redefined from actual derivatives before implementation.
- **Correction 2 — renderer duplication:** the old SVG renderer recomputed a canthus
  radius. This was removed; bridge controls are now produced once by geometry.
- **Correction 3 — near-zero opening false positive:** the existing absolute
  `1e-9` self-intersection epsilon reported a legitimate tiny bridge as intersecting
  when `opening` approached zero. The detector now uses a scale-relative default.
- **Correction 3b — tiny-geometry tangent threshold:** a fixed endpoint-tangent
  epsilon would reject valid geometry at very small authored scales. Continuity's
  tangent and derivative tolerances are now scale-relative as well.
- **Correction 4 — topology checked at the wrong boundary:** checking only the upper+
  lower lid samples was insufficient. The complete closed contour, including bridge
  samples, is now checked.

No renderer-side visual workaround was used.
