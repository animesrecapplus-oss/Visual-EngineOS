# V1.3 — Audit, Status and Work Ledger

## Why this file exists

This is the factual tracking document for V1.3. It distinguishes:

1. what exists in code;
2. what is tested;
3. what is only represented/documented;
4. what remains unimplemented;
5. what is deliberately outside the current milestone.

No feature is marked implemented merely because a class, enum, database column or document exists.

## Audit baseline

The baseline was inspected from `visual_engine_v1.3_geometry_contract.zip` before implementation continued.

Verified baseline characteristics:

- generic `VisualContract` exists;
- `LocalTransform` exists;
- `GeometryContract` exists;
- `RuntimeGraph` indexes hierarchy/relation endpoints;
- historical visual resolver exists;
- historical resolver composes parent transforms;
- historical resolver multiplies visibility/opacity;
- historical resolver accepts external shadow/occlusion/state context;
- geometry identity uses SHA-256;
- the baseline had no explicit field-level visual inheritance mechanism;
- the baseline did not expose a generic `ResolvedComponent` envelope;
- geometry path validation accepted arbitrary command names/arity beyond finite-number validation.

The baseline archive's README/status count must not be treated as authoritative without executing the test suite.

## Implemented in this checkpoint

### 1. `VisualOverrides`

Added explicit child-level inheritance semantics.

Fields support:

- fill color;
- contour field overrides;
- material field overrides;
- opacity;
- visibility.

`None` means inherit.

Legacy `Component.visual` remains explicit for compatibility.

### 2. `ResolutionContext`

External resolution inputs are now grouped into a typed context:

- shadow alpha/color;
- occluder identifiers;
- active states.

This reduces an ever-growing resolver argument list without introducing semantic component knowledge.

### 3. `ResolvedComponent`

The generic resolver now returns an envelope containing:

- stable component ID;
- component kind as metadata only;
- resolved visual contract;
- local geometry contract;
- deterministic trace.

### 4. State-name merging

Enabled component state-layer names are merged with context state names and sorted. This is a deterministic foundation, not a full state conflict solver.

### 5. Geometry path validation

The path contract now validates the currently supported command set and arity:

```text
M = 2
L = 2
C = 6
Q = 4
Z = 0
```

Unknown commands and wrong arity are rejected at the model boundary.

## Tests added in this checkpoint
