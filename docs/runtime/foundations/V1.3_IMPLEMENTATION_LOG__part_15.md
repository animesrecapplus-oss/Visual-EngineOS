## V1.4 functional brick — MOR CanthusMetrics — 2026-09-17

### Objective

Implement the next small step after `EnvelopeMetrics`: quantify the already-resolved inner and outer
canthus bridges so the geometry can later be compared against the anime reference families without
using vague labels such as “soft”, “large”, “pointy” or “triangular”. This brick measures; it does
not alter the bridge.

### Audit before implementation

`geometry/continuity.py` already owns cubic bridge construction, endpoint tangent matching and
sampling. `EnvelopeMetrics` already owns the invariant eye frame. Recreating either geometry or the
local frame would duplicate canonical logic. Therefore `CanthusMetrics` consumes the existing cubic
controls and semantic canthi only.

### Implementation

- `src/visual_engine/components/face/eyes/morphology/canthus_metrics.py` — **L1-L243**.
  Canonical `CanthusMetrics` dataclass and `measure_canthus()`. The bridge is represented as a cubic
  `B(t)`; chord `C=||P3-P0||`; arc length is `integral ||B'(t)||dt`; curvature is
  `(x'y''-y'x'')/||B'||^3`; total absolute turning is `integral |kappa| ||B'||dt`; endpoint tangent
  angles use the same inner→outer eye frame as `EnvelopeMetrics`. The layer exposes normalized arc
  length, turning efficiency, minimum-speed ratio, raw and normalized curvature peak, endpoint
  curvature concentration over the first/last 20% of arc length, smallest sampled half-turn window,
  maximum perpendicular chord deviation, curvature sign changes and a bounded diagnostic
  `triangle_evidence` index.
- `src/visual_engine/components/face/eyes/morphology/__init__.py` — **L1-L6**. Exported the
  canonical metric type/function.
- `tests/unit/test_v14_mor_canthus_metrics.py` — **L1-L136**. Seven focused tests cover a straight
  zero-curvature bridge, current-engine bridges, rigid-transform/scale invariance, sampling
  convergence, malformed/degenerate inputs and the non-binary status of triangular evidence.
- `tools/visual_qa_v14_mor_canthus_metrics.py` — **L1-L138**. Eight actual eye-family cases produce
  SVG/PNG renders and inner/outer sampled diagnostics; three synthetic curves (`straight`,
  `rounded_quarter`, `pointy_two_stage`) calibrate detector response. The manifest is deterministic;
  timings are intentionally separated into `performance_timing.json`.

- `docs/components/eyes/morphology/V1.4_MOR_CANTHUS_METRICS_CONTRACT.md` — **L1-L116**. Mathematical contract, numerical
  quadrature policy, diagnostic triangle evidence and explicit nonclaims.

### Mathematical / anti-false-positive decisions

1. The eye axis is inherited from `EnvelopeMetrics`; the bridge is never re-oriented by a second
   coordinate system.
2. Tangent angles are measured relative to the eye axis, so rigid scene rotation does not change
   morphology angles.
3. Arc length and total absolute curvature use fixed 128-point Gauss-Legendre quadrature; diagnostic
   sampling does not redefine these primary integrals. The 128-node choice was challenged against an
   independent 256-node calculation across current bridge families; maximum observed primary-integral
   difference was below `6e-10`. This is empirical validation, not a universal error bound.
4. A bridge with a zero-speed point is rejected rather than assigned an arbitrary curvature.
5. `turning_efficiency = |net_turn| / total_abs_turning` exposes over-turning and non-simple tangent
   travel instead of hiding it behind C1 endpoint equality.
6. Endpoint curvature concentration is measured by arc-length windows, not by curvature-mass windows.
7. `max_chord_deviation_ratio` quantifies third-side/bulge geometry but is not inherently “bad”.
8. `triangle_evidence` combines endpoint concentration, curvature peak/mean, turning inefficiency and
   chord deviation as a diagnostic signal only. No binary acceptance threshold is embedded; a future
   threshold must be calibrated from digitized reference curves.
9. Synthetic evidence proves that a pointy two-stage cubic scores materially above a rounded quarter
   arc, while a straight bridge scores zero. This validates detector direction without claiming an
   anime truth range.
10. Visual QA deliberately overlays the sampled bridge points on the actual rendered eye. This prevents
    accepting numerically coherent metrics whose underlying geometry is visibly wrong.

### Visual challenge findings

The generated current-engine cases visibly confirm the previously observed point/triangle-like
canthus termination in several families. The metrics expose the same problem numerically: current
bridges can have low turning efficiency and very high endpoint curvature concentration. This brick
**does not correct that defect** because correction belongs to a separate geometry-generation step.
That separation is intentional: measurement must first tell us exactly what changed.

The synthetic comparison also shows why `arc_to_chord_ratio` alone is insufficient: a rounded curve
can have substantial chord deviation without being pointy, while a pointy two-stage curve can have
an arc/chord ratio close to 1 but extremely concentrated curvature.

### Performance overlay

A first implementation used adaptive Simpson integration, but the performance challenge showed it was
needlessly expensive for this fixed cubic diagnostic. It was replaced by fixed 128-point Gauss-Legendre
quadrature after an independent 128-vs-256 node comparison across current bridge families. The QA
records geometry build, inner/outer metric extraction, SVG serialization and PNG rasterization
separately. Timing is not included in the deterministic manifest. The exact values for the accepted
run are stored in `artifacts/v14_mor_canthus_metrics/performance_timing.json` and appended to the
chronological performance history.
