### Objective

Close the next architectural gap after V1.3.6: relations could already produce an
explicit `PlacementIntent`, but the system lacked a formal hard-constraint boundary
for containment, clearance and penetration.

### Implementation

Added `src/visual_engine/runtime/placement_constraints.py`.

Implemented:

- `ContainmentConstraint`;
- `ClearanceConstraint`;
- `NonPenetrationConstraint`;
- `PlacementConstraintSet`;
- `ConstraintCheck`;
- `ConstrainedPlacementSolution`;
- `validate_placement_constraints()`;
- `resolve_constrained_placement()`.

Added `resolve_placed_geometry()` to `runtime/placement.py` so a solved relation can
be materialized as a renderer-independent `GeometryContract` without mixing scene
or camera composition into placement.

Extended `runtime/spatial_relationships.py` so explicit relation placement metadata
can declare a closed `constraints` mapping. Unknown constraint names fail closed.
The normal relation-placement path now enforces declared constraints rather than
silently ignoring them.

### Engineering policy

The implementation deliberately does not introduce a generic optimizer. The current
placement variables have an analytic solution; hard geometric predicates are then
validated against the resulting geometry. If a hard condition is not satisfied,
the resolver fails rather than inventing a correction or trade-off.

### Tests

Added `tests/unit/test_v13_placement_constraints.py` and extended relation-placement
tests for explicit constraint metadata and unknown-constraint rejection.

Coverage includes containment, clearance, non-penetration, exact materialization of
resolved geometry, relative dimensions, deterministic validation, and fail-closed
metadata parsing.

## V1.3 placement → materialized geometry → visibility closure

Implemented the first closed generic spatial-impact path:

`PlacementSolution → Resolved Source Geometry → Source Semantic Regions → Visibility Kernel → AffectedRegionEvents`

The new `runtime/placement_visibility.py` materializes the resolved affine placement exactly once, resolves source semantic regions through the registered provider or generic primitive-labelled fallback, transforms those regions into the target frame, constructs a renderer-independent `Occluder`, and invokes the existing overlap-safe visibility kernel.

The implementation contains no object-type branches. The source may be any component kind and the target may expose arbitrary semantic regions. The kernel determines affected target regions from geometry/depth/optical properties, not from names such as eye/hand/glasses/etc.

Validation includes partial coverage, frame materialization, rotation/scale/translation without double application, and behind-depth rejection. Full test suite passes.

Current boundary: this closes the one-source placement-to-impact loop. It does not yet provide unique causal attribution for multiple overlapping occluders, physical 3D optics, or downstream mutation of state/appearance. Those remain separate contracts.

## V1.3 — Visibility Causal Attribution checkpoint — 2026-09-14

### Objective

Resolve the remaining ambiguity after multi-occluder overlap-safe visibility:
which portions of a target region are uniquely covered, jointly covered, depth
-dominated, or optically attributable to each occluder.

### Implementation

Added `runtime/visibility_attribution.py` with:

- `AttributionKind`;
- `OccluderAttribution`;
- `VisibilityAttributionResult`;
- `resolve_visibility_attribution()`.

The resolver builds a deterministic planar arrangement from the target and all
front occluder intersections. Each cell receives a depth-ordered occlusion stack.
Pairwise intersections remain geometric facts; exclusive/shared/dominant measures
are derived from the cell partition; optical marginal loss is computed by an
explicit counterfactual removal of one layer from the same stack.

### Important semantic boundary

The existing `AffectedRegionEvent` contract was not redefined. Its pairwise event
must not be interpreted as unique causal ownership when multiple occluders overlap.
`OccluderAttribution` is the explicit causal-attribution contract.

### Verification

- dedicated attribution tests: PASS;
- full pytest suite: PASS;
- `python -m compileall -q src`: PASS.

The suite is now 252 test functions at this checkpoint.

### Explicit non-goals

No object-specific branches, no 3D optics, no refraction/diffraction, no semantic
interpretation of object names, and no downstream mutation of state/appearance.
