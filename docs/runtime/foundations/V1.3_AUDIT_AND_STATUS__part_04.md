## Latest checkpoint — Domain Resolver Input/Result Contract

**Status: implemented and verified.**

The appearance pipeline now has a second explicit barrier after domain payload
validation: the resolver transaction contract. One resolver input owns one rendering
domain, carries explicit dependency identities and resolver identity, and revalidates
its contributions. Resolver results are immutable, status-explicit, provenance-aware
and restricted to the existing domain vocabulary.

The contract deliberately does not implement domain algorithms. No color mixing,
material shading, lighting, transmission, reflection, emission, rasterization or
renderer-specific behavior is claimed.

**Verification:** 318 tests passed; `compileall` passed.


## Latest checkpoint — BASE Domain Resolution — 2026-09-15

**Status: implemented and verified.**

The first concrete appearance-domain resolver is now present. BASE resolution is
strictly single-authority: one opaque contribution resolves; zero, multiple, or
translucent contributions reject explicitly rather than inventing precedence or
compositing behavior. The result uses the existing domain/result/provenance contract.

**Verification:** 332 tests PASS; `compileall` PASS.

**Remaining:** multi-contribution BASE composition, alpha compositing, color-space
semantics and all other appearance domains remain unimplemented.


## Latest checkpoint — MATERIAL Domain Resolution — 2026-09-15

**Status: implemented and verified.**

The second concrete appearance-domain resolver treats one non-empty opaque MATERIAL
contribution as an authoritative record. It preserves the validated field values
and rejects ambiguous cardinality, empty authority and translucent authority. No
material composition or physical shading is claimed.

**Verification:** 341 tests PASS; `compileall` PASS.

## A0 corrective audit — 2026-09-15

The full-project audit identified and corrected four runtime correctness defects:

1. global visibility aggregation with no front occluder;
2. duplicate/overlap-unsafe legacy coverage implementation;
3. geometry cache omission of authored `Component.geometry`;
4. ocular extreme-gaze and closed-lash behavior.

It also identified a hard placement gap for brows and a lifecycle ambiguity around mutable
`Component` objects referenced by `RuntimeGraph`. The brow gap is now enforced. The graph
lifecycle remains an explicit documented contract: authoring mutation requires rebuilding
the runtime graph; no hidden synchronization was introduced.

The audit also confirms that projected external shadow geometry is not implemented and must
remain a separate future domain. It must be capable of affecting individual semantic eye
regions/components without object-specific branches.

Current A0 verification: 347 collected tests pass; compileall passes; deterministic ocular
SVG/PNG evidence is stored under `artifacts/qa_v13_a0/`.

## A0 structural closure audit — 2026-09-15

The two structural A0 residues were reworked rather than merely documented:

1. **RuntimeGraph lifecycle** — graph indexes are immutable; a deterministic topology/relation
   digest detects post-compilation hierarchy/relation mutation; graph queries fail fast on stale
   topology; `rebuild()` is the explicit lifecycle transition.
2. **PostgreSQL lifecycle** — ordered SQL migrations are now executed through a transaction,
   recorded in `schema_versions`, protected against gaps/unknown versions, and exposed through
   the repository. A live integration gate exists but only runs with an explicit PostgreSQL DSN.
3. **Eyebrow reference frame** — the brow is anchored to a full-opening upper-lid-fold reference,
   not the state-dependent visible aperture. Closed/covered eyes therefore retain the same
   superior anatomical relationship.

This checkpoint is **not** A10. A10 remains the independent second full-project audit after
A3-A9 have been addressed.

## A0 structural closure re-audit 2 — 2026-09-15

The previous structural-closure PostgreSQL claim is superseded. A migration-runner defect was
found: migration `001` could be recorded in `schema_versions` without executing its DDL. The
runner now executes every missing migration, including `001`, before recording its checksum and
committing the transaction. Checksum drift, unknown versions, gaps and checksum-less legacy
history are rejected.

RuntimeGraph compilation also now fails closed on malformed cycles, repeated component-object
references and parent-link mismatches. The eyebrow regression is tested against the actual emitted
SVG path, not only internal reference fields.

Current verification: **364 collected / 363 passed / 1 skipped**; compileall PASS; deterministic
ocular QA PASS. The one skipped test is the optional live PostgreSQL pytest gate because no
`VISUAL_ENGINE_POSTGRES_DSN` exists in this environment. The strict live gate exits status 2 in
that situation. Therefore live PostgreSQL remains **UNVERIFIED**, not PASS.

## A4 — Master documentation / vision / roadmap / status reconciliation — 2026-09-16

**Status: implemented and verified.**

A4 was audited before editing. The existing documents contained correct historical evidence but
several current-status surfaces were stale: `ROADMAP.md` still presented semantic regions and the
visibility foundation as future work, `ENGINE_VISION.md` repeated that old frontier, and the generic
component contract still described state precedence and geometric occlusion as absent. The decision
ledger also contained duplicate IDs.

### Reconciliation performed

- `ENGINE_VISION.md`: current frontier now distinguishes implemented 2D semantic/visibility foundations
  from remaining interaction, 3D, rendering and optical nonclaims.
- `ARCHITECTURE_CONTRACT.md`: current state semantics and A3 fingerprint identity are aligned with
  the implementation; A4 synchronization is now normative.
- `ARCHITECTURE_PRINCIPLES.md`: reviewed as stable; no contradictory implementation-status claim required.
- `ROADMAP.md`: current authoritative state and execution order now point to A5–A8 hardening; old
  checkpoint history is explicitly historical.
- `V1.3_GENERIC_COMPONENT_CONTRACT.md`: completion matrix now reflects the implemented state-policy
  resolver and the implemented renderer-neutral 2D visibility kernel.
- `DECISIONS.md`: duplicate decision headings were assigned unique IDs D-043 through D-050; D-051 records
  the synchronization policy.
- `V1.3_IMPLEMENTATION_LOG.md`: this A4 operation is recorded chronologically.

### Explicit nonclaims preserved

A4 does **not** claim production rendering, 3D optics, physical shadow projection, complete interaction
application, live PostgreSQL verification, cross-process test execution evidence, or quantitative visual
acceptance. Documentation synchronization is not evidence of implementation by itself.
