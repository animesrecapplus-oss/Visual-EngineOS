## V1.3 — A10 independent second full audit — 2026-09-16

### Pre-implementation audit

A10 was explicitly checked before implementation. No completed A10 gate, second independent audit harness, or
cross-source structural-closure evidence existed. A9 already covered adversarial/property behavior, so A10 was
kept independent rather than duplicating those tests.

### Audit axes

The second audit inspected and cross-checked:

- architecture ownership versus compatibility facades;
- top-level import dependency topology and fresh-interpreter imports;
- version policy versus package metadata;
- migration identifier ordering and uniqueness;
- current documentation status versus roadmap checkboxes and nonclaims;
- previous A4–A9 verification gates;
- deterministic A8 evidence reproducibility across two independent runs;
- persistence/cache/renderer status claims and their explicit environmental limits;
- source/test compilation and complete pytest execution.

### Concrete findings and corrections

1. The Phase-1 roadmap contained a residual semantic-region contradiction: its prose said the foundation was
   implemented while a broad checkbox still marked semantic geometry as future. The checkbox was split into the
   implemented V1.3 semantic-region foundation and the still-planned production semantic-geometry layer.
2. Internal source modules still imported the historical `visual_engine.model` compatibility facade. Those imports
   were routed to `components.common`, leaving `visual_engine.model` as a compatibility-only public surface.
3. Stable digest ownership created a dependency-cycle risk between `versioning` and relation dependency indexing.
   The digest primitive moved into `runtime.identity`, a lower-level module with only canonicalization dependency;
   `runtime.versioning.stable_digest` remains publicly available for compatibility.

### Implementation and verification

Added an independent structural test suite and fail-closed verifier. The verifier does not trust A9 as proof: it
re-runs A4–A9, performs its own AST/import/version/documentation/migration checks, runs a fresh package import smoke,
compiles source/tests, executes full pytest, and compares A8 report SHA-256 across two consecutive runs.

Final verification result:

- A10 verifier: **PASS**.
- A4–A9: **PASS**.
- Full pytest: **PASS — 412 collected tests**.
- `compileall -q src tests`: **PASS**.
- Top-level import graph: **acyclic**.
- Fresh package import smoke: **PASS — 90 discovered modules**.
- A8 evidence reproducibility: **PASS — identical report SHA-256 across two runs**.
- Live PostgreSQL: **UNVERIFIED**.
- Package build: **NOT VERIFIED** because build tooling/backend was unavailable.

### Structural decision

A10 establishes **bounded V1.3 structural closure**. The audited architecture, contracts, canonical ownership,
implementation/test synchronization, documentation, versioning, cache identity and renderer-facing structural
boundaries are closed for the current checkpoint. Future interaction/deformation, production color/lighting,
physical optics, complete 3D, prompt compilation, animation and production artistic quality remain outside this
closure.

## V1.4 Eye Deepening — atomic/subatomic decomposition — 2026-09-16

### Audit before implementation

Before adding a new eye subsystem, the existing documentation and source were inspected for prior coverage. The audit
confirmed that the project already contains substantial atomic foundations for morphology, gaze/pupil containment,
explicit eyelids/folds, lashes, eyebrows, highlights, expression presets, pair constraints, renderer-neutral geometry,
camera-frame transforms, appearance contracts, visibility/coverage and deterministic identity/cache infrastructure.
It also confirmed that several broader claims remain only partial or planned: deep iris microstructure, full pupil
behaviour/deformation, anatomical eyelid solving, advanced lash/brow morphology, physical/scene reflection, colour
intelligence, camera projection/LOD, prompt-to-parameter compilation, constrained near-infinite variation and the
complete visual acceptance loop.

No existing A0–A10 gate was duplicated. This checkpoint instead adds the missing **planning/coordination layer** needed
to execute those remaining eye systems without conflating a broad workstream with a completed feature.

### What was implemented

- Created `docs/components/eyes/blueprint/V1.4_EYE_ATOMIC_BLUEPRINT__part_01.md`, a human-readable work breakdown covering **284 atomic/subatomic tasks**
  across 17 streams.
- Created `docs/components/eyes/blueprint/index.json`, the machine-readable source of truth for stable task IDs, status,
  stream relationships and mandatory evidence fields.
- Created `docs/components/eyes/blueprint/V1.4_EYE_EXECUTION_PROTOCOL.md`, defining the mandatory lifecycle:
  **DEVELOP → TEST → ARTIFACT → VISUALIZE → CORRECT → VALIDATE → ACCEPT**.
- Created `tools/verify_v14_eye_blueprint.py`, a fail-closed structural verifier for task IDs, lifecycle completeness,
  stream references and inventory counts.
- Created `tests/unit/test_v14_eye_blueprint.py`, checking uniqueness, lifecycle integrity and coverage of the requested
  pupil/iris/lashes/brow/highlight/colour/expression/camera/prompt/variation/visual-QA axes.
- Updated the eye README so the package points to the new deepening blueprint and no longer describes the current
  implementation as one monolithic `core.py` responsibility.

### Workstreams formalized

`GEN` common contracts; `MOR` morphology; `LID` eyelids; `IRI` iris; `PUP` pupil; `LAS` lashes; `BRW` eyebrows;
`HIL` highlights; `COL` colour/appearance; `EXP` expression; `PAIR` bilateral identity; `OCC` occlusion/interaction;
`STY` style; `CAM` camera/LOD; `VAR` constrained variation/default aesthetic; `PRM` prompt-to-visual specification;
`RND` rendering/evidence/visual acceptance.

The decomposition deliberately includes underestimated axes such as parameter orthogonality, continuity, self-intersection,
LOD/detail budgets, provenance, cache boundaries, seed determinism, conflict resolution, occluder causality, camera
invariance, visual regression and uniqueness/distribution of generated variants.

### Relationship model

The planned dependency direction is explicit rather than hidden in renderer code:

`Prompt → Visual IR/provenance → Identity/Morphology/Style/State/Expression/Gaze → Pair/Constraints/Regions → Geometry →
Occlusion/Interaction → Appearance → Camera/LOD → Renderer-neutral artefact → SVG/PNG evidence → visual review/correction`.

Morphology owns intrinsic geometric limits; expression owns intent; appearance consumes geometry/material/light context;
camera changes presentation space; occlusion represents relationships/consequences; style transforms controlled priors;
prompt compilation produces inspectable intermediate data; variation samples a constrained valid manifold.
