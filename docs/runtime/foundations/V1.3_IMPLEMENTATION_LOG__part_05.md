### Implementation details

The implementation deliberately reuses `ConsequenceRule` and
`ConsequenceRequest` rather than introducing a parallel rule/request model.
However, attribution has its own matcher and resolver entry point. This gives
one declarative rule vocabulary while preventing semantic coercion between
`AffectedRegionEvent` and `OccluderAttribution`.

`attribution_enabled=False` is a fail-closed compatibility boundary. It was added
after reviewing the default rule ranges: without explicit opt-in, an ordinary
visibility rule could otherwise match every attribution record and create a
false positive downstream request.

## 2026-09-14 — Consequence Request Aggregation checkpoint

Implemented `runtime/consequence_aggregation.py` and
`tests/unit/test_v13_consequence_aggregation.py`.

The new layer consumes only declarative requests. It provides semantic
fingerprints, explicit conflict groups, deterministic aggregation policies,
separate downstream precedence, provenance and a stable result digest. It does
not mutate downstream visual state.

`ConsequenceRequest.precedence` was added as an optional field with default `0`
to preserve existing positional construction while separating consequence
precedence from `ConsequenceRule.priority`.

## 2026-09-15 — Consequence → State/Effect Binding

Added `runtime/consequence_bindings.py` and `tests/unit/test_v13_consequence_bindings.py`.

The new compiler is deliberately not a mutation engine. It maps accepted
`ResolvedConsequence` objects to the existing `StateActivation` and `VisualEffect`
contracts through explicit binding data. Missing mappings remain visible as
`unbound` rather than being guessed. State precedence and effect composition are
therefore not duplicated.

Verification: full pytest suite PASS; compileall PASS.

## V1.3 — Appearance Resolution Contract — 2026-09-15

- `AppearanceDomain` taxonomy;

## V1.3 — Appearance Domain Contract Validation — 2026-09-15

Added `DomainFieldContract`, `DomainContract`, `DOMAIN_CONTRACTS`,
`DomainContractError`, and contribution validation in
`runtime/appearance_contract.py`. The seven rendering domains are now closed semantic
contracts before algorithms: BASE, MATERIAL, COLOR, LIGHTING, TRANSMISSION,
REFLECTION and EMISSION.

Validation rejects unknown fields, missing required fields, invalid value kinds and
invalid numeric bounds. It never mixes, converts, clips, shades or renders values.
`resolve_appearance_contract()` is the enforcement boundary. STATE/EFFECT remain under
their existing contracts.

Verification: full pytest suite PASS; compileall PASS.
