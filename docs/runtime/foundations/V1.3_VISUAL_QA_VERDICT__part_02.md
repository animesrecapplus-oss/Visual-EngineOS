### 6. Eyebrows

The previous renderer made several semantic eyebrow names visually too similar. The renderer now gives explicit geometry differences to:

- short;
- long;
- thick;
- dense;
- arched;
- high arch;
- low arch;
- angular;
- straight;
- ornate;
- faded;
- inward.

Bilateral rendering also provides left/right context to the `inward` variant so the inner ends can orient toward the face centre.

### 7. Pupil smoke

The first smoke implementation was technically emitted but visually hidden because it started at the pupil centre and the pupil fill was rendered afterward over the same area.

The corrected implementation launches smoke from the pupil boundary and extends it outward. This is why the new QA render visibly shows the smoke escaping the pupil.

### 8. Comments / maintainability

Comments were added around non-obvious invariants and algorithms rather than obvious statements. In particular:

- coordinate-system assumptions;
- gaze assembly semantics;
- two-pass lid/gaze resolution;
- containment;
- smoke launch geometry;
- eyebrow bilateral context;
- architecture compatibility facades.

## Architecture reorganization

The eye family now has a dedicated ownership tree:

```text
src/visual_engine/components/
├── common/
│   ├── meta.py
│   ├── visual_contract.py
│   └── geometry_contract.py
│
└── face/
    └── eyes/
        ├── core.py
        ├── pair.py
        ├── expression.py
        ├── profiles.py
        ├── styles.py
        ├── pupil/
        ├── iris/
        ├── eyelid/
        ├── lashes/
        ├── eyebrow/
        ├── highlights/
        └── effects/
```

The old `visual_engine.geometry.eye*` and `visual_engine.model.*` modules are compatibility facades. They are not second implementations. This gives existing callers a stable migration path while establishing the new ownership locations.

The domain subpackages currently expose stable public entry points while the coupled `EyeAppearance`/geometry contract remains in `eyes/core.py`. This is intentional: prematurely splitting tightly coupled structures would create circular imports and duplicate ownership. As the pupil, iris, eyelid, lash and eyebrow systems become independently solvable, their actual implementation can move into their corresponding subpackages without changing the public architecture.

## Next progression — without refactoring the project

The line remains:

```text
V1.3 closure
   ↓
relation/dependency semantics
   ↓
production geometry cache + invalidation integration
   ↓
V1.3 closure audit
   ↓
true geometric occlusion
   ↓
anatomical eyelid/exposure solver
   ↓
face-level component interactions
```

Visual QA remains a permanent gate. Every future component must be tested at three levels:

1. structural/model tests;
2. deterministic runtime tests;
3. rendered visual QA.

A feature is not promoted to "solid" merely because its class or parameter exists.
