## A8 — Generic end-to-end cross-layer verification — 2026-09-16

### Pre-implementation audit

A8 was not already implemented as a single closure gate. The repository contained individual eye vertical
slices and a PostgreSQL vertical slice, but no deterministic test that connected the generic authoring graph,
RuntimeGraph, resolution, geometry generation/cache, spatial transform, renderer-neutral output, and
persistence serialization in one controlled execution.

### Implementation

`tools/verify_a8_e2e.py` now builds a minimal but non-trivial `HumanFace` graph with two `Eye` children and
explicit bilateral relation edges. It drives the existing APIs in order, verifies cache miss/hit behavior,
resolves the generated geometry into camera coordinates, serializes component contracts, emits deterministic
SVG evidence, and checks stale RuntimeGraph rejection after topology mutation. The evidence renderer is
verification-only and fails closed for masks or primitive kinds it does not understand.

`tests/unit/test_v13_a8_e2e.py` runs the exact harness twice in independent output directories and compares
the generated geometry, cache identity, resolution fingerprint, resolution digest, camera geometry hash,
SVG hash, and serialization hash. This catches process/output drift without treating a single successful
execution as proof of reproducibility.

## A9 — Adversarial/property hardening + responsibility refactor — 2026-09-16

### Audit before implementation

Existing A0–A8 tests already covered multiple isolated invariants. A9 therefore added only missing adversarial
coverage and repaired concrete identity/refactoring weaknesses found by executing the existing suite. The audit
confirmed that `eyes/core.py`, `render/svg.py` and `runtime/geometry_cache.py` carried mixed responsibilities
large enough to justify decomposition without changing their public APIs.

### Concrete hardening performed

1. Strict canonicalization now rejects cyclic values, non-finite numbers and non-string mapping keys instead of
   silently coercing or recursing until a generic Python exception.
2. Geometry metadata uses the same fail-closed key/cycle principles at its model boundary.
3. Geometry cache keys validate identity fields and dependency IDs before mutating cache state.
4. Ocular implementation was decomposed into `definitions.py` and `geometry_builder.py`, leaving `core.py` as
   a compatibility facade.
5. SVG implementation was decomposed into primitives/effects/contours with `svg.py` retaining document-level
   public assembly.
6. Geometry cache fingerprinting was separated from LRU/concurrency policy while preserving legacy imports.
7. Adversarial tests cover canonicalization, cycle detection, relation permutation invariance, content mutation,
   cache invalidation idempotence, concurrent same-key construction, hostile metadata and singular transforms.

## A10 — Independent second full audit — 2026-09-16

**Status: PASS offline. V1.3 structural hardening is closed within the verified boundaries; long-term
production/visual scope remains explicitly open.**

### Audit method

A10 deliberately did not treat A9's verifier as sufficient evidence. It independently inspected the
repository's current source tree, import topology, compatibility ownership, version policy, migration ledger,
master documentation, previous verification gates, clean package imports and deterministic A8 evidence.

### Concrete findings corrected

1. **Roadmap contradiction:** Phase 1 prose said semantic-region foundations were implemented while its generic
   semantic-geometry checkbox still said future. The checklist now distinguishes the implemented V1.3 foundation
   from the planned production semantic-geometry layer.
2. **Legacy ownership leakage:** internal modules still imported `visual_engine.model`, even though that package
   had already become a compatibility facade. Internal imports now target `components.common`; compatibility remains
   available at the public legacy boundary.
3. **Digest dependency cycle:** relation identity depended on `versioning`, while `versioning` depended on relation
   dependency construction. Stable digest ownership moved to `runtime.identity`, which has no graph/dependency/cache
   dependency. The historical `runtime.stable_digest` import remains valid.

### Independent checks

- fresh interpreter import of every discovered package module: PASS;
- package/engine version agreement: PASS;
- migration identifiers: ordered, unique and contiguous;
- current documentation markers: synchronized;
- A4–A9 verifiers: PASS;
- full pytest and compileall: PASS;
- two consecutive A8 verifier runs: identical evidence digest.

### Explicit nonclaims

Live PostgreSQL remains unverified because no live DSN/server is configured. Package build execution was not

or completion of the future interaction/deformation, color/lighting, prompt-compiler and animation systems.
