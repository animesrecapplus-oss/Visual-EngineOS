## V1.3 — Semantic region spatial attachment checkpoint

Implemented the next logical boundary after the initial coverage kernel: semantic
regions can now be provided by component-specific providers and resolved through the
existing local → world → scene → camera transform pipeline without renderer coupling.

Added `runtime/region_maps.py`:
- `SemanticRegionProvider` contract;
- `RegisteredSemanticRegionProvider`;
- deterministic `SemanticRegionProviderRegistry`;
- `RegionMapResolution` provenance of provider/version/frame;
- vocabulary-free primitive-based provider for explicitly labelled area geometry;
- `resolve_region_map()` which builds regions in component-local coordinates and then
  applies the already-established spatial transform contract.

The generic provider deliberately does not know anatomy or object types. Semantic
vocabulary remains supplied by generators/components. Unlabelled non-area primitives
are not guessed into semantic regions.

Validation:
- local region maps remain renderer-independent;
- hierarchy and scene placement transform region geometry consistently;
- camera-frame resolution is supported;
- unsupported component kinds fail rather than silently receiving a guessed provider.

## V1.3.5 — Generic Spatial Relationship / Placement Solver — 2026-09-14

### Objective

Close the architectural gap identified after the visibility kernel: the engine could calculate what an already-positioned occluder covers, but it did not yet have a generic solver for positioning arbitrary source geometry relative to arbitrary target geometry.

### Implementation

Added `runtime/placement.py` with:

- `AnchorReference`;
- `DimensionConstraint`;
- `CoverageIntent`;
- `PlacementIntent`;
- `PlacementSolution`;
- `PlacementScaleMode`;
- `PlacementDepthRelation`;
- `resolve_placement()`.

The solver works only from geometry contracts and explicit relationship intent. It does not inspect component names or object categories.

Anchor registration is solved as an affine transform. Relative dimension constraints are ratios of target bounds. Coverage intent uses actual polygon intersection area and deterministic binary search over uniform scale.

A source anchor outside the source region or target anchor outside the target region is rejected for coverage solving because the required monotonicity would otherwise be unverified. Dimension and coverage constraints are also rejected together rather than silently selecting one.

`PlacementSolution` exposes the final affine matrix and point transformation so downstream systems can consume the result without reproducing transform math.

### Tests

Added `tests/unit/test_v13_spatial_placement.py` covering:

- anchor alignment with scale/rotation;
- relative dimensions;
- non-uniform dimensions;
- inconsistent uniform constraints;
- measured coverage solving;
- invalid coverage anchors;
- ambiguous constraint rejection;
- deterministic transform point mapping.

### Documentation

Added `docs/runtime/placement/V1.3_SPATIAL_PLACEMENT__part_01.md` (split document; see adjacent parts) and updated:

## V1.3.6 — Relation → Placement → Semantic Target Resolution — 2026-09-14

### Objective

Connect the isolated V1.3.5 `PlacementIntent` solver to the existing `RuntimeGraph`
and semantic-region system without introducing object-specific conditionals.

### Implementation

Added `src/visual_engine/runtime/spatial_relationships.py`.

The module provides:

- `RelationPlacementSpec`;
- `RelationPlacementResolution`;
- `compile_relation_placement()`;
- `resolve_relation_placement()`;
- `resolve_graph_placements()`.

A relation carries an explicit, closed `metadata["placement"]` declaration. The
compiler validates its keys and values, constructs the existing `PlacementIntent`,
and optionally selects an explicitly named semantic target region.

Target anchors have explicit ownership semantics:

- `component`: use the named anchor declared by the target component while using
  the semantic region as placement geometry;
- `region`: require the same named anchor to be explicitly present on the region.

No anchor, center, direction, object type, camera transform or placement rule is
inferred.

### Tests

Added `tests/unit/test_v13_relation_placement.py` covering explicit compilation,
no implicit placement, semantic-region targeting, anchor ownership, graph-wide
resolution and fail-closed metadata validation.
