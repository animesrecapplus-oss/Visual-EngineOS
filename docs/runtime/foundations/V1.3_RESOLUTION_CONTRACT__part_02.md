## ResolvedComponent

V1.3 now provides a renderer-neutral envelope:

```text
ResolvedComponent
├── component_id
├── kind
├── visual: ResolvedVisualContract
├── geometry: GeometryContract
└── trace: ResolutionTrace
```

The renderer receives resolved data. It should not inspect semantic `kind` to invent geometry or visual policy.

## Diagnostics

`ResolutionTrace` records deterministic high-level provenance such as:

```text
root.visual=explicit-root
child.visual=explicit-legacy
child.visual_overrides=inherit-or-override
```

This is deliberately a minimal first diagnostic layer. It does not yet claim complete per-field provenance.

## Determinism requirements

The resolver must produce the same logical result for the same graph and context. State names are sorted. Persistent identity must use canonical serialization and SHA-256 rather than Python's randomized `hash()`.

Cross-process serialization tests are still a remaining V1.3 gate.

## What is intentionally not solved here

- full appearance-layer composition;
- state conflict resolution;
- automatic relation propagation;
- constraint inheritance/scoping;
- geometric occlusion;
- physical shadows;
- 3D transforms;
- perspective;
- renderer-specific realization.

These are separate systems and must not be hidden inside this resolver.
