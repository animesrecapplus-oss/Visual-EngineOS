# V1.3 A0 structural closure — re-audit 2 — 2026-09-15

## Purpose

This pass re-opens the previous A0 structural-closure checkpoint instead of accepting its
PostgreSQL result as authoritative. The goal is to eliminate false positives in the two
remaining structural areas explicitly identified by the project directive:

- the real PostgreSQL lifecycle against a live PostgreSQL server;
- the `Component` / `RuntimeGraph` mutation lifecycle;
- and the observed eyebrow/closed-eye geometric relation.

The previous checkpoint contained a migration-runner defect: migration `001` could be recorded
in `schema_versions` without executing its DDL. The previous unit tests did not detect this
because their fake cursor modeled the ledger but not the requirement that every migration SQL
payload execute. This pass corrects both the runner and the test oracle.

## PostgreSQL correction

### Defect found

The previous runner created `schema_versions` and inserted migration `001` directly into the
ledger before executing its SQL. That is not a migration: it is only a ledger update. A clean
PostgreSQL database could therefore report `001` as applied while its application tables did
not exist.

### Correct lifecycle

```text
connect
  -> transaction
  -> transaction-scoped advisory lock
  -> ensure ledger
  -> read version + checksum history
  -> reject unknown/gapped/legacy histories
  -> for each missing migration:
       execute exact SQL
       record version + SHA-256 checksum
  -> commit
```

If any migration fails, the transaction is not committed and the ledger does not advance for
that migration.

The runner also rejects an already-recorded migration whose checksum differs from the checked-in
SQL. This makes migration files immutable historical inputs rather than mutable scripts whose
meaning can silently change after deployment.

### Live gate

`tools/verify_live_postgres.py` is deliberately stricter than the normal pytest integration test:
without `VISUAL_ENGINE_POSTGRES_DSN` it exits with status `2`, rather than SKIP. When configured,
it performs:

1. real connection;
2. migration;
3. exact expected schema version check;
4. entity write;
5. entity read;
6. equality round-trip assertion;
7. second migration call to prove idempotence.

The gate was executed in this environment and returned:

```text
LIVE_POSTGRES_GATE=BLOCKED: VISUAL_ENGINE_POSTGRES_DSN is not set
exit=2
```

This is an environment limitation, not a PASS.

## RuntimeGraph correction

`RuntimeGraph` remains a compiled view of the mutable authoring tree. This pass hardens the
boundary further:

- traversal is defensive and detects hierarchy cycles before recursive overflow;
- the same component object appearing twice is rejected;
- child `parent_id` must agree with the parent object that contains it;
- topology/relation digest invalidates a graph after mutation;
- stale queries fail closed;
- `rebuild()` is the explicit transition to a fresh compiled view;
- runtime index containers remain immutable.

Local parameter/appearance/geometry mutation is intentionally not converted into an automatic
full graph rebuild. That would conflate topology lifecycle with content invalidation and would
create hidden work. Content fingerprints/cache invalidation remain the owner of those changes.

## Eyebrow / closed-eye correction

The brow is anchored to a full-opening superior ocular reference, not to the state-dependent
visible aperture. Closing or covering the eye therefore cannot collapse the brow toward the
closed lid line.

The regression is now tested at two levels:

1. the stable `brow_reference_top_y` and `brow_reference_scale` values;
2. the actual emitted SVG brow path, which is byte-identical between normal and closed states
   for the same eye morphology and brow appearance.

This is a geometric invariant, not an expression-specific offset.
