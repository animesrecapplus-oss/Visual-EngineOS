# V1.3 — A0 Correctness Hardening / Eye Contract Verification

**Date:** 2026-09-15
**Status:** implemented corrections + verified boundaries; V1.3 is not declared production-complete.

## 1. Scope

A0 closes correctness defects discovered during the full-project audit before another
appearance domain is added. It deliberately does not implement the future physical
shadow/lighting engine or deep ocular morphology.

## 2. Corrections implemented

### 2.1 Global visibility aggregation

`runtime/visibility.py` previously left `total_visible` at zero when there was no front
occluder, despite returning `visible=1.0` for every region. The aggregate is now updated
for the no-front case. Per-region and global visibility therefore agree.

### 2.2 Legacy coverage kernel

`runtime/coverage.py` contained a second convex-clipping implementation that could
double-count overlapping primitives belonging to one occluder. `resolve_coverage()` is
now a compatibility adapter over the authoritative overlap-safe visibility kernel.
There is one geometric implementation of coverage semantics.

### 2.3 Geometry cache input completeness

`geometry_input_fingerprint()` now includes the authored `Component.geometry` field.
The generic Component contract exposes geometry as a possible generator input; omitting
it could alias distinct authored geometry under the same cache identity.

### 2.4 Extreme ocular gaze

The previous gaze solver subtracted a pupil footprint margin and additionally limited
the assembly by the iris ellipse. That prevented the pupil/iris assembly from reaching
the actual white-eye perimeter.

The A0 contract is now:

```text
Gaze direction
    ↓
actual eyelid aperture boundary
    ↓
iris + pupil assembly center may reach boundary
    ↓
SVG eye aperture clips the assembly footprint
```

The pupil is intentionally allowed to extend outside the scleral aperture at extreme
gaze. The exposed part is the intersection of the pupil geometry with the eye aperture.
This is a rendering/occlusion rule, not a claim that the biological iris moves outside
the anatomical sclera.

SVG has no CSS-like `z-index` for ordinary painter-order geometry. The equivalent
contract is established by aperture clipping and render ordering: the sclera defines
the visible aperture and the iris/pupil assembly is only visible inside that clip.

### 2.5 Closed-eye lashes

Upper and lower lash emitters now return no lash geometry when `opening <= 0` or the
state is `closed`/`covered`. This removes the unwanted default where a closed eye could
still receive a full lash system attached to a flattened lid.

### 2.6 Brow/eye separation

`BrowSpec` now has explicit `min_eye_gap` and `max_eye_gap` bounds. The renderer clamps
the requested brow vertical position to this gap envelope before applying gaze coupling.
Expression presets therefore cannot directly move the brow through the eye boundary.

This is a hard visual placement invariant, not the final anatomical facial-expression
solver.

### 2.7 Final contour provenance

`EyeGeometry.contour_points` now stores the final gaze-follow contour rather than the
pre-deformation translated contour. Width/height-derived downstream calculations and
the actual outer path therefore refer to the same resolved aperture.

## 3. Verification of user-proposed ocular observations

### A — External occluder shadow on every eye component

**Validated as a project requirement, not yet implemented.** The architecture explicitly
separates `OCCLUSION` from `SHADOW`; the current V1.3 visibility kernel computes geometric
coverage and optical visibility, while real projected shadow geometry remains a future
shadow-model domain.

Therefore the correct future behavior is:

```text
occluder geometry
    ↓
visibility / coverage
    ↓
projected shadow geometry
    ↓
intersection with each affected target semantic region
    ↓
shadow contribution per visible component/region
```

For an eye this must be able to affect sclera, iris, pupil, eyelid, highlight/reflection,
etc., according to the actual projected shadow and material/light rules. It must not be
implemented as `if occluder == hand: darken eye` or any object-specific branch.

Current evidence intentionally records this as **NOT IMPLEMENTED** rather than producing
a false positive.

### B — Brow/eye distance must be constrained independently of expression

**Validated and implemented as a hard placement invariant.** The current defaults are
`min_eye_gap=0.08` and `max_eye_gap=0.90`, expressed relative to the resolved eye scale.
The expression presets may modify brow intent but do not bypass the gap clamp.

This is intentionally a first constraint. Rich brow morphology, skin deformation,
orbital anatomy and expression-specific coupling remain future work.

### C — Lashes on a closed eye

**Validated as a real defect and corrected.** Closed/covered eyes now emit no lash
geometry from the default lash emitters.

### D — Pupil cannot reach the eye perimeter

**Validated as a real limitation and corrected.** Before A0, the solver used an iris
boundary and pupil-footprint safety margin. The extreme-gaze artifact suite showed the
pupil remained substantially inset. After A0, cardinal and diagonal extreme gaze can
place the assembly center on the sampled eyelid aperture; the pupil/iris footprint is
then cropped by the eye clip.
