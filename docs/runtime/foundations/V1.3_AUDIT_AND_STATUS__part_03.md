- normal gaze moves iris+pupil as one assembly;
- pupil remains centred in iris by default;
- highlights follow the assembly;
- pupil containment remains enforced for custom offsets;
- bounded eyelid follow reacts to gaze;

## Relation Dependency Checkpoint — 2026-09-13

**Status: implemented and tested.** Cross-branch relation semantics now participate in
resolution identity and invalidation. This is the required correctness boundary before
the production geometry cache. The next gate is cache implementation with these
fingerprints as immutable cache identities, followed by quantitative invalidation/cache
QA and then true geometric occlusion.

### Verification

- Full pytest suite: 158 tests passed.
- `python -m compileall -q src`: passed.
- Existing deterministic visual QA matrix: rerun successfully after relation/dependency changes.
- Production cache: intentionally not implemented yet; the next step consumes the now-safe `ResolutionFingerprint.cache_identity` boundary.

## V1.3.5 — Spatial placement status — 2026-09-14

The project now has a renderer-independent generic spatial placement foundation after the visibility/consequence layers.

**Implemented:** explicit anchor registration, relative dimensions, uniform/non-uniform scaling, arbitrary rotation/offset, depth relation, measured coverage-driven uniform scaling, deterministic affine solution.

**Not implemented:** relation-driven automatic placement, semantic-region-targeted placement constraints, collision/contact solving, 3D/perspective, prompt compilation, placement persistence.

No object-specific placement rules were added. The solver fails closed when its coverage-search preconditions are not satisfied.

## V1.3.7 placement-constraint audit — 2026-09-14

**Implemented:** explicit hard constraints for containment, clearance and
non-penetration; relation metadata integration; resolved geometry materialization.

**Not implemented:** generic optimization, arbitrary alignment frames, contact
manifolds, collision response, directional prompt semantics, placement fingerprints.

**Quality posture:** no object-category branches were introduced; malformed
constraint declarations fail closed; full tests and compile checks pass.

## V1.3 — Causal Attribution → Consequence Compilation — 2026-09-14

**Implemented:** a strict declarative bridge from `OccluderAttribution` to the
existing `ConsequenceRequest` model.

### Correctness boundary

Ordinary visibility events and causal attribution are now separate resolver domains:

```text
AffectedRegionEvent
      ↓
resolve_consequences()

OccluderAttribution
      ↓
resolve_attribution_consequences()
```

Attribution rules require explicit `attribution_enabled=True`. This prevents
existing broad visibility rules from becoming accidental attribution rules.

### Remaining nonclaims

This checkpoint does not apply consequence requests. It does not implement
state mutation, geometry mutation, appearance mutation, conflict resolution,
request aggregation semantics, or invalidation of downstream artifacts.

### Verification

- 258 tests passed;
- compileall passed;
- no object-category branches introduced;
- no conversion of attribution into ordinary visibility events.

## V1.3 Consequence Aggregation — 2026-09-14

Status: **implemented and verified**.

The consequence boundary now has an explicit aggregation/conflict stage between
request compilation and future mutation. Exact duplicates are idempotent;
conflicts require an explicit resolution group; downstream precedence is
separate from rule matching priority; provenance and a deterministic result
digest are retained; ambiguous mixed-target input fails closed.

This checkpoint still makes no claim of state/geometry/appearance mutation.
The next integration audit is reuse of the existing state/effect precedence
contracts without duplicating them.

## V1.3 — Consequence Binding Audit — 2026-09-15

The consequence pipeline now has an explicit binding boundary after aggregation.
Accepted requests can be compiled into existing state/effect envelopes without
mutation. The compiler fails closed on missing mappings and leaves geometry and
appearance requests unbound.

Remaining: application transaction, downstream dependency/invalidation integration,
and later dedicated geometry/appearance consequence resolvers.

## V1.3 — Appearance Layer Resolution status

**Status: implemented and verified.**

`Component.appearance` is now resolved through an explicit layer-binding contract.
The resolver is local-only, deterministic, provenance-aware and fail-closed. State
activation and effect conversion reuse upstream typed inputs rather than duplicating
their policy engines.

The appearance layer dependency digest is propagated into the appearance input
contract. It is intentionally not presented as a replacement for the existing global
resolution fingerprint.

No color/material/lighting behavior is claimed yet.


## Latest checkpoint — Appearance Domain Contract Validation

Status: implemented and tested.

The appearance pipeline now has a closed semantic validation gate between typed
`AppearanceContribution` objects and future domain-specific algorithms. The validator
contains no rendering behavior. Invalid payloads fail closed at the appearance
resolution boundary.
