## V1.3 State / Effect Precedence checkpoint

Implemented after Transform Invariants + Provenance + Version/Invalidation:

- `StateLayer` gained priority, exclusive group, conflict and requirement metadata;
- state resolution became deterministic and data-driven;
- duplicate logical states collapse to one activation;
- exclusive groups choose one winner;
- explicit conflicts are symmetric;
- requirements resolve to a fixed point;
- state decisions record accept/reject reasons;
- `VisualEffect` was introduced as a renderer-neutral external effect envelope;
- effects have deterministic IDs, priority and typed composition laws;
- opacity and visibility are multiplicative;
- occlusion scalar coverage is separate from shadow;
- multiple shadow alpha contributions combine without exceeding one;
- targeted effects cannot leak to siblings;
- legacy `shadow_alpha` remains supported by conversion to a generic effect;
- PostgreSQL migration `007_v1_3_state_effect_precedence.sql` adds state/effect persistence structures;
- resolution/schema version boundaries were advanced to invalidate results created under the previous semantics.

Performance hardening found an independent construction hot spot: `Component.add_child()` previously scanned the entire subtree for every insertion, making bulk construction O(n²). The duplicate check is now sibling-local; global uniqueness remains a `RuntimeGraph` invariant. A 10,000-child flat graph was measured after the change rather than relying on an unmeasured complexity claim.

Measured local benchmark on the development runtime (Python 3.13 environment):

```text
components    graph build       target resolution
1             0.064 ms          0.102 ms
100           1.066 ms          0.137 ms
1,000         24.496 ms         0.142 ms
10,000        1450.199 ms       0.146 ms
```

These numbers are diagnostic, not a production performance guarantee. The runtime currently resolves one target and does not yet have the production geometry cache.

## V1.3 Visual QA + ocular feedback correction pass — 2026-09-13

This pass was deliberately performed against rendered output, not only against unit-level structures. The objective was to detect visual defects that ordinary contract tests cannot see and then convert those observations into code, tests and documented nonclaims.

### What was tested

A deterministic visual matrix was added in `scripts_visual_qa_v13_feedback.py` and its outputs are stored in `artifacts/history/v1.3/qa_feedback/`.

The matrix covers:

- semantic `round` versus explicit `ellipse`;
- all current eye shape families;
- nine gaze directions;
- upper/lower lash density, length and form variants;
- twelve eyebrow variants;
- gaze-follow eyelid behaviour;
- pupil glow and smoke on light/dark backgrounds;
- anime-golden and reflective-large-eye reference-oriented presets;
- bilateral inward eyebrow orientation.

### Problems found and corrected

1. **Gaze assembly:** the previous model allowed the internal ocular elements to appear independently displaced. The current normal mode treats iris + pupil as one gaze assembly. The pupil remains centred in the iris by default and highlights follow the assembly.
2. **Lid follow:** a bounded two-pass gaze/lid coupling now changes the aperture when looking up/down instead of leaving a completely rigid eyelid envelope.
3. **Pupil containment:** custom pupil offsets are clamped after assembly placement and cannot bypass the containment contract.
4. **Round shape:** `round` is now circular at full opening. `ellipse` is the explicit non-circular shape.
5. **Lashes:** default upper lashes are shorter/heavier than before; lower lashes are intentionally much lighter and sparser. Existing explicit lash forms remain available.
6. **Eyebrows:** semantic variants now generate visibly different geometry: short, long, thick, dense, arched, high-arch, low-arch, angular, straight, ornate, faded and inward. Bilateral rendering supplies side context for inward orientation.
7. **Pupil smoke:** the previous smoke path started inside the pupil and was covered by the later pupil fill. The new launch point is the pupil boundary, so smoke visibly escapes the pupil.

### Architecture organization

Eye-specific code now has an explicit owner under `components/face/eyes/`. Public subpackages exist for pupil, iris, eyelid, lashes, eyebrow, highlights and effects. Shared component contracts have a `components/common/` home.

The old `geometry/eye*.py` modules are compatibility facades only. New eye logic must not be added there.

## V1.3 Relation/Dependency Checkpoint — 2026-09-13

Implemented the next architectural gate before geometry caching:

- `runtime/dependencies.py` introduces normalized relation semantics and indexed cross-branch dependencies.
- Known relation types have explicit directions; unknown types remain neutral unless `dependency_direction` is declared.
- Dependency closure is transitive and cycle-safe.
- `dependency_fingerprint()` now covers the ordered hierarchy chain plus transitive semantic relation dependencies.
- `invalidation_reasons()` now explains relation-driven invalidation paths.
- Explicit relation effect declarations compile into the existing `VisualEffect` contract.
- Relation effect declarations also become invalidation dependencies, including `effect_target=None` global effects.
- Duplicate effect IDs are rejected after relation/context effects are combined.
- Resolution semantic version advanced from `2` to `3` because the resolution dependency contract changed.
- Added migration `008_v1_3_relation_dependencies.sql`.
- Added 15 relation/dependency tests; full suite passes.
- Existing V1.3 visual QA matrix was rerun successfully after the change; no eye-rendering regression was introduced.

## Geometry cache checkpoint — 2026-09-13

Implemented the production runtime geometry-cache boundary after relation/dependency semantics.

- Added `runtime/geometry_cache.py`.
- Added stable `GeometryCacheKey` with geometry-specific dependency/input fingerprints.
- Kept visual-only changes out of the geometry key.
- Included relation topology and explicit `metadata["geometry_inputs"]` in geometry dependency identity.
- Added bounded thread-safe LRU storage with deterministic byte accounting.
- Added per-key single-flight construction to prevent duplicate concurrent builds.
- Added reverse dependency index for selective explicit invalidation.
- Added stable geometry digest on every cache entry.
- Added cache statistics for QA/performance measurement.
- Added 14 cache tests covering hit/miss, dependency changes, visual-only changes, relation topology, generator/version boundaries, LRU/byte bounds, failures and concurrency.

The cache remains process-local and renderer-neutral. No claim is made that PostgreSQL or a distributed cache is implemented at this checkpoint.

Validation: full suite passes after cache implementation; `compileall` passes. A synthetic 200-component benchmark measured ~1.92x hot-path speedup in the current environment. The benchmark also identified dependency-key construction as the next performance profiling target.
