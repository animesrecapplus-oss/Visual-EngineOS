# V1.3.3 — Multi-component geometry generation

## Purpose

This checkpoint validates that the geometry generator contract works beyond an isolated eye.
The engine now supports explicit generator dependencies and recursive preparation before a
composite generator executes.

```text
HumanFace
  ├── Eye(left)  -> face.eye
  └── Eye(right) -> face.eye
          |
          v
      face.eye_pair
          |
          v
 face.human_with_eyes
```

## Generator dependency contract

A generator may declare `geometry_dependencies(component, inputs)`.
The orchestration layer then:

1. detects cycles;
2. resolves every declared geometry dependency;
3. passes the resolved child geometries through `prepare_inputs()`;
4. projects those prepared inputs through `cache_inputs()`;
5. computes a cache key containing the declared dependency set;
6. executes the generator only on cache miss.

A dependency is therefore executable, not merely documentary.

## Registry semantics

The registry now distinguishes:

- **default generators** selected from a component kind;
- **explicit alternatives** selected by stable generator name.

This permits `HumanFace` to have a normal `face.human` generator while also exposing
`face.eye_pair` and `face.human_with_eyes` as explicit composite views without replacing
the default.

## Current generators

| Generator | Kind | Role |
|---|---|---|
| `face.eye` | `eye`, `Eye` | canonical ocular geometry |
| `face.human` | `HumanFace` | parametric head outline |
| `face.eye_pair` | `HumanFace` | composes exactly two direct eye geometries |
| `face.human_with_eyes` | `HumanFace` | composes head + eye pair |

`face.eye` accepts both `eye` and `Eye` because historical entity data uses both spellings.
The default eye-only registry remains restricted to the legacy `eye` kind for compatibility.

## Cache correctness

Composite geometry depends on its child geometry identities. A change to one eye therefore
changes the parent composite key and rebuilds only the affected child plus the composite.
A visual-only mutation excluded by the eye generator's cache projection does not rebuild the
composite geometry.

The cache also records the declared child IDs in its reverse dependency index, so explicit
component invalidation can target the composite entry without clearing unrelated entries.

## Coordinate-frame rule

`merge_geometry_contracts()` only merges contracts that are already expressed in the same
parent coordinate frame. It intentionally does **not** invent or apply child transforms.
Transform propagation remains a separate runtime concern. This avoids silently double-applying
translation, rotation or scale and leaves the later scene/world composition step explicit.
