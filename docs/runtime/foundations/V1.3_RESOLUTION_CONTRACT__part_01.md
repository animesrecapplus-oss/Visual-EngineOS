# V1.3 — Inheritance & Resolution Contract

## Purpose

This document defines the next hardening layer of V1.3: how a component's local contract becomes a deterministic resolved component in a hierarchy.

The goal is **not** to make every property inherit. The goal is to define an explicit policy for each class of property and prevent semantic decisions from leaking into renderers.

## Verified starting point

The implementation was audited from the V1.3 Geometry Contract archive before this work. The existing resolver already composed 2D transform matrices, accumulated `z`, multiplied opacity/visibility, and applied an externally supplied shadow. However, visual fields were effectively replaced by the last component in the hierarchy. There was no explicit field-level distinction between `inherit` and `explicit` for descendants.

That limitation is now addressed incrementally with `VisualOverrides`, while preserving the existing `Component.visual` behavior for compatibility.

## Resolution model

```text
Component definitions
        |
        v
   RuntimeGraph
        |
        v
ResolutionContext
        |
        v
Inheritance + transform + state resolution
        |
        v
Effect application
        |
        v
ResolvedComponent
        |
        +--> SVG / CPU / future renderer adapters
```

## Property policies

| Property | V1.3 policy | Reason |
|---|---|---|
| local transform | compose | child remains in parent coordinate frame |
| x/y/rotation/scale | matrix composition | preserves transform ordering |
| component z | accumulate | establishes hierarchical depth coordinate |
| geometry local_z | added after component world z | geometry can have local depth offset |
| visibility | multiply | hidden parent hides descendants |
| opacity | multiply | translucent parent attenuates descendants |
| fill | explicit override or inherit | color is not mathematically composable |
| contour | field-level override or inherit | contour attributes are independent fields |
| material | field-level override or inherit | material is a structured contract |
| state names | merge as deterministic set | conflict policy is a later dedicated state system |
| appearance layers | no implicit inheritance yet | ordering/merge semantics are not stable enough |
| relations | no automatic inheritance | propagation is relation-specific |
| constraints | no automatic inheritance | scope and exemptions must be explicit |
| geometry | local only | geometry is not an appearance value |

## Legacy versus explicit inheritance

`Component.visual` remains a complete, explicit local contract. This preserves existing callers and avoids silently changing the meaning of existing components.

New code may use:

```python
VisualOverrides(
    fill_color=None,       # inherit
    contour=ContourOverride(width=1),
    material=MaterialOverride(roughness=0.2),
    opacity=0.5,
    visibility=None,
)
```

`None` means **inherit** for that field.

This is intentionally different from the defaults of `VisualContract`. A default `VisualContract()` is a complete local contract; `VisualOverrides()` is a request to inherit everything.

## Transform contract

For a hierarchy:

```text
Root -> Parent -> Child
```

world matrices are resolved as:

```text
M_world = M_root * M_parent * M_child
```

where every local transform is represented as a 3x3 homogeneous 2D matrix.

The current implementation retains the matrix representation after composition. It does not reconstruct a world TRS from the resulting matrix. This is important when rotation and non-uniform scale coexist.

`z` is accumulated independently from the 2D matrix:

```text
component_world_z = sum(local_transform.z)
geometry_world_z = component_world_z + geometry.local_z
```

This is a depth coordinate only. It is **not** a geometric occlusion solver and is not a substitute for perspective/3D depth.

## Visibility versus opacity versus occlusion

These concepts are deliberately separate:

```text
visibility != opacity != occlusion
```

- `visibility`: whether the component participates in the resolved visual result;
- `opacity`: attenuation of the component's appearance;
- `occlusion`: spatial coverage by another geometry.

A later occlusion solver may determine that 40% of an eye's area is covered without changing the eye's material opacity from 1.0.

## State resolution

V1.3 currently merges enabled local state-layer names with externally supplied active-state names and sorts them deterministically.

It does **not** yet resolve mutually exclusive state conflicts such as:

```text
closed + wide_open
```

That requires a dedicated state precedence/transition contract and is therefore not claimed as implemented here.

## External effects

`ResolutionContext` is the explicit boundary for effects supplied from outside the component's base contract:

```text
shadow
occluder IDs
active states
```

This prevents the generic resolver from knowing whether the target is an eye, hand, hair, clothing, or another object.

Exact polygon intersection, projected shadows, transmission and reflection remain future systems.
