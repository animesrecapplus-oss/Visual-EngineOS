### Anti-false-positive discipline

A parent stream is never marked complete because some child atoms already exist. A preset is not evidence of a general
solver; a colour field is not evidence of colour intelligence; a camera transform is not evidence of perspective/3D;
a deterministic hash is not evidence of visual equivalence; and a prompt string is not evidence of prompt compilation.
Every accepted atom must have implementation, tests, deterministic artefacts, visual inspection, correction history and
validation evidence.

## V1.4 functional brick — MOR canthus independence + contour safety

### Scope
Implemented only the narrow morphology brick required to move the next V1.4 atoms forward without opening a new monolithic module:

- `MOR.canthus_inner`
- `MOR.canthus_outer`
- `MOR.self_intersection`

`MOR.continuity` and global `MOR.morph_orthogonality` remain partial; this brick does not claim those broader contracts are solved.

### Audit before implementation
The existing contour builder exposed one shared `canthus_roundness` value and had no explicit reusable contour self-intersection guard. The correct owner was the already separated `eyes/geometry` layer, so no logic was added to a facade or renderer.

### Implementation
- Created `src/visual_engine/components/face/eyes/geometry/canthus.py` (explicit inner/outer endpoint resolution).
- Extended `src/visual_engine/components/face/eyes/morphology/spec.py` with optional independent inner/outer roundness while preserving the legacy field as the backwards-compatible default.
- Updated `src/visual_engine/components/face/eyes/geometry/contour.py` to consume the canonical canthus resolver.
- Created `src/visual_engine/components/face/eyes/geometry/invariants.py` with finite-contour validation and closed-polyline crossing detection. Shared endpoints are explicitly excluded from the crossing test so legitimate canthus joins are not false positives.
- Updated `src/visual_engine/components/face/eyes/geometry/builder.py` to fail closed on non-finite/self-intersecting open contours, while allowing the intentionally degenerate closed-eye representation.

### Evidence lifecycle
1. DEVELOP — parameter domains, ownership, backwards compatibility and failure semantics defined before code changes.
2. TEST — independent inner/outer changes, legacy equivalence, iris/pupil orthogonality check, 324-case morphology matrix across shape/opening/canthus bounds.
3. ARTIFACT — 9 deterministic SVG + 9 PNG cases and JSON manifest under `artifacts/v14_mor_canthus/`.
4. VISUALIZE — contact sheet reviewed for default, sharp/soft inner/outer, narrow, upturned and downturned cases.
5. CORRECT — initial implementation exposed a missing legacy control variable and an over-sensitive intersection detector; both were corrected before acceptance. No renderer-side workaround was introduced.
6. VALIDATE — focused suites passed; full regression and A4–A10 verification are required before checkpoint acceptance.
7. ACCEPT — only the three scoped atoms above are promoted to `IMPLEMENTED_ATOMIC`.

## V1.4 — MOR.continuity functional brick — 2026-09-16

### Scope and audit

Implemented **only** `MOR.continuity`. `MOR.morph_orthogonality` and
`MOR.morph_variation` remain `PARTIAL_OR_SKETCH`; they are intentionally not inferred
from parent-stream progress.

Before coding, the existing contour path was audited mathematically. The previous
renderer had a hard-coded cubic canthus transition, while the geometry contract only
stored upper/lower sampled margins. Therefore the system could not prove that the
closure tangent matched the lid tangent. The old contour docstring also overstated
this as C1 continuity. That claim was corrected before acceptance.
