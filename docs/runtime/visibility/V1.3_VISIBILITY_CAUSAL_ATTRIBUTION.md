# V1.3 — Visibility Causal Attribution

## Objective

Close the multi-occluder gap after the placement → visibility closure.

The visibility kernel already computes overlap-safe total geometric coverage. The
remaining question is causal attribution:

> Which part of a target region is attributable to each occluder when several
> occluders overlap, have different depths, or transmit light?

This contract is domain-neutral. It does not know whether an occluder is a hand,
eye patch, object, hair strand, glass panel, character, or anything else.

## Contract

```text
Target Region + Front Occluders
            ↓
      Planar Arrangement
            ↓
       Local Occlusion Stack
            ↓
 ┌──────────┼───────────┬───────────────┐
 ↓          ↓           ↓               ↓
Pairwise   Exclusive   Shared        Dominant
coverage   coverage    coverage      coverage
                         
            ↓
   Optical counterfactual
            ↓
   Marginal optical loss
```

### Metrics

For target region area `T` and occluder `A`:

- **coverage** = `area(T ∩ A) / area(T)`
- **exclusive coverage** = area covered by `A` and by no other front occluder
- **shared coverage** = area covered by `A` and at least one other front occluder
- **dominant coverage** = area for which `A` is the nearest front occluder
- **optical marginal loss** = visibility without `A` minus visibility with all
  occluders, integrated over the target region

The metrics answer different questions and must not be conflated.

## Important non-additivity rule

Pairwise coverage is intentionally not additive:

```text
coverage(A) + coverage(B)
```

may exceed the total target coverage because the same target area can belong to
both footprints.

Exclusive coverage is additive across occluders and describes a disjoint spatial
partition. Dominant coverage is another disjoint partition of covered area, but
uses depth ordering instead of overlap ownership.

Optical marginal loss is a counterfactual measure. It is deliberately **not** an
additive attribution and must not be normalized or forced to sum to total optical
loss.

## Depth rule

Front occluders are ordered deterministically by descending `z`, with
`occluder_id` as the stable tie-breaker. The first layer in a local stack is the
dominant layer.

Behind occluders are excluded. Coplanar occlusion is included only when explicitly
requested by `coplanar_occludes=True`.

## Optical rule

For a local front-to-back stack:

```text
visibility = Π (1 - opacity * (1 - transmission))
```

For each occluder, marginal optical loss is evaluated by removing only that layer
from the same local stack. This makes the counterfactual explicit and deterministic.

## Why this is separate from `AffectedRegionEvent`

The existing `AffectedRegionEvent` records that an occluder intersects a semantic
region and reports aggregate visibility. It does not claim unique causal ownership
when multiple occluders overlap.

This checkpoint therefore adds a separate `OccluderAttribution` contract rather
than silently changing the semantics of existing events.

A later consequence/event integration may consume these records explicitly.

## Failure policy

- duplicate occluder IDs fail closed;
- empty target regions produce no attribution;
- behind occluders produce no attribution;
- incompatible geometry frames remain the responsibility of upstream contracts;
- inability to construct the deterministic planar arrangement raises an explicit
  error rather than returning a plausible approximation.

No object-specific fallback is permitted.

## Verification

The test suite covers:

1. disjoint occluders;
2. overlapping occluders;
3. depth reversal;
4. transparent/transmissive layers;
5. counterfactual marginal loss;
6. input-order determinism;
7. duplicate-ID rejection;
8. behind-layer rejection;
9. dominance bounds and exclusive/shared partition invariants.

This remains a 2D planar visibility contract. It does not claim physical 3D
optics, refraction, diffraction, volumetric media, or semantic interpretation of
object categories.
