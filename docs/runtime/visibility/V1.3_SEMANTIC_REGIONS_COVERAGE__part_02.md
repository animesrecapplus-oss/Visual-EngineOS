## 8. Golden Component validation

The eye remains the reference stress test because it contains many independently
visible semantic regions. A successful generic coverage system must eventually
handle partial coverage of:

- upper/lower eyelids;
- lashes;
- eyebrow;
- sclera;
- iris;
- pupil;
- highlights;
- tear system;

without introducing eye-specific logic into the generic coverage engine.

## 9. Next technical increments

1. Attach region maps to generated component/scene instances without coupling them
to renderer code.
2. Transform region geometry through the existing local → world → scene pipeline.
3. Add robust spatial boolean operations for concave regions and overlapping shapes.
4. Add a true multi-occluder visibility resolver with correct overlap handling.
5. Emit semantic affected-region events that downstream state/effect resolvers can
consume.
6. Validate the same contracts on non-eye examples.

## 10. Spatial attachment checkpoint

Semantic regions are now first-class runtime data that can be produced by a
`SemanticRegionProvider` and resolved through the same transform pipeline as ordinary
geometry. This keeps region identity in local component space while allowing the
coverage resolver to consume world/scene/camera-space regions.

```text
component + generated geometry
        ↓
SemanticRegionProvider
        ↓
local RegionMap
        ↓
local → world → scene → camera
        ↓
resolved RegionMap
        ↓
Coverage / Visibility
```

No renderer is involved and no occluder vocabulary is introduced.
