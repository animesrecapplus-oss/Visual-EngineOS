# V1.3 — Causal Attribution → Consequence Compilation

**Status:** IMPLEMENTED — declarative bridge from measured causal visibility to consequence requests.

## Objective

Connect the validated multi-occluder attribution layer to the existing generic
consequence system without changing the meaning of `AffectedRegionEvent` and
without applying mutations during compilation.

The contract is:

```text
VisibilityAttributionResult
        ↓
OccluderAttribution
        ↓
ConsequenceRule.matches_attribution()
        ↓
ConsequenceRequest
        ↓
future state / geometry / appearance / effect application
```

## Why a separate attribution path is required

`AffectedRegionEvent.coverage` is a geometric pairwise measurement. In an
occluder overlap it is not a causal attribution. Reusing it as if it represented
`dominant_coverage`, `exclusive_coverage` or `optical_marginal_loss` would create
false positives.

The compiler therefore consumes `OccluderAttribution` directly.

## Explicit opt-in

A `ConsequenceRule` has `attribution_enabled=False` by default. Existing rules
therefore cannot accidentally fire when passed to the attribution resolver.
Attribution-specific thresholds are independently declared for:

- pairwise coverage;
- exclusive coverage;
- shared coverage;
- dominant coverage;
- optical marginal loss;
- depth relation;
- semantic region kind/tags.

This preserves backward compatibility and establishes a closed domain boundary.

## Non-goals

This layer does not:

- mutate components or scene state;
- modify geometry;
- modify appearance or color;
- infer object categories;
- infer anatomy;
- convert causal attribution into an additive quantity;
- resolve conflicts between downstream requests;
- perform rendering;
- perform physical 3D optics.

## Determinism

Attributions are processed by `(region_id, occluder_id)`. Rules retain the existing
priority/ID ordering. Requests use the existing canonical `ConsequenceRequest`
ordering and identify their source domain with the stable event key suffix
`causal_attribution`.

## Validation matrix

The implementation is required to demonstrate:

1. dominant thresholds use dominant coverage, not pairwise coverage;
2. shared and exclusive thresholds remain independent;
3. optical marginal loss is not substituted by geometric coverage;
4. existing event rules do not fire without explicit attribution opt-in;
5. target identity must match the RegionMap;
6. request ordering is deterministic;
7. compilation remains declarative and side-effect free.
