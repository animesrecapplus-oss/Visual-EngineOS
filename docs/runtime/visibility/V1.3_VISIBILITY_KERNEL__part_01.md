# V1.3 — Geometry Boolean / Visibility Kernel

**Status:** IMPLEMENTED — robust 2D visibility kernel; physical 3D optics and renderer clipping remain future work.

## Architectural position

The visibility pipeline is now explicitly:

```text
Primitive
  ↓
Planar Region
  ↓
Boolean Geometry
  ├── UNION
  ├── INTERSECTION
  └── DIFFERENCE
  ↓
Depth-filtered Occluder Set
  ↓
Overlap-safe Multi-Occluder Visibility
  ↓
Semantic Region Results
  ↓
AffectedRegionEvent
  ↓
State / Interaction / Appearance resolvers
```

The kernel does not contain knowledge of eyes, hands, hair, clothing, characters,
or any other object category.

## 1. Primitive → region geometry

`primitive_to_region()` converts supported area primitives into planar geometry:

- `polygon`
- `ellipse`
- `circle`

Ellipses/circles are deterministically polygonized before boolean operations.
The public API does not expose a renderer-specific geometry object.

Line/polyline primitives are deliberately rejected as area regions rather than
silently assigning them an arbitrary thickness.

## 2. Union

`union_geometries()` performs a real geometric union over all input regions.
Overlapping shapes are merged once. This removes the double-counting defect of the
first coverage foundation.

## 3. Intersection

`intersection_geometry()` and `boolean_operation(..., INTERSECTION)` support
concave input regions and return the actual intersection topology.

## 4. Difference / subtraction

`difference_geometry()` preserves disconnected output and polygon holes.
The renderer-neutral `BooleanPolygon` contract stores exterior rings and interior
rings explicitly.

## 5. Concave polygons

Concavity is handled by the boolean geometry backend rather than by assuming that
every polygon is convex. This is important for anatomy, clothing boundaries,
hair silhouettes and arbitrary generated shapes.

## 6–7. Multiple occluders and overlap

`resolve_visibility()` first filters occluders by depth and then resolves their
spatial union against each semantic target region. Therefore:

```text
A ∪ B
```

is measured once even when A and B overlap.

The optical stack is separately evaluated front-to-back so overlapping transparent
layers are not treated as one opaque shape.

## 8. Geometric coverage

For a semantic region:

```text
coverage = area(target ∩ union(front_occluders)) / area(target)
```

The result is clamped to `[0,1]` and is independent of opacity and transmission.

## 9. Visibility residual

Optical visibility is not defined as simply `1 - geometric_coverage` anymore.
For each spatial cell, front occluders are composited using their effective blocking
alpha:

```text
effective_alpha = opacity × (1 - transmission)
visibility *= (1 - effective_alpha)
```

Thus a fully transparent transmitting object can have 100% geometric coverage
while leaving target optical visibility at 100%.

## 10. Transmission

Transmission remains a separate output. It is never folded into the geometric
coverage number.

This preserves the distinction:

```text
coverage ≠ opacity ≠ transmission ≠ visibility
```

Physical refraction, wavelength-dependent transmission and material-specific
optical response are outside this phase.

## 11. Depth

Only an occluder in front of the target enters the visibility stack by default.
Coplanar geometry is neutral unless `coplanar_occludes=True` is explicitly selected.
Deterministic ordering for front layers is `z DESC`, then stable `occluder_id`.

This is a 2D depth ordering model, not a 3D z-buffer or perspective renderer.
