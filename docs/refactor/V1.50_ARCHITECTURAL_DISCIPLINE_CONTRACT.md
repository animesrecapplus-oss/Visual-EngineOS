# V1.50 — Architectural discipline contract

## Objective

Turn component hierarchy, documentation, contracts, tests, adversarial review, impact analysis, visual validation, persistence and cleanup into one repeatable engineering system.

## Mandatory gate

`VERIFY → ARCHITECT → IMPACT → IMPLEMENT → HOSTILE TEST → REVIEW → OPTIMIZE → INTEGRATE → VISUALIZE → DOCUMENT → PURGE → CERTIFY`

## Component truth

A real component receives a semantic ID, owner, parent/children, responsibility/non-responsibility, consumers, dependencies, guarantees,
assumptions, invariants, contracts, tests, adversarial cases, relations, decisions, errors, impact surface and evidence.

## Traceability

Stable IDs connect `DEC → CON → INV → CODE → TST/ADV → EVD` and, for runtime behaviour,
`PROMPT/INPUT → PARAMETER → COMPONENT → GEOMETRY → TRANSFORM → VISIBILITY/APPEARANCE → RENDER → EVD`.
Reverse tracing is required for defect diagnosis.

## Modification rule

No change is local until consumers, parent/child/sibling relations, dependencies, contracts, invariants, cache/fingerprint/provenance,
persistence, determinism, tests and visual effects have been analysed.

## Hostile rule

Attack impossible states, wrong types, NaN/∞, zero/negative/extreme values, overflow/precision, malformed inputs, cycles,
non-determinism, stale cache, API over-permissiveness, composition conflicts, catastrophic performance and silent visual regressions.

## Visual rule

When output can change, execute `PROMPT → PARAMETERS → PERSISTENCE → RESOLUTION → CODE → EXECUTION → FRAME/IMAGE/VIDEO → INSPECTION → DIAGNOSIS → CORRECTION → TEST → NEW EXECUTION`.

## File rule

Code and durable text target ≤150 lines. New/modified code explains non-obvious intent and invariants. The V1.50 pilot enforces comment coverage on every non-blank code line in its owned pupil files.

## Artifact rule

`artifacts/` remains. At certification, only `artifacts/current/vX.Y/` for the current brick remains. Superseded generated contents are purged; durable conclusions remain in `docs/`.

## Non-negotiables

No speculative implementation, no false completion from blueprint labels, no opportunistic refactor, no hidden renderer semantics, no silent API break,
no COLOR change without a real downstream consumer, and no module split justified solely by line count.
