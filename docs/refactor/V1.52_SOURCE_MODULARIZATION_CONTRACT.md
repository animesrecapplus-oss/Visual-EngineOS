# V1.52 — source modularization contract

## Scope

V1.52 applies the architectural-immune-system protocol to one responsibility selected only after re-audit,
consumer tracing and impact analysis.

## Selected seam

- Audited module: `src/visual_engine/runtime/domain_resolution.py`.
- Responsibility: immutable domain-result contract.
- Canonical owner: `src/visual_engine/runtime/domain_result_contract.py`.
- Compatibility owner: `domain_resolution` re-export surface.

## Included contract

`DomainResolutionStatus`, `DomainResolvedField`, `DomainResolutionProvenance` and `DomainResolutionResult`,
plus the shared rendering-domain/digest guards required by that contract.

## Excluded

Input construction, `DomainResolutionInput`, `build_domain_resolution_input`, `unresolved_domain_result`,
semantic result validation, domain algorithms, persistence, cache ownership, fingerprints and rendering.

## Hostile correction

The selected constructor boundary previously accepted impossible runtime status/container types. V1.52 adds
explicit type guards for status, domain, fields, reasons, provenance and lineage without changing valid values,
digests or resolver algorithms.

## Mandatory guarantees

- one canonical implementation owner;
- historical/public imports remain identity-compatible;
- no reverse import into `domain_resolution`;
- no new dependency cycle;
- exact duplicate audit remains clean;
- result/provenance digest semantics remain deterministic;
- persistence/database and cache/fingerprint boundaries remain unchanged;
- COLOR semantics remain frozen;
- new source stays at or below 150 lines.

## Visual boundary

The selected responsibility contains no geometry, visibility, camera or renderer operation. Independent visual QA
is therefore `NOT_APPLICABLE`; no synthetic image evidence is allowed.

## Release boundary

Retain only `artifacts/current/v1.52/`. The certified ZIP remains external to the project tree.
